# PenShot 0.4.8 发布说明

> 状态：随 release-please 发布 PR 发布。本版版本号 `0.4.8`（`pyproject.toml` 与 `penshot/__init__.py` 同步）。
> 本版为开发分支累积改动的一次性收口，聚焦连续性检查、三层记忆、审计修复回路与报告一致性。

---

## 1. 版本概述

0.4.8 将 0.4.7 之后开发分支上的改动统一合并到 `main`：连续性守护扩展为锚点 + 快照 + 跨块校验，记忆层统一为 `BaseMemoryLayer` 三层结构，审计与修复回路改为按确定性问题码结算，工作流报告（`continuity_report.json` / `repair_history.json` / `quality_report.json`）的状态与计数口径对齐。

改动规模：70 个文件，+3900 / -601。

## 2. 本版变更

### 2.1 连续性守护

- 场景/角色锚点：外观锚点只保留外观子句，字段白名单首值优先，长度仅在子句边界截断，避免动作/情绪词污染锚点。
- 状态快照：修复前后保留状态快照，检查与复审基于同一快照口径，历史已收敛问题不再重复计分。
- 跨块校验：长剧本分块后补充跨块角色/场景/道具校验，分块边界不再漏检。
- 风格漂移：风格漂移检测与六维风格前缀统一，互斥打光只保留一个家族。
- 道具：道具结构化解析并写入场景契约，供后续片段引用。
- 外观状态子句不再混入服装锚点，避免同一角色因动作/情绪被误报为外观变化。

### 2.2 记忆层

- 三层记忆（短期/中期/长期）统一 `BaseMemoryLayer`，读写接口与工作流键一致。
- 修复记忆读取链路，阶段完成后的记忆写入可被下一阶段正确召回。
- 长期记忆增加保留上限与自动清理，避免无限增长。

### 2.3 审计与修复回路

- 修复参数改用确定性问题码，并按真实修复动作结算，避免“假修复”与空转重试。
- 修复后强制复审，审计只采信复检结果。
- 模型支持校验对齐能力注册表。
- 历史阶段统计缺少完整度时不再误判为 `poor`。
- 修复后重算阶段问题，避免无进展的重复修复循环。
- 声明 `last_audit_result` 状态字段，检查点恢复时审计状态保持一致。

### 2.4 提示词与路由

- 片段固定 `seed`，保证同一片段重跑可复现。
- 音频链每轮重置，避免上一轮对话上下文残留。
- 剧本语言推断与音频提示词归一，支持跨剧本模板迁移。
- 片段模型回写路由结果；计划场景作为首帧唯一权威；必需资产待生成时显式标记。

### 2.5 工作流与检查点

- 稳定 `thread_id`，支持断点续跑。
- 工作流缓存按任务隔离，并回收检查点连接，避免连接泄漏。

### 2.6 报告一致性

- **连续性报告**：连续性问题均不可自动修复时记录 `unfixable_skipped` 轮次，`final_status` 由 `not_checked` 修正为 `continued_with_issues`，不再与“检查已执行且流程继续”的事实矛盾。
- **修复历史**：`repair_history.json` 汇总质量审查阶段的修复动作，`repair_count` 与日志中的修复动作数一致；新增 `continuity_repair_count` / `quality_repair` 分列。
- **质量报告**：`quality_report.json` 增加 `post_repair_score`、`repair_status`、`repair_issue_count`、`repair_action_count`，修复后复检分数不再只存在于审计明细中。

## 3. 验证记录

- 单元/工作流测试：`python -m pytest -q` 全量 995 项通过。
- 新增回归覆盖：记忆读取链路、连续性锚点与快照、审计问题码、路由回写、检查点、报告一致性。
- 链式修复验证：单剧本端到端运行，10 镜 → 10 片段，审计分数 90 → 修复后 100，2 条中等严重度 `action_break` 告警按预期修复，报告状态与修复计数与日志一致。
- 代码检查：`ruff check` 对本次改动文件通过。

## 4. 升级说明

- 无破坏性改动，无需数据迁移；配置项、SDK 调用方式与契约 schema 保持兼容。
- 报告新增字段均为可选：
  - `quality_report.json`：`post_repair_score`、`repair_status`、`repair_issue_count`、`repair_action_count`。
  - `repair_history.json`：`continuity_repair_count`、`quality_repair`。
- `continuity_report.json` 的 `final_status` 新增取值 `continued_with_issues`，对应“已检查、存在不可自动修复问题、流程继续”的场景。依赖旧枚举值的下游请按未知值兜底处理。
- 建议升级后重新运行一次样本剧本，核对三份报告中的修复计数是否与运行日志一致。

## 5. 已知限制

- CI 当前仅运行 flake8，`pytest` 步骤处于注释状态，测试通过依赖本地执行。
- 本版端到端验证覆盖单个中文剧本样本，多语言、超长剧本与并发任务尚未纳入本版回归范围。
- `mypy` 类型检查存在存量债务，未在本版清理。
