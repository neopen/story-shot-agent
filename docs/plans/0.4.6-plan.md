> 依据：`docs/plans/0.4.6-spec.md`（spec-ok）
> 原则：确定性规则优先、不新增生成能力、最小改动、旧产物可读。

## 1. 总体架构与落点

改动集中在生成前链路，不触碰路由之后的资产执行：

```
SEGMENT_SHOT  ──►  时长重算 + 总时长报告        (A)
SPLIT_VIDEO   ──►  片段去重 / 合并 / 按动作重切  (B)
CONVERT_PROMPT──►  台词语言归一 + 首帧提示词清洗 (C、D)
ROUTE_MODEL   ──►  场景/运镜校验（0.4.5 既有，不改）
ASSETS        ──►  风格锚定兜底 (E)、服装材质回填 (F)
```

六个工作流：

| 编号 | 工作流 | 主要落点 |
| --- | --- | --- |
| A1 | 确定性时长函数 | `shot_segmenter/estimator/action_nodes.py`（新） |
| A2 | 时长接入与总时长报告 | `estimator/estimator_factory.py`、`estimator/action_estimator.py` |
| B | 片段去重与重切 | `video_splitter/fragment_dedupe.py`（新）、`base_video_splitter.py` |
| C | 台词语言 | `prompt_converter/script_language.py`（新）、`prompt_converter_models.py`、`llm_prompt_converter.py`、提示词模板 |
| D | 首帧提示词清洗 | `model_adapter/first_frame_builder.py` |
| E | 风格锚定兜底 | `continuity_guardian/style_anchors.py` |
| F | 服装材质回填 | `constants/appearance.py`、`character_sheet_generator.py`、`asset_generator_agent.py`、`workflow_nodes.py` |

A 拆为两步：A1 只落地纯确定性函数（动作节点计数、台词字数、`compute_duration`），不依赖 B；B 的重切直接调用 A1 的 `compute_duration` 判定子段是否过短，因此 A1 MUST 先于 B 完成。A2 再把 A1 接入 `estimator_factory` 并输出总时长报告，可与 B 并行但不得早于 A1。

## 3. 数据模型与接口契约

### 3.1 片段去重（B）

```python
# fragment_dedupe.py
def dedupe_fragments(
    fragments: List[VideoFragment],
    *,
    shots: Optional[Sequence[ShotInfo]] = None,
    max_duration: float = 5.0,
    min_duration: float = 2.5,
) -> Tuple[List[VideoFragment], List[Dict[str, Any]]]:
    """返回处理后的片段与操作报告（merge/resplit/truncate）"""
```

- 判定：同 `shot_type`、同 `main_character`、同 `scene_id`、动作动词集合有交集，任一两条即候选。
- `main_character` / `scene_id` 由 `fragment.shot_id` 在 `shots` 中反查；`shots` 缺失或反查失败时退回 `continuity_notes`。
- 结构化信息（`shots` 反查与 `continuity_notes`）均无法给出 `scene_id` 时，MUST NOT 直接放行：对相邻两片段剥离运镜短语后的提示词做 `difflib.SequenceMatcher` 比较，相似度 ≥ 0.85 仍 SHALL 标记为疑似重复，并在操作报告中注明 `matched_by=text_similarity`。
- 相似度兜底只对相邻片段生效，避免跨场景误判；命中后同样走 FR-071/072/073 的合并或重切链路。
- 合并：`duration = a.duration + b.duration`，描述按时间顺序拼接，运镜短语并入；`element_ids` 取并集。
- 重切：仅当存在 ≥2 个不同动作节点；按节点边界切分描述，时长按子句长度占比分配；每段做 `[min_duration, max_duration]` 校验。
- 子段过短：先与相邻子段合并；合并后仍 > `max_duration` 则按 FR-073 截断并告警。
- 处理后按顺序重编号 `frag_001…`，映射 `{新 ID: 原始 shot_id/fragment_id}` 写入 `metadata["fragment_id_map"]`；C/D 按 ID 取台词或首帧来源时 MUST 经该映射反查，不得假设 ID 连续。

### 3.2 时长（A1 / A2）

```python
# action_nodes.py
def count_action_nodes(text: str) -> int
def count_dialogue_chars(shot: ShotInfo, script: ParsedScript) -> int
def compute_duration_from_text(
    text: str,
    *,
    dialogue_chars: int = 0,
    has_motion: Optional[bool] = None,
    max_duration: float = 5.0,
    min_duration: float = 2.5,
) -> float
def compute_duration(
    shot: ShotInfo,
    script: ParsedScript,
    *,
    max_duration: float = 5.0,
    min_duration: float = 2.5,
) -> float
```

- `compute_duration` 读取 `shot` 的动作/描述与台词后转发给 `compute_duration_from_text`，保持单一口径。
- B 的重切子段没有独立 `ShotInfo` 时 MUST 调用 `compute_duration_from_text` 判定是否 `< min_duration`，不得另行硬编码 2.5s。
- 公式：`1.5`（静态）或 `2.0`（含运镜）+ `0.6 × 动作节点数` + `台词字数 / 4`，再夹取 `[2.5, 5.0]`。运镜判定复用 `camera_builder.detect_motion_from_text`，避免第二套词表。

`ShotSequence.stats` 新增：

```json
{
  "element_duration": 32.0,
  "target_duration": null,
  "duration_delta": null,
  "duration_source": "action_nodes"
}
```

`target_duration` 读取 `parsed_script.metadata["target_duration"]` 或 `stats["target_duration"]`；存在且差值 > 0 时才告警。

`prompt_converter_result.json` 的 `metadata.duration_report` 复制上述字段（由 CONVERT_PROMPT 节点写入）。

### 3.3 音频语言（C）

```python
class AIAudioPrompt(BaseModel):
    dialogue_language: Literal["zh", "en"] = Field(
        default="zh", description="台词语言，0.5 迁移为 dialogue_cues.language"
    )
```

```python
# script_language.py
def detect_script_language(parsed_script: Any) -> str
def normalize_audio_language(audio: AIAudioPrompt, language: str) -> AIAudioPrompt
```

- 推断：`metadata.language` > 正文 CJK 占比 ≥ 0.3 > `zh`。
- `zh`：移除英文台词引号句，`voice_description` 非中文时用 `emotion + voice_type` 映射中文描述。
- `en`：保留英文台词段；中文对照 MAY 保留在非台词描述段，位置由实现决定，MUST NOT 进入 `audio.prompt` 的台词描述段。
- 实现层收紧：本版把中文对照固定放在 `\n\n` 之后的注释段，依据 FR-087 的 MAY 授权，使“台词段单语言”可被断言；若后续需要放宽，只改 `normalize_audio_language` 的落点，不改契约。
- 模板同步要求 LLM 输出 `dialogue_language`；解析层以确定性归一为准。

_SHOT_PREFIX_RE = re.compile(r"^(?:大?全景|远景|中近景|中景|近景|极?特写|过肩|主观|双人)镜头?\s*[：:]\s*")

### 3.5 风格锚定（E）

- `collect_mood_evidence` 增加场景 `audio_context.env_sounds[].description` 扫描；`MoodEvidence.resolved_by` 同步收敛为 `extracted`（命中）/空（未命中），`explicit_audio_atmosphere`、`keyword_scan` 等细分只留在 `MoodEvidence.source`。
- 新增 `collect_lighting_evidence`：扫描场景地点/描述中的 `冷白/昏暗/刺眼/暖黄/霓虹/阳光`。
- `_build_provenance` 新增顶层 `source`（来源细分）以及 `lighting_source`、`lighting_keyword`、`defaults_applied`。
- `resolved_by` SHALL 只取 `extracted` 或 `default_fallback`：任一既有证据或 FR-091 扩展证据命中即记 `extracted`，全部未命中时进入 FR-088 兜底并记 `default_fallback`。
- `no_signal` 已被 FR-089 禁止，本版不再保留该取值；判断“genre 无信号”改看 `genre_source is None` 与空的 `genre_candidates`，不以 `resolved_by` 表达。
- 来源细分写入 `provenance.source`，取值固定为 `field_priority` / `audio_atmosphere` / `env_sound` / `lighting_keyword` / `keyword_scan`，优先级同序；`mood_only` 不再作为独立取值，genre 为空由 `genre_source is None` 判断。`explicit_audio_atmosphere` 与 `keyword_scan` 不再出现在 `resolved_by`，避免与 FR-091 的 `extracted` 语义冲突。
- 既有测试中断言 `field_priority` / `mood_only` / `explicit_audio_atmosphere` / `keyword_scan` 的用例同步改为“`resolved_by` + `provenance.source`”组合断言。
- 无信号时补 `mood=neutral`、`lighting=natural lighting`、`palette=muted colors`；`genre` 保持为空。
- 默认值只填空缺，不覆盖显式维度；`description` 由 `build_style_text` 统一渲染。

### 3.6 服装材质（F）

```python
def backfill_character_outfits(
    plan: Any,
    texts_by_character: Mapping[str, Sequence[Tuple[str, str]]],
    script_materials: Optional[Mapping[str, str]] = None,
    manifest: Any = None,
) -> List[str]:
```

- `script_materials`：`global_metadata.character_outfits` 中角色 → `material`。
- 候选顺序：剧本材质 > 片段提示词。
- 回填后重新计算 `_missing_outfit_fields`：为空则删除 `outfit_missing_fields`、关闭 `requires_special_attention`；非空则保留标记并写明剩余项。
- `outfit_backfill_source` 记录 `script:character_outfits.material` 或片段 ID。
- 保护：`asset_ref` 非空、`metadata.human_edited`、清单 `revision > 0` 任一成立即跳过。
- `manifest is None` 时的“按未编辑处理”是 FR-096 在无清单场景下的已知降级，属于有意的权衡：无法确认 `revision` 时仍允许回填，风险是可能覆盖未落盘的人工编辑；因此 `asset_ref` 与 `metadata.human_edited` 必须优先检查，命中即跳过，并统一记 `info` 说明“无 revision 信息，按未编辑处理”。

## 5. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 重编号导致下游引用错位 | 去重发生在 SPLIT_VIDEO，路由与资产回填均在其后；同时输出 `fragment_id_map` 并落盘 |

| FR-075 改变全部时长，既有测试与历史统计失效 | 先更新 `test_action_duration.py`，再用两轮样本回放确认；保留 estimator 作为无描述回退 |
| 8 动作节点重切后子段过短 | 严格走 FR-073a 合并 → 截断链路，不产生 <2.5s 或 >5s 片段 |

| 材质回填覆盖人工修改 | 三重保护（asset_ref / human_edited / revision），无清单时记 info |
| 模板改动影响 0.4.5 模板召回测试 | 更新 `test_prompt_template_metadata.py` 的版本断言；保留旧模板兼容读取 |

## 7. 实施顺序（供 TASKS 拆解）

| 顺序 | 工作流 | 理由 |
| --- | --- | --- |
| 1 | A1 确定性时长函数 | 纯函数、无依赖；B 的重切需要它判定子段是否 <2.5s |

| 5 | C 台词语言 | 涉及模型与模板，改动面中等 |
| 6 | E 风格兜底 | 需先明确证据优先级 |
| 7 | F 服装材质 | 依赖资产回填链路，最后收口 |
