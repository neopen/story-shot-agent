# PenShot 0.4.5 执行清单

## 背景

0.4.4 已发布（Experimental Preview），管线端到端可用，连续性守护能自动检测并修复场景跳转（13 片段产出里的 frag_005 是证据）。但产出仍有三个数据级问题，导致用户拿到 JSON 后"看起来完整、实际不能用"。0.4.5 不新增 feature，只修这三个断点。

---

## 必须做（P0，三条全做，缺一条 0.4.5 就不算完成）

### 任务 1：资产从 `pending` 到可回填

**现状**：`asset_plan` 里 8 个资产全部 `status: "pending"`、`asset_ref: ""`。`fix(routing): 图生视频 asset_ref 仅取场景首帧` 已修路由，但资产本身没生成，路由空转。

**要做**：
- 在 `asset_plan` 生成后，增加一个"资产执行器"节点或独立脚本，调用图像生成 API（至少支持三视图和场景图）产出图片，回填 `asset_ref` 和 `status: "ready"`。
- 如果 0.4.5 不接入真实图像生成，则必须提供"下游回填接口 + 示例回填脚本"：用户拿到 pending 资产后，按格式填 `asset_ref`，系统能校验并转为 ready。

**验收标准**：跑一次完整链路后，`asset_plan` 里至少 `char_001` 和 `scene_001` 的 `status` 不是 pending，`asset_ref` 非空。

---

### 任务 2：角色服装描述的完整性校验

**现状**：`char_002` 的 `image_prompt` 是"可能是浅色连衣裙或套装"，`char_003` 是"白色深蓝色棉质"（截断，没说是什么衣服）。0.4.4 有 `fix(appearance): 修复角色外观锚点混写与自由文本噪声`，但产出里这两处没被修。

**要做**：
- 在 `character_sheet` 生成前，加校验：服装描述必须包含"类型 + 颜色 + 材质"三要素；含"可能""或""之类"等不确定词时，判定为不完整。
- 不完整时，优先回退到拆解稿的 `character_outfits` 字段（那里有"蓝白相间校服""黑色宽松运动T恤"等明确描述）；回退不到时，标记 `requires_special_attention: true` 并在 `metadata` 里写明原因。

**验收标准**：`char_002` 和 `char_003` 的 `image_prompt` 不再出现"可能是""或"，且包含明确的服装类型。

---

### 任务 3：`style_anchor.description` 与片段 style 前缀对齐

**现状**：`asset_plan.style_anchor.description` 仍残留 `muted colors, melancholic tone`，片段 style 前缀已去掉。资产图和片段视频风格不一致。

**要做**：
- `asset_plan` 生成 `style_anchor` 时，复用与片段相同的 `style_anchor_provenance` 决议结果，不要独立保留一份旧的 `description`。
- 如果 `discarded` 字段里记录了被丢弃的维度（如 `muted colors`、`melancholic tone`），`asset_plan.style_anchor.description` 里不能出现这些词。

**验收标准**：`asset_plan.style_anchor.description` 不含 `muted colors` 和 `melancholic tone`，且与 13 个片段的 style 前缀一致。

---

## 应该做（P1，时间允许就做，不做不阻塞发布）

### 任务 4：`usage.fragments` 精确化

**现状**：`prop_001`（便利贴）和 `prop_003`（篮球）的 usage 覆盖 frag_005 到 frag_013 全部 9 个片段，但 frag_012 里既没有便利贴也没有篮球。

**要做**：回填 `usage.fragments` 时，检查片段 prompt 里是否真的提到了该资产名或对应描述词，没提到的不写进 usage。

---

### 任务 5：`camera.motion` 与 prompt 一致性校验

**现状**：frag_013 的 prompt 写 `slow push-in`，但 `camera_control.motion` 是 `static`。

**要做**：构建 `camera` 时，从最终 prompt 解析运动动词（push-in、dolly、handheld、zoom 等），与 `motion` 字段比对，不一致就覆盖或标 warning。

---

### 任务 6：跑一次 E2E 真实链路

**现状**：`AC-E2E-003`（带 `asset_manifest` 的真实链路）依赖外部 LLM，0.4.4 未联网执行。

**要做**：至少跑一次，把结果写进 0.4.5 Release Notes。结果不完美也比"未执行"有说服力。

---

## 不做（明确划出边界，避免范围蔓延）

- 不新增 feature（0.4.5 是修数据级问题，不是加能力）。
- 不改切割器的"超过 5 秒才拆"规则（这是设计选择，不是 bug；高密度短镜头的问题留到 0.4.6）。
- 不做"透明人比喻的视觉化"（这是语义级叙事完整性问题，需要 quality_audit 新增规则，放到 0.4.6 或 0.4.7）。
- 不做 RAG 召回精度优化（5/13 命中率可接受，加诊断字段的事放到后续版本）。

---

## 给 AI 编码助手的执行顺序

1. 先做任务 3（style_anchor 对齐）——改动最小，只需复用 `style_anchor_provenance` 的决议结果，风险最低。
2. 再做任务 2（服装完整性校验）——需要改 `character_sheet` 生成逻辑，加校验和回退，中等复杂度。
3. 最后做任务 1（资产回填）——最复杂，涉及执行器或回填接口，但它是用户最痛的点，必须做。
4. 任务 4、5 如果时间允许，在任务 1-3 完成后穿插做。
5. 任务 6 在发布前跑，结果写进 Release Notes。

---

## 验收标准（0.4.5 发布前必须全部满足）

- [ ] 跑一次完整链路后，`asset_plan` 里至少 2 个资产的 `status` 不是 `pending` 且 `asset_ref` 非空。
- [ ] `char_002` 和 `char_003` 的 `image_prompt` 不含"可能是""或"，服装描述包含明确类型。
- [ ] `asset_plan.style_anchor.description` 不含 `muted colors` 和 `melancholic tone`。
- [ ] `pytest` 全量通过，`ruff check` / `ruff format` 通过，`mypy` 无新增错误。
- [ ] E2E 真实链路至少跑过一次，结果写入 Release Notes（无论成败）。
- [ ] 13 片段示例产出重新导出，与 0.4.5 的修复结果一致。

---

## 发布口径

0.4.5 仍然是 **Experimental Preview**，标题勾选 pre-release。Release Notes 的"已知事项"如果任务 1-3 全部完成，可以删掉"资产 pending""角色服装描述可能不完整""style_anchor 残留"这三条；如果只完成部分，保留未完成的那几条。

> **不要在 Release Notes 里写"已修复"而实际产出里仍然存在——这是 0.4.4 的教训（`fix(appearance)` 声称修了，但 `char_002`/`char_003` 没变）。**
