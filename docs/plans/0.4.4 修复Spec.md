## 1. 功能目标

修复 0.4.3 产出的分镜结果在**角色锚点、资产引用、风格、景别、召回可观测性、资产提示词**六个方面的内部矛盾与信息缺失，使下游拿到的 `prompt_converter_result.json` 自身自洽、可追溯、可直接消费。

---

## 2. 范围界定

### 2.1 范围内

| 编号 | 能力 | 对应缺陷 |
|---|---|---|
| A | 角色外观锚点结构化，情绪/动作不再混入服装 | 问题 1 |
| B | 三视图降级为身份参考，新增片段场景首帧；资产 `usage.fragments` 回填 | 问题 1c、问题 2 |
| C | 统一风格模型、题材判定校验与打光冲突消解 | 问题 4 |
| D | 景别词表统一，`camera` 与最终 prompt 一致 | 问题 5 |
| E | 锚点召回链路修复与可观测化（加载兼容、重建优先、诊断原因） | 问题 3 |
| F | 角色/道具/场景资产提示词质量重建 | 问题 6 |
| G | 增加对应质量门禁，防止回归 | 本次缺陷未被审计拦截 |
| H | 一次性数据迁移：隔离旧缺陷模板、重建索引、校准召回阈值 | 0.4.3 已入库的 127 条模板会污染后续召回 |

### 2.2 Non-Goals（禁止实现）

- 不调用任何文生图 / 文生视频 API，不新增供应商或密钥。
- 不改变工作流拓扑、节点顺序、`AgentStage` / `PipelineNode` 枚举；本修复全部为既有节点内的确定性后处理。
- 不做 0.5 音频边界、NeoTask 事件契约、唇形同步、混音等音频工作。
- 不重做模型路由策略、能力表、评分权重；仅修正景别归一与探针。
- 不更换嵌入模型与向量库，不重写检索排序算法；召回修复仅限索引加载兼容、缓存/索引一致性、重建策略与诊断字段。
- 不重构 `TaskFactory`、任务层、记忆层架构。
- 不删除既有输出字段，不改变 `usage.characters` / `usage.scenes` 的既有语义。
- 不实现视频级质检（VQA / VLM / OCR / Pose）。
- 不以“重新调用 LLM 重写”作为修复手段；风格、景别、资产使用范围、锚点均须确定性产出。

### 2.3 兼容性边界

- 输出字段以**加法**为主；新增字段缺失时下游必须能忽略。
- `references[].as_first_frame` 语义发生变更，`asset_ref` 语义随之收紧（见 8.1），必须提升 `schema_version` 并在下游文档中显式说明。
- 旧版 `asset_manifest` 必须继续可解析，不得因新增字段报错。
- `include_global` 参数不得继续作为“声明但无效”的死参数存在：要么实现跨剧本召回，要么移除。

## 3. 使用者与业务场景

| 使用者 | 关注点 | 典型场景 |
|---|---|---|
| 下游视频生成管线 | 首帧图、身份参考、场景参考是否可直接执行 | 读取 `route_plan.adapted_packages[]` 调用图生视频 |
| 下游资产服务 | 应按哪些片段生成哪些资产 | 读取 `asset_plan.assets[].usage.fragments` 做按需生成 |
| 评审 / 运维 | 一致性召回为什么没生效 | 查看 `metadata.anchor_recall` |
| PenShot 开发者 | 同一输入是否稳定、可回归 | 用保存的阶段结果做确定性单测 |

关键业务场景：

1. 首次运行某剧本，无历史提示词模板。
2. 第二次及以后运行，知识库已有成功提示词。
3. 下游随任务提交 `asset_manifest` 回填真实资产引用。
4. 剧本只有自由文本角色描述，没有结构化 `character_outfits`。
5. 分镜出现 `over_shoulder`、`extreme_close_up`、`long_shot` 等扩展景别。
6. 多个场景共享同一地点，但时间/天气不同。
7. 质量审计结果为 `minor_issues`，而非完全通过。
8. 同一角色跨多个片段出现，服装与身份必须稳定。
9. 同一剧本已有历史模板，但索引文件由当前 llama-index 版本持久化（`default__vector_store.json`）。
10. 剧本内题材信号互相冲突：场景文本写“紧张”，音频氛围写“温暖浪漫”。
11. 上游显式给出非规范题材值（如 `cinematic`），或完全没有题材字段。
12. 新剧本首次运行，但其他剧本已有可复用的活跃模板，需要跨剧本冷启动召回。
13. 首次运行审计为 `minor_issues`，需要以 `cold_start_seed` 方式入库以启动后续召回。

## 4. 功能需求清单

### 4.1 A — 角色外观锚点

- **FR-001** WHEN 解析结果包含 `global_metadata.character_outfits` 且存在该角色记录 THEN 系统 SHALL 优先使用其中的颜色、风格、材质、服装描述生成外观锚点。
- **FR-002** WHEN 结构化服装缺失、需要回退到角色自由文本描述 THEN 系统 SHALL 只提取外观类子句，并排除包含情绪、表情、表演、动作、道具、场景词的子句。
- **FR-003** 系统 SHALL NOT 在子句内部按字符数截断外观锚点；长度限制只能在子句边界生效，禁止出现“湿漉”这类半截词。
- **FR-004** `appearance_anchors` SHALL 只允许外观白名单字段：`age`、`gender`、`body`、`hair`、`face`、`clothing`、`accessories`；情绪字段 SHALL NOT 出现在 `clothing` 或任何外观锚点中。
- **FR-005** 同一角色的外观锚点在所有片段中 SHALL 完全一致，不因片段描述差异而变化。
- **FR-006** WHEN 片段需要表达情绪 THEN 情绪 SHALL 由片段级提示词或独立的片段级字段承载，不得写回角色契约。

### 4.2 B — 首帧语义与资产使用范围

- **FR-010** 角色三视图 SHALL 只作为身份参考：`references[].role = "identity_reference"`，`references[].as_first_frame = false`。
- **FR-011** WHEN 片段采用 `image_to_video` THEN 系统 SHALL 为该片段产出一个**片段专属首帧静帧提示词**，其内容由场景锚点、角色外观、景别、片段动作共同决定；该提示词 SHALL NOT 等于角色三视图提示词。
- **FR-012** `asset_plan.assets[].usage.fragments` SHALL 在路由完成后回填：
  - 角色资产：所有以该角色为主角的片段；
  - 场景资产：所有位于该场景地点下的片段；
  - 道具资产：所有位于该道具 `appears_in` 场景下的片段。
- **FR-013** 对 `route_plan` 中每个 `references[].asset_id`，对应资产的 `usage.fragments` SHALL 包含该片段 ID；即引用集合必须是使用范围的子集。
- **FR-014** 回填完成后，`asset_plan.json` 与 `prompt_converter_result.json` 中的两份资产计划 SHALL 保持一致，且均为回填后的版本。
- **FR-015** 未被任何片段使用的资产允许 `usage.fragments` 为空，但 MUST 能通过 `usage.characters` / `usage.scenes` 解释其存在原因。
- **FR-016** `asset_ref` 的语义 SHALL 收紧为“首帧静帧引用”；角色三视图的真实引用 MUST NOT 写入 `asset_ref`，只能出现在 `references` 中。

### 4.3 C — 风格模型

- **FR-020** 风格锚点 SHALL 按 `genre`、`lighting`、`palette`、`mood`、`framing`、`grade` 六个维度建模；未知维度可忽略，不得报错。
- **FR-021** 渲染到 `[Style: ...]` 前缀时，每个维度 SHALL 最多出现一个值。
- **FR-022** 推断优先级 SHALL 为：显式元数据 > genre 规范风格 > 显式氛围 > 关键词扫描 > 默认值。
- **FR-023** 中文氛围词 SHALL 覆盖“清新、治愈、温暖、浪漫、压抑、紧张”等本次样本出现的词；在 **mood 维度**，显式 `audio_atmosphere` MUST 优先于对场景文本的一阶关键词扫描（genre 维度仍按 FR-028 的证据优先级）。
- **FR-024** 同一画面中 SHALL NOT 同时出现互斥打光（如 `soft warm lighting` 与 `high contrast lighting`）；冲突时保留高优先级来源，丢弃项写入诊断信息。
- **FR-025** 片段风格前缀、`fragment.style`、资产提示词风格描述 SHALL 使用同一解析结果；三视图 MUST 使用中性棚拍光，不得使用剧情氛围打光。
- **FR-026** 11 个片段最终渲染出的风格前缀 SHALL 完全一致（当输入契约一致时）。
- **FR-027 题材规范化**：WHEN 显式元数据（`metadata.genre` / `style` / `category`）提供题材 THEN 系统 SHALL 仅当其值属于规范题材集合（`GENRE_STYLE_MAP` 键或显式题材枚举）时才写入 `genre`；非规范值（如 `cinematic`、`neo-noir`）SHALL 转入 `style_description` 候选或忽略，并记录 `genre_rejected`，MUST NOT 直接作为 `genre` 渲染到风格前缀或资产计划。
- **FR-028 证据优先级**：题材推断 SHALL 按字段优先级执行：显式题材 > 标题 > 场景地点/描述 > 连续性要点 > 音频氛围；`audio_atmosphere` 属于弱证据，SHALL NOT 单独决定 `genre`（除非其余字段均无信号且标记 `confidence=low`）；每次推断 MUST 记录 `genre_source`（字段名）与 `genre_keyword`（命中的原始词）。
- **FR-029 冲突与溯源**：WHEN 多个字段给出互斥题材/氛围候选（如场景文本含“紧张”、音频氛围含“温暖浪漫”）THEN 系统 SHALL 按 FR-028 优先级决议，并输出 `metadata.style_anchor_provenance`：`genre_source`、`genre_keyword`、`genre_candidates`、`genre_conflict`、`mood_source`、`mood_candidates`、`resolved_by`、`discarded`；`genre` 与 `mood`/`lighting` 冲突时 MUST 按 FR-024 消解；无法可靠判定时 `genre` 允许为空，MUST NOT 用默认题材补位。

### 4.4 D — 景别一致性

- **FR-030** 景别词表 SHALL 覆盖 `ShotType` 枚举全部值，至少包括 `wide_shot`、`long_shot`、`medium_shot`、`close_up`、`extreme_close_up`、`over_shoulder`、`pov`、`two_shot`、`following_shot`，以及“全景、远景、中景、近景、特写、极特写、过肩、主观、双人”等中文别名。
- **FR-031** `camera.shot_type` SHALL 与最终提示词文本中的景别表述一致；探测顺序为“最终 prompt 文本 > 来源镜头景别 > 默认值”。
- **FR-032** WHEN 来源景别是已知扩展景别（如 `over_shoulder`）THEN 系统 SHALL 输出对应值，MUST NOT 静默降级为 `medium_shot`。
- **FR-033** WHEN 来源景别完全未知 THEN 系统 SHALL 保留原始值或显式映射并在日志中告警，MUST NOT 无告警地覆盖为默认值。
- **FR-034** `camera` SHALL 保留 `source_shot_type` 字段用于溯源；`camera.shot_type` 的取值 SHALL 统一使用 `ShotType` 的字符串值。

### 4.5 E — 锚点召回链路与可观测性（含回归修复）

> 0.4.3 样本的 `hits = 0` **不是冷启动**：该剧本在本轮运行前已有 116 条历史模板（11-05/06/08 入库），但模板索引加载器以旧文件名 `vector_store.json` 判定“无索引”，导致检索直接返回空；随后 `add_template` 又用单文档新索引覆盖了既有 `index_store`。证据见 §8.8。

- **FR-040** `metadata.anchor_recall` SHALL 至少包含：`fragments`、`queries`、`queries_skipped`、`attempted`、`hits`、`status`、`kb`（`template_count` / `index_docs` / `legacy_templates` / `global_template_count` / `global_scripts` / `has_index` / `storage_dir`）、`min_score`、`max_score`、`top_k`。
- **FR-041** `status` SHALL 取值于：`hit`、`hit_global`、`first_run_no_history`、`first_run_global_hit`、`empty_templates`、`index_unavailable`、`index_load_failed`、`cache_index_mismatch`、`embeddings_unavailable`、`all_below_threshold`、`retrieval_error`。
- **FR-042** `queries` SHALL 只统计成功构造出锚点查询的片段，`queries_skipped` 统计因无锚点被跳过的片段，`attempted` 统计实际执行的检索次数；MUST NOT 直接使用片段总数冒充查询数。
- **FR-043** `first_run_no_history` SHALL 仅在“当前剧本缓存模板数为 0、无可加载索引且跨剧本召回无命中”时出现；若当前剧本为空但跨剧本命中，`status` SHALL 为 `first_run_global_hit`；只要存在当前剧本历史或全局命中，MUST NOT 返回 `first_run_no_history`。
- **FR-044 跨剧本冷启动召回（已确认实现，默认 `include_global=True`）**：`include_global=True` 时，系统 SHALL 在当前剧本无可用模板或同剧本零命中时，回退检索其他剧本的活跃模板；同剧本结果优先占用名额，跨剧本结果只补足剩余名额；每条命中 MUST 标注 `source_scope`（`script` / `global`）与来源 `script_id`；跨剧本召回 MUST NOT 写入当前剧本缓存或索引；默认排除 `legacy` 模板。
- **FR-045** 成功提示词入库策略 SHALL 在两个入库点（`quality_audit_node` 与 `WorkflowMemory._update_knowledge_manager_with_success`）保持一致：默认只接收“审计通过，或分数不低于 90 且无 major/critical”的结果；**首次运行例外**：当该剧本活跃模板数为 0 时，不强制分数门槛，只要不含 `major` / `critical` 即可入库，`source` 标记为 `cold_start_seed`；第二次及以后恢复严格阈值；入库 `source` MUST 反映真实审计状态，MUST NOT 对 `minor_issues` 结果标记为 `quality_audit_passed`；入库 metadata SHALL 新增 `schema_version` 与 `audit_status`；召回默认排除 `schema_version = legacy` 的模板，`anchor_recall.kb.legacy_templates` MUST 给出被排除数量。
- **FR-046 索引加载兼容性**：`PromptTemplateManager._load_index_for_script` SHALL 兼容 llama-index 当前持久化格式：`default__vector_store.json` + `docstore.json` + `index_store.json` 任一有效组合即视为可加载；MUST NOT 以旧文件名 `vector_store.json` 缺失作为“无索引”判据。
- **FR-047 重建优先于覆盖**：WHEN 索引加载失败但缓存非空 THEN 系统 SHALL 先从缓存全量重建索引（复用既有 `_rebuild_index_for_script`）再检索或写入；`add_template` MUST NOT 在加载失败时用“单文档新索引”覆盖既有 `index_store`。
- **FR-048 缓存/索引一致性**：WHEN `len(cache) != index_docs` THEN 检索前 SHALL 触发一次全量重建，并在 `anchor_recall` 中记录修复前后的模板数与文档数；同一任务内 MUST NOT 重复重建。
- **FR-049 检索诊断**：`search_similar` SHALL 返回结构化诊断（`status`、检索条数、最高分、异常信息），使调用方能够区分“无模板 / 索引不可用 / 索引加载失败 / 分数不达标 / 检索异常”；MUST NOT 用空列表静默表示所有失败原因。
- **FR-049A 阈值校准**：`min_similarity_score` SHALL 基于样本实测校准，禁止继续沿用未经验证的 `0.7`：对 11 条锚点查询各取 top-1 分数，记录 `min` / `P50` / `max`；默认阈值取 `max(0.45, floor(P50 × 20) / 20)`；若 `P50 < 0.45`，保留 `all_below_threshold` 并告警“模板与查询语义不匹配”，MUST NOT 无依据继续下调阈值。校准结果 SHALL 写入配置、PLAN 与发布说明。

### 4.6 F — 资产提示词质量

- **FR-050** 角色三视图提示词 SHALL 只描述静态外观，顺序为：年龄/性别 → 发型/面部 → 上装 → 下装 → 鞋 → 配饰。
- **FR-051** 三视图提示词 SHALL NOT 包含表演状态（如“带哭腔”）、瞬时动作（如“骑着电动车”“掏出毛巾”）、道具（如《飞鸟集》）或剧情场景。
- **FR-052** 同一语义内容 SHALL 只出现一次；拼接前必须做归一化去重。
- **FR-053** 三视图提示词 SHALL 使用中性棚拍光与中性背景，MUST NOT 拼接剧情氛围打光。
- **FR-054** 道具与场景提示词 SHALL NOT 直接拼接原始 `genre` 标签作为画面风格；风格描述 SHALL 来自 4.3 的维度解析结果。
- **FR-055** 资产提示词长度 SHALL 在构建阶段受控，超限时在子句边界裁剪，MUST NOT 产生半截词。

### 4.7 G — 质量门禁

- **FR-060** 审计 SHALL 检测外观锚点字段污染：`clothing` 含情绪/动作/表演词、锚点含半截词、同一锚点混入多个语义域。
- **FR-061** 审计 SHALL 检测 `camera.shot_type` 与最终提示词景别表述不一致。
- **FR-062** 审计 SHALL 检测风格前缀中的互斥打光并存。
- **FR-063** 审计 SHALL 检测 `route_plan` 引用资产在 `usage.fragments` 中缺失。
- **FR-064** 上述任一违规 SHALL 在 `quality_auditor_result.json` 中以可定位的 `fragment_id` / `asset_id` 呈现；严重级别至少为 `warning`，影响下游执行的为 `major`。

### 4.8 H — 一次性数据迁移与阈值校准

- **FR-065 安全迁移**：迁移脚本 SHALL 默认 dry-run（只输出统计、不写文件）；仅在显式 `--apply` 时写入；默认处理 `data/embedding/prompt_templates/` 下全部剧本（因跨剧本召回会使用其他剧本模板），`--script-id` 可限定单剧本；每个被写入的剧本目录 MUST 先备份 `templates_cache.json` 与 `index_store/` 到带时间戳的备份目录。
- **FR-066 缺陷模板隔离**：脚本 SHALL 依据确定性签名识别 0.4.3 缺陷模板（污染锚点含“手持手帕和湿漉”“神情焦急”、互斥打光并存、`source=quality_audit_passed` 但无 `audit_status`），将其移入隔离清单并从活跃检索中移除；MUST NOT 直接删除底层数据。其中 `source=quality_audit_passed` 且无 `audit_status` 仅作为旧模板的辅助判定，MUST NOT 单独构成隔离条件；隔离以内容签名（污染锚点 ∪ 互斥打光）为准。迁移报告 SHALL 输出 `template_count_before` / `quarantined_count` / `legacy_count` / `active_count`，并满足 `quarantined_count + legacy_count + active_count = template_count_before`。
- **FR-067 旧模板标记与重建**：未被隔离但缺少 `schema_version` 的模板 SHALL 标记为 `schema_version = legacy`、`audit_status = unknown`；迁移报告 metadata SHALL 包含 `legacy_count` 与 `active_count`；迁移完成后 SHALL 从活跃缓存全量重建索引，并报告迁移前后模板数与索引文档数。
- **FR-068 幂等与回滚**：重复执行 `--apply` MUST NOT 产生新的变更；任一写入失败 SHALL 可从备份完整恢复，并输出回滚指令。

## 5. 非功能性约束

- **NFR-001 确定性**：相同输入（阶段结果 + 契约）必须得到相同的锚点、风格前缀、景别、资产使用范围与资产提示词，不依赖 LLM 随机性。
- **NFR-002 兼容性**：新增字段为可选；旧 `asset_manifest`、旧 SDK 调用方式保持可用；版本号与 `schema_version` 同步。
- **NFR-003 日志**：所有丢弃、降级、未知映射、冲突消解必须记录 `warning` / `debug`，禁止静默回退。
- **NFR-004 性能**：新增逻辑只做内存遍历，复杂度不高于 O(片段数 × 资产数)；索引重建仅在检测到缓存/索引不一致时执行一次，MUST NOT 在每个片段或每次检索时重复；不得新增 LLM 调用。
- **NFR-005 安全**：运行时不引入外部网络、密钥或新的文件写入路径；一次性迁移脚本仅在显式 `--apply` 下写入 `data/` 内模板目录，且必须先备份；不记录敏感信息。
- **NFR-006 可测试**：各修复项均须有单元测试；使用本次保存的阶段结果与模板缓存作为确定性 fixture，不依赖在线 LLM。
- **NFR-007 回归**：现有 52 个相关单测全部通过；不允许以修改断言的方式掩盖缺陷，除非断言本身描述的是被本 Spec 明确变更的契约。
- **NFR-008 代码规范**：中文注释与文档字符串，ruff / ruff-format / mypy 通过；新增逻辑放入对应 agent 包，不继续膨胀 `workflow_nodes.py`。

## 6. 边界与异常场景

| 场景 | 期望行为 |
|---|---|
| 剧本无 `character_outfits` | 回退自由文本外观子句；仍无有效子句则不注入服装锚点，不得输出垃圾文本 |
| 角色描述只有一句混合情绪与服装 | 只保留服装子句，情绪丢弃；若无法切分则锚点留空并告警 |
| 片段无主角色（如 frag_005） | 不注入角色锚点；场景/道具使用范围仍正常回填 |
| 同一地点对应多个场景且时间不同 | 场景资产仍按地点去重；`usage.fragments` 取该地点下全部片段 |
| 道具 `appears_in` 的场景不存在 | 该道具使用范围为空并告警，不影响其他资产 |
| 角色资产存在但无任何片段使用 | 允许保留资产，`usage.fragments` 为空，`usage.characters` 非空 |
| 片段提示词无显式景别 | 使用来源镜头景别；来源也缺失时使用默认值并告警 |
| 来源景别为 `over_shoulder`、`pov`、`two_shot` | 原样输出，不得降级 |
| 风格来源互相冲突 | 按 FR-022 / FR-024 优先级保留一个，丢弃项写入诊断 |
| genre 未知、氛围为中文 | 通过中文氛围映射得到风格；无法映射时使用稳定默认值 |
| 显式 genre 为非规范值（如 `cinematic`） | 不作为 `genre`；转入 `style_description` 或忽略，并记录 `genre_rejected` |
| genre 仅由 `audio_atmosphere` 命中 | 视为弱证据，标记 `confidence=low`；存在场景/标题信号时不得采用 |
| genre 与氛围候选互斥（如场景“紧张”、氛围“浪漫”） | 按字段优先级决议，`genre_candidates` 与 `resolved_by` 写入 provenance |
| 所有题材字段均无信号 | `genre` 留空，风格前缀只由 `mood` / `lighting` 构成，不得用默认题材补位 |
| 索引目录由新版 llama-index 持久化（`default__vector_store.json`） | 正常加载，不得判为“无索引” |
| 索引加载失败但缓存非空 | 从缓存全量重建后再检索，`status` MUST NOT 为 `first_run_no_history` |
| 当前剧本无模板、其他剧本有活跃模板 | 跨剧本召回，`status = first_run_global_hit`，命中标注 `source_scope=global` 与来源 `script_id`；不写当前剧本 |
| 当前剧本与全局均有命中 | 同剧本优先，全局只补足剩余名额 |
| 其他剧本索引不可用或嵌入失败 | 跳过该剧本并记录 `global_scripts` 失败原因，不影响当前剧本结果 |
| `include_global=False` | 只检索当前剧本，不触发跨剧本回退 |
| 首次运行且存在 major / critical | 不入库；`cold_start_seed` 例外不适用于严重缺陷 |
| 缓存模板数大于索引文档数 | 检索前重建一次，记录修复前后数量；`anchor_recall.kb` 反映真实值 |
| 知识库无索引 / 无模板 / 嵌入不可用 | `anchor_recall.status` 给出对应原因，不抛异常、不阻断流程 |
| 召回分数全部低于阈值 | `status = all_below_threshold`，并记录 `min_score`、`max_score` 与模板数量 |
| 历史模板含旧版缺陷风格前缀 | 入库 metadata 带 `schema_version` / `audit_status`；召回结果按来源标注，`legacy_templates` 计数可见 |
| 迁移脚本未加 `--apply` | 只输出将要隔离/标记的数量，不写任何文件 |
| 迁移过程中写入失败 | 从备份恢复，输出回滚指令，不留下半迁移状态 |
| 对同一脚本重复执行迁移 | 幂等，第二次输出 0 变更 |
| 阈值校准样本 P50 小于 0.45 | 保留 `all_below_threshold` 并告警“模板与查询语义不匹配”，不继续下调 |
| 迁移后活跃模板为 0 | 索引置空，召回状态为 `empty_templates`，不阻断主流程 |
| 审计结果为 `minor_issues` | 不阻断主流程；但带 major/critical 的缺陷不得入库 |
| 下游提交非法 `asset_manifest` | 保持既有降级行为：忽略非法回填，计划保持 pending |
| 下游只支持单首帧、不支持多参考图 | 保留身份参考声明；下游可自行回退文生视频，PenShot 不强制 |
