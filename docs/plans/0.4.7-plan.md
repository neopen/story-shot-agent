## 1. 总体架构与落点

改动全部位于 `CONVERT_PROMPT → ROUTE_MODEL → AUDIT_QUALITY` 三段，不触碰资产执行与下游生成：

```
CONVERT_PROMPT ──► 地点确定性重写/阻断 + 景别短语归一 + 修复编码匹配   (S2、S3、R1~R3)
ROUTE_MODEL    ──► 镜头计划场景权威 + 阻断状态传递                     (S1)
AUDIT_QUALITY  ──► issue_codes 契约 + 空问题过滤 + 场景锚点违规 + 状态语义 (R1~R4、S4)
OUTPUT         ──► 不变（人工项/阻断片段已由既有 warnings 通道承载）
```

三个问题域与工作流编号：

| 编号 | 问题域 | 主要落点 |
| --- | --- | --- |
| S1 | 场景权威 | `model_adapter/first_frame_builder.py`、`model_adapter/image_to_video.py` |
| S2 | 地点重写与阻断 | `prompt_converter/scene_prompt_realign.py`（新）、`prompt_converter_agent.py` |
| S3 | 景别归一与探测器 | `prompt_converter/camera_builder.py`、`prompt_converter/base_prompt_converter.py`、`prompt_converter_agent.py`、`quality_auditor/rule_quality_auditor.py` |
| S4 | 场景锚点审计 | `model_adapter/image_to_video.py`、`workflow/workflow_nodes.py`、`quality_auditor/rule_quality_auditor.py` |
| R1 | 修复编码契约 | `quality_auditor/quality_auditor_models.py`、`quality_auditor_agent.py` |
| R2 | 阶段处理器按编码命中 | 各 `*_agent.py` / `rule_*` / `llm_*` 修复入口 |
| R3 | 修复动作计数 | `prompt_converter/llm_prompt_converter.py`、`prompt_converter_agent.py` |
| R4 | 修复状态与空问题过滤 | `repair_outcome.py`、`workflow/workflow_nodes.py`、`quality_auditor_agent.py` |

执行顺序约束：

- S1 必须先于 S2、S4：路由拒绝替换后，地点冲突才只能由提示词重写或阻断收敛。
- R1 必须先于 R2、R3、S3 的修复分支：没有 `issue_codes`，所有按编码匹配的处理器仍是死代码。
- S3 的归一函数先于其修复分支落地，避免重复实现景别映射。

## 3. 数据模型与接口契约

### 3.1 场景权威（S1 / S4）

```python
# first_frame_builder.py
@dataclass
class SceneAnchorResolution:
    ...
    scene_anchor_source: str = ""  # plan / plan_missing

def resolve_scene_anchor(
    prompt, contract, scene=None, fragment=None,
    first_frame_asset_id: str = "",
    plan_scene_asset_id: str = "",
) -> Optional[SceneAnchorResolution]
```

判定矩阵：

| 计划场景 | 计划场景资产 | 提示词提到其他场景 | 结论 |
| --- | --- | --- | --- |
| 有 | 有 | 是 | 返回 `None`，不替换；地点问题交由 S2 改写/阻断 |
| 有 | 无 | 是且唯一命中 | `auto_replace` + `scene_anchor_source=plan_missing` + warning |
| 有 | 无 | 多个或零资产 | 维持 `ambiguous` / `no_asset` 阻断 |
| 无 | — | 任意 | 维持既有行为，追加“计划场景缺失，场景权威降级”warning |

```python
# image_to_video.py
def collect_plan_scene_violations(
    route_plan: Dict[str, Any],
    fragments: Optional[List[Any]],
    shots: Optional[List[Any]],
    contract: Any,
) -> List[Dict[str, Any]]:
    """返回 type=scene_anchor_mismatch、stage=route_model 的违规项"""
```

- 输入为 `instructions.route_plan` 的序列化字典；只检查 `mode=image_to_video` 且存在首帧引用的包。
- 计划场景存在且契约有对应资产时，首帧 `asset_id` 必须等于该资产，否则产生违规项。
- 违规项交由既有 `merge_violations` 合并，规则审查按 MAJOR 计分。

### 3.2 地点重写与阻断（S2）

```python
# scene_prompt_realign.py
@dataclass(frozen=True)
class SceneConflict:
    fragment_id: str
    term: str            # 冲突原词（英文别名或中文词）
    language: str        # en / zh
    clause: str          # 冲突所在子句
    reason: str          # venue_furnishing / rewrite_failed

@dataclass
class SceneRealignResult:
    prompt: str
    replaced: List[Tuple[str, str]]     # (原词, 替换词)
    conflicts: List[SceneConflict]

def realign_scene_prompt(
    prompt: str, plan_location: str, *, fragment_id: str = ""
) -> SceneRealignResult

def apply_scene_prompt_realignment(
    instructions: AIVideoInstructions,
    fragments: List[VideoFragment],
    parsed_script: Any,
) -> Dict[str, int]
```

- 计划地点解析：片段 `continuity_notes["location"]`（形如 `场景scene_002`）提取场景 ID → `parsed_script.get_scene_by_id()` 取 `location`；解析失败返回空，整段跳过并记 `info`。
- 冲突检测沿用 `first_frame_builder` 的场景地点词表与 `_strip_quoted_content` 口径；计划地点词已出现则不视为冲突。
- 改写：仅替换地点短语，英文用计划地点的英文别名，中文用计划地点中文词；计划地点由多段组成时取最长命中段。
- 阻断：冲突子句命中该场景的专有陈设（教室：课桌椅/黑板/讲台；客厅：沙发/电视/茶几；卧室：床/衣柜；厨房：灶台/冰箱；办公室：办公桌/电脑）且计划地点不含同一陈设时，记 `reason=venue_furnishing`，不改写。
- 输出写入 `instructions.metadata`：
  - `scene_prompt_realigned: [{fragment_id, from, to}]`
  - `scene_prompt_conflicts: {fragment_id: [{term, clause, reason}]}`
- 路由阶段读取 `scene_prompt_conflicts`，命中片段 `package.status = "needs_manual_fix"` 并追加 warning；`plan.blocked_fragments` 由既有逻辑自动收集。

### 3.3 修复编码与状态（R1~R4）

```python
# quality_auditor_models.py
class QualityRepairParams(BaseModel):
    issue_types: List[str] = Field(default_factory=list)   # 保留：LLM 修复提示
    issue_codes: List[str] = Field(default_factory=list)   # 新增：确定性策略命中

```

```python
# repair_outcome.py
REPAIR_STATUS_MANUAL = "manual_required"
```

状态判定：

| 问题数 | 动作数 | 自动编码命中 | 状态 |
| --- | --- | --- | --- |
| 0 | — | — | `no_issues` |
| >0 | >0 | 全覆盖 | `repaired` |
| >0 | >0 | 有未覆盖 | `partial` |
| >0 | 0 | 无命中（纯人工项） | `manual_required` |
| >0 | 0 | 有命中却未执行 | `no_action_taken`（ERROR，视为链路缺陷） |

- `workflow_nodes._audit_quality` 的全局状态汇总：任一产物 `no_action_taken` → `no_action_taken`；否则任一 `manual_required` → `manual_required`；否则沿用 `partial/repaired` 判定。
- 空问题过滤在 `_merge_reports_with_dedup.add_violation` 入口执行：`issue_code` 与 `issue_desc` 同时为空即丢弃并记 `debug`，不计分、不进 `repair_params`。已定位根因：`MemoryManager.get()` 走语义召回，`issues_parse_script` 等键并非精确匹配，会返回 `stage_*_latest` 包装字典，被转换成空 `other` 违规；本批只做聚合过滤，不启停阶段问题接入。

### 3.4 景别归一与探测器（S3）

```python
# camera_builder.py
SHOT_PHRASE_MAP: Dict[str, Tuple[str, str]] = {
    "close_up": ("close-up shot", "特写镜头"),
    "extreme_close_up": ("extreme close-up shot", "极特写镜头"),
    "medium_shot": ("medium shot", "中景镜头"),
    "wide_shot": ("wide shot", "全景镜头"),
    "long_shot": ("long shot", "远景镜头"),
    "two_shot": ("two-shot", "双人中景镜头"),
    "over_shoulder": ("over-the-shoulder shot", "过肩镜头"),
    "pov": ("POV shot", "主观镜头"),
}

def normalize_prompt_shot_phrase(prompt: str, shot_type: str) -> Tuple[str, Optional[str]]
```

- 定位顺序：跳过 `[Style: …]` 前缀 → 第一段落第一个景别短语；存在则替换为目标短语，缺失则在段首插入。
- 含中文段落（`\n\n` 之后的对照段）同样归一其开头中文景别短语；英文段只插英文短语，不混入中文。
- `camera.shot_type` 为空或不在映射表（如 `zoom`/`following_shot`）时跳过，不改写、不告警（FR-106a）。
- `detect_shot_type_from_text` 的文本别名删除 `zoom shot/zoom/变焦/推拉`；`_EXACT_ALIASES` 保留，供结构化来源值归一。审计与归一共用 `SHOT_PHRASE_MAP`。

## 5. 兼容性与风险

- **签名兼容**：`resolve_scene_anchor` 新增参数带默认值；`QualityRepairParams` 只新增可选字段；旧产物缺 `issue_codes`/`scene_prompt_realigned` 时按空处理。
- **探测器收紧的影响面**：`detect_shot_type_from_text` 不再返回 `zoom`，`build_camera_control` 在无来源景别且提示词仅含 `zoom` 时回落到默认 `medium_shot`；运镜仍由 `detect_motion_from_text` 记录为 `zoom`，结构化运镜信息不丢失。计划对现有相机测试逐一核对，不发散改其他别名。
- **地点重写只做短语替换**：LLM 的同义改写（如 `inside a school room`）不在词表内则无法替换；此时若命中陈设规则则阻断，否则按原样放行并记 `info`，不伪称已重写。
- **计划场景本身可能错误**：本批信任镜头计划，只保证“计划—首帧—提示词”三者一致；计划错误另案处理。
- **阻断增加人工项**：`frag_010` 这类“走廊镜头写成教室课桌椅”的片段会从 `ready` 变为 `needs_manual_fix`，属预期保守结果，发布说明需写明。
- **阶段问题仍不接入审计**：本批只过滤空条目，不修 `issues_*` 记忆键；该改动会显著改变评分口径，留待独立批次。
