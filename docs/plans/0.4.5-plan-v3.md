## 必须做（P0）

### 任务 2（补全）：服装完整性校验覆盖“信息不足”

**现状**：`char_003` 的 `image_prompt` 是 `高中校服`，缺颜色、材质、袖子挽起、汗渍；frag_011/frag_012 的 prompt 里明确写了 `slightly disheveled blue and white cotton school uniform, sweat drops on forehead`。资产描述与片段描述信息落差大，且未被标记。

**要做**：
- 在 `character_sheet` 生成前，校验服装描述是否包含“类型 + 颜色 + 材质”三要素。
- 缺任意一项，标记 `requires_special_attention: true`，并在 `metadata.attention_reason` 写明缺哪一项（如 `"服装描述缺少颜色和材质"`）。
- 优先从片段 prompt 里回填缺失要素（frag_011 有“blue and white cotton”，frag_012 有“slightly disheveled”），回填后仍不完整则保留标记。

**验收标准**：`char_003` 的 `metadata` 出现 `requires_special_attention: true`，`attention_reason` 指出缺失项；`image_prompt` 至少包含颜色和材质（如“蓝白相间棉质高中校服”）。

**测试输入**：你提供的这份 `asset_plan`，直接跑校验逻辑，检查 `char_003` 是否被标记。

### 任务 1（仅回填方案）：资产从 `pending` 到可回填

**现状**：8 个资产全部 `status: "pending"`、`asset_ref: ""`。`fix(routing): 图生视频 asset_ref 仅取场景首帧` 已修路由，但资产本身没生成，路由空转。

**要做**（**不接入任何图像生成 API，不在默认工作流实例化图像客户端**，符合 0.5 边界文档）：
- 定义 `asset_manifest` 格式，基于 `asset_plan` 的字段，建议结构：

```json
{
  "task_id": "TSK44450026111214443791",
  "script_id": "SN4445005582174366474090",
  "assets": [
    {
      "asset_id": "char_001",
      "asset_ref": "file:///path/to/char_001.png",
      "checksum": "sha256:...",
      "generated_at": "2026-11-12T15:00:00Z",
      "source": "external"
    }
  ]
}
```

- 合法 `asset_ref` 支持：本地路径（`file://`）、HTTP(S) URL、带校验和的引用。
- 提供示例回填脚本 `examples/backfill_assets.py`：读入用户提供的图片路径或 URL，写入 `asset_plan` 对应资产的 `asset_ref` 和 `status: "ready"`，做基本校验（文件存在、格式可识别、`asset_id` 匹配）。
- 在管线加校验节点：`asset_manifest` 存在时，校验通过则转 ready；校验失败保持 pending 并给出明确错误（如 `asset_id` 不匹配、文件不存在、校验和错误）。
- 默认工作流（不提供 `asset_manifest`）不实例化任何图像客户端，资产保持 pending。

**验收标准**：用示例脚本回填 `char_001` 和 `scene_001` 后，`asset_plan` 里这两个资产的 `status` 是 `ready` 且 `asset_ref` 非空；默认工作流跑一次，资产仍是 pending，且日志里没有“实例化图像客户端”的记录。

**测试输入**：提供的 `asset_plan`，加上一份手工写的 `asset_manifest`（只填 `char_001` 和 `scene_001`）。

### 任务 7（新增）：场景锚定一致性校验

**现状**：frag_012 的 prompt 写 `high school classroom`，但 `references` 里 `scene_002`（走廊/班级记忆墙）是 `first_frame`。教室戏用走廊首帧，会导致背景错误。

**要做**：

- 在 `route_plan` 生成 `references` 后，检查片段 prompt 里描述的场景（教室 / 走廊 / 记忆墙等）与 `first_frame` 资产的 `owner_name` 是否一致。
- 不一致时，标 warning 并记录到 `execution_suggestions` 或 `metadata`，例如 `"frag_012 描述教室场景，但首帧资产为走廊/班级记忆墙，建议改用 scene_001"`。
- 如果片段 prompt 里没有明确场景描述（如 frag_011），跳过校验，不误报。

**验收标准**：用 15 片段产出跑校验，`frag_012` 出现场景锚定 warning；`frag_011`（未明确场景）不误报。

**测试输入**：提供的 15 片段产出。

## 应该做（P1）

### 任务 5：`camera.motion` 与 prompt 一致性校验（补充反向检查）

**现状**：frag_015 的 prompt 写 `slow push-in`，`camera_control.motion` 是 `dolly`——方向一致，可接受。但校验逻辑目前只检查“有运动动词但 motion 不匹配”，不检查“没运动动词但 motion 是 dolly”这种反向情况。frag_010 的 prompt 没有运动动词，`motion` 是 `static`，是合理的，但需要确认这条不会误报。

**要做**：构建 `camera` 时，从最终 prompt 解析运动动词（push-in、dolly、handheld、zoom、pull-back 等），与 `motion` 字段比对。不一致时，如果方向语义接近（push-in ≈ dolly-in），降级为 info；语义相反（push-in vs static）才标 warning。

**验收标准**：frag_015 的 `push-in` vs `dolly` 不报 warning；如果构造一个 `push-in` vs `static` 的测试片段，应报 warning。
