# PenShot 0.4.9 发布说明

> 状态：已随 release-please 发布（`v0.4.9`）。
> 本版聚焦真实剧本运行暴露的分镜链路误报与误阻断，并完成许可证迁移。

---

## 1. 版本概述

0.4.9 将 0.4.8 之后开发分支上的改动合并到 `main`：以三个真实剧本的运行日志为样本，逐项收口运镜、道具、角色、地点、审计与路由环节的误报和误阻断；同时把项目许可证由 MIT 迁移为 Apache-2.0。

改动规模：315 个文件，+2246 / -1033，其中大部分文件仅为许可证头统一替换，功能性改动集中在分镜（segment）、连续性（continuity）、提示词转换（convert/realign）、目标模型路由（route）与工作流决策（workflow）。

## 2. 本版变更

### 2.1 运镜检测与时序

- 英文运镜关键词改为按单词边界匹配：`pan` 不再命中 `apartment / pants / panic / compartment`，`tilt` 不再命中 `head tilted` 等人物姿态。
- 补齐动词变形（`pans / panning / zooms / zooming / tilts / tilting / orbits / orbiting` 等），真实运镜仍可识别。
- 修正错误的 `camera.motion` 会经 `detect_motion_from_text` 污染分镜时长估算（运动/静态基准不同）的问题；模型适配器的同类探测一并修复。
- 消除由此产生的“运镜关键词冲突”伪告警。

### 2.2 道具连续性

- 道具持有状态改为显式释放模型：放下、放在、递给、交给、扔、丢、摔、碰倒、打翻、脱下、摘下等动作后清空持有状态。
- 台词元素中提到的道具视为话题，不再计入角色持有状态。
- 结构化 `prop_object` 需在元素原文中出现才采信，避免把其他角色或容器（外卖箱、包里）中的道具算到当前角色头上；未命中时回退到持握动词文本提取。
- 长道具短语按 2 字片段对齐，兼容“一份餐盒爬上六楼”这类文本抽取噪声。
- 释放对象与当前持有道具不一致时不再错误清空其他道具。

### 2.3 动作与角色连续性

- 动作断裂只比较相邻的同角色镜头，`凝视 -> 拾起 -> 迈步` 这类正常叙事推进不再被判为中等严重度的动作断裂。
- 画外音/仅声音角色（如电话另一端）按台词元素的镜头归属计入覆盖，不再误报 `character_not_in_shots`。

### 2.4 地点重写与场景锚定

- 补充“咖啡店 / 咖啡厅 / 街角”地点词表：计划地点写“城市街角咖啡店外长椅旁”时，提示词中的 `cafe / coffee shop / street / street corner` 视为同一地点，不再被当作非计划地点阻断。
- 检测前屏蔽非地点固定搭配（`library card` 等），避免借阅卡被识别为图书馆场景。
- 按命中区间抑制被更长地点词覆盖的短词（`coffee shop` 内的 `shop`），改写成功后不再残留冲突。
- 分镜阶段保留片段连续性注释并补充场景 ID，修复地点重写的场景定位。

### 2.5 审计与修复回路

- 与连续性检查同口径：待修复的中度问题全部落在 `requires_manual_fix`（无自动策略）时，记录告警并继续执行，不再反复修复直至审计循环超限、转入人工干预并最终超时失败。
- 人工处理项仍随最终输出暴露（`requires_manual_fix` / `repair_status`）。

### 2.6 提示词阶段与路由

- 模型支持检查改用能力注册表（`get_capability` / `parse_model_name`），修复访问 `ShotConfig.supported_models` 不存在字段导致的 `AttributeError`；该异常此前会使修复后的阶段问题刷新被静默跳过。
- 路由产出的 `kling_3` / `runway_gen4` 等已注册模型不再被误判为不支持。
- `critical_text` 判定收紧：裸“招牌/标牌”不再构成可读文字要求，需出现“文字 / 字样 / 写着 / 店名”等明确表述；“咖啡店招牌模糊可见”这类氛围招牌不再误报首帧缺少文字证据。

### 2.7 许可证

- 项目许可证由 MIT 迁移为 Apache-2.0，新增/统一 SPDX 头注释与 `NOTICE` 文件，`LICENSE` 同步替换。

## 3. 验证记录

- 单元/工作流测试：`python -m pytest -q` 全量 **1019 项通过**。
- 新增回归覆盖：运镜词边界、道具释放与台词道具、画外音角色覆盖、无自动策略审计决策、地点词同族与固定搭配、模型注册表判定、招牌 `critical_text` 判定。
- 真实任务回放：
  - 《604室的访客》：运镜冲突告警 3 → 0，道具误报 2 → 0。
  - 《深夜来电》：画外音角色误报消失，审计不再循环耗尽后超时，任务由失败转为完成。
  - 《雨中的约定》：地点冲突阻断片段 6 → 0，`prop_change` 2 → 0；仅真实需要呈现文字的借阅卡片段仍判 `critical_text`。

## 4. 升级说明

- 无破坏性改动，契约 schema、SDK 调用方式与配置项保持兼容。
- 行为变化（均为减少误报）：
  - 片段 `camera.motion` 可能由误判的 `pan/tilt` 回归 `static` 或真实运镜，分镜时长估算随之变化。
  - 氛围招牌片段不再以 `critical_text` 理由路由，改按一致性/可用性正常路由。
  - 无自动策略的中度质量问题不再阻塞流程，改为在输出 `warnings` 中携带人工处理项。
- 许可证变更：下游再分发需遵循 Apache-2.0 条款，保留 `LICENSE` 与 `NOTICE`。

## 5. 已知限制

- 道具连续性仍是启发式检查，输出 `warning` 级、不阻断；角色同时操作多件道具时以人工判断为准。
- 未启用资产生成执行器时，片段会标记 `pending_assets`，需先生成角色/场景资产再进入下游渲染。
- CI 当前仅运行 flake8，`pytest` 步骤仍处于注释状态，测试通过依赖本地执行；`mypy` 存量债务未在本版清理。
