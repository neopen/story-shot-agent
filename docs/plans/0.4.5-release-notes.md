## 修复项（截至 2026-11-12）

### 数据自洽

- **资产计划风格与片段同源**：`asset_plan.style_anchor.description` 不再透传契约原始值，改由与片段相同的风格消解逻辑生成；旧的 `muted colors, melancholic tone` 等已被决议丢弃的短语不会再出现在资产计划里。契约本身不被回写。
- **服装歧义消解**：形如“A 或 B / 可能 A / 之类”的服装描述按确定性顺序消解（`style` 指向 > 服装名词命中 > 阅读顺序第一个），结果写入 `metadata.outfit_resolution`；非强证据的消解额外标记 `requires_special_attention=true`、`outfit_alternatives` 与 `attention_reason`，供人工复核。误判可用既有 `asset_prompt_edits` 覆盖。
- **服装信息不足可见且可回填**：角色三视图生成时校验服装描述是否含“类型 + 颜色 + 材质”，缺项即标记 `requires_special_attention=true` 并把缺失项写入 `attention_reason`（如 `服装描述缺少颜色和材质`）。路由阶段拿到最终提示词后，用同一角色的片段服装短语回填 `image_prompt`、记录 `outfit_text` / `outfit_backfill_source`；因源锚点本身不完整，回填后仍保留人工复核标记。已生成、已回填或人工编辑过的资产不会再次回填。
- **道具使用范围精确化**：`usage.fragments` 与片段 `references` 统一为“场景命中 + 文本提及”双条件。同场景内并未出现的道具不再被整批挂到片段上；过时的路由引用会被丢弃，`route refs ⊆ usage.fragments` 不变量保持成立。
- **运镜与提示词一致（含反向校验）**：运镜词表补充 `push-in / pull-back / dolly in-out / tracking`；多词具体短语优先于单词（`slow pull-back` 不再落入 `zoom`）；同一文本命中多个运动族时保留最具体者并告警；`static` 与明确运镜动词冲突时告警。新增反向校验：提示词写死 `static camera/固定机位` 而 `camera.motion` 是运动族时记 WARNING；提示词完全没有运镜表述而 motion 非 static 只记 info 日志，不升级为违规；推镜/拉镜/变焦同属 dolly 族，互不告警。
- **场景锚定一致性告警**：比对片段文本描述的场景地点与 `first_frame` 场景资产的 `owner_name`，不一致时在 `adapted_packages[].warnings` 与日志中提示“建议改用 scene_XXX”。内置中英地点词表（教室↔classroom、走廊↔corridor/hallway 等）；文本未提场景、当前场景也被提及、或同时提到多个其他场景时跳过；对白/引号内容先剔除，台词里提到“走廊”不会误判画面在走廊。

### 声明与回填闭环（不新增生成能力）

- **默认路径边界收口**：`AssetGeneratorAgent` 默认 `enable_execution=False`，不再惰性解析任何文生图客户端；即使环境变量配置了图像供应商，默认工作流也只产出 `pending` 声明。需要本地真实生成时，必须显式注入执行器或客户端，或传入 `enable_execution=True`。
- **回填清单校验**：清单兼容 `bindings` 与下游常用的 `assets` 字段，并接受 `script_id` / `generated_at`（资产级时间戳写入 `metadata.generated_at`）。引用校验支持本地路径、`file://` 与 `http(s)://`：显式 `file://` 缺失、本地文件 sha256 不匹配、`asset_id` 不在计划中时，资产保持 `pending` 并在报告 `errors` 中给出明确原因，坏引用不再挂进契约；裸路径（如 `/cdn/xxx.png`）仍按不透明引用兼容，避免历史产物整批失效。
- **回填工具**：新增 `scripts/asset_manifest_tool.py`。
  - `template <asset_plan.json> [-o manifest.json]`：按计划生成空回填模板（含 `schema_version`、`task_id`、`asset_id_map`）。
  - `validate <asset_plan.json> <manifest.json>`：校验 ID 存在性、重复绑定、引用可用性与 sha256；未填写的条目默认记为“待回填”，`--strict` 才要求全量覆盖。
  - `apply <asset_plan.json> <manifest.json> [-o asset_plan_filled.json]`：离线把 `asset_ref` / `status` 写回计划副本，供无生成环境验证交接链路。
  - 三个子命令只读输入、只写显式输出，不发起网络请求。
- **示例脚本**：新增 `examples/backfill_assets.py`，用 `--set char_001=路径或URL` 把已有图片写进清单，本地文件自动计算 `sha256:`；`--apply` 同时写出回填后的计划副本。

## 升级注意

- 默认工作流行为变化：此前若环境配置了文生图供应商，资产会被真实生成；0.4.5 起默认只声明。依赖默认生成行为的集成方需显式开启执行器。
- 回填清单状态口径：契约枚举是 `AssetStatus.GENERATED = "generated"`，需求里的 “ready” 在实现中即 `generated`；`FAILED` / `SKIPPED` / `PENDING` 不变。
- 回填校验变严：显式 `file://` 指向的文件不存在、sha256 不匹配、清单里出现计划外 `asset_id` 时，资产保持 `pending` 并写入报告 `errors`（此前会直接挂载坏引用）。裸路径与 `http(s)` 引用不做存在性探测，保持兼容。
- 回填清单仍为 `ASSET_SCHEMA_VERSION`（当前与 `CONTRACT_SCHEMA_VERSION` 同为 `0.4.4`），字段向后兼容；`validate` 会拒绝与计划版本不一致的清单。
- 服装歧义为“确定性选择 + 显式待确认”，不是原文保留；下游应优先消费 `requires_special_attention` 与 `outfit_alternatives` 决定是否人工复核。
- 服装回填只替换三视图提示词中的服装短语，不改契约锚点；回填后仍带 `requires_special_attention=true`，避免下游把“已补全”误当成“锚点已完整”。
- 运镜词表中裸“手持”不再判为 handheld（`手持白色同学录` 是拿道具）；手持运镜需出现 `handheld/手持镜头/手持拍摄/手持晃动/晃动`。质量审查新增 `camera_motion_prompt_mismatch`（WARNING），命中会使审查状态变为 `MINOR_ISSUES`，但不阻断流程。
- 场景锚定告警写入 `adapted_packages[].warnings`（新增可选字段），不改变路由决策；消费方需自行决定是否改用建议的 `scene_XXX`。
- 提示词模板知识库的迁移（`scripts/migrate_prompt_templates_044.py`）与 0.4.4 发布说明一致，0.4.5 未改动迁移口径。

## 已知事项

- 资产默认仍为 `pending`，需要下游回填或显式开启执行器；本版本不提供内置真实生成链路。
- 服装歧义与回填可能被确定性选择，请复核 `requires_special_attention=true` 的资产。
- 运镜冲突会记录 WARNING，但不阻断流程；`frag_006` 这类“提示词明确写 static、`camera.motion` 却是 handheld”属数据级矛盾，本版本只暴露不自动改写。
- 场景锚定只给建议，不自动切换首帧资产；多场景同时命中或未写地点时保持静默。
- 切割器“超过 5 秒才拆”的规则、叙事级完整性与 RAG 召回精度均不在本版本范围内。
