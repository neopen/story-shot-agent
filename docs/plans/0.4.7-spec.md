# PenShot 0.4.7 Spec：分镜一致性 P0 修复（场景权威 / 修复链路 / 景别口径）

> 状态：已批准（spec-ok，2026-11-19）
> 依据：两轮最新真实产物
> - `data/output/SN4445005582174366474090/TSK44450026111722309230/`（13 片段 / 41.2s / 评分 85）
> - `data/output/SN1526225901938958510925/TSK15262226111417229062/`（13 片段 / 35.1s / 评分 80）
> 前置裁决（2026-11-19）：本批仅做 P0 三项；场景冲突以镜头计划为准；景别由确定性规则改写提示词。

---

## 1. 功能目标（Goal）

修复三个会直接把错误画面交给下游的正确性问题，且不新增任何生成能力：

1. 场景锚定不再用提示词文本反推镜头计划，避免“走廊镜头使用教室首帧”这类静默漂移。
2. 质量审查到阶段修复的参数契约统一，消除“发现 N 个问题、执行 0 个修复动作”。
3. 提示词景别与镜头计划景别保持一致，消除每轮 2–3 条景别不一致告警与运动词误判。

---

## 2. 范围界定

### ✅ 范围内

- 镜头计划 `scene_id` 对片段首帧场景资产与场景地点的权威约束。
- 提示词地点冲突的确定性重写与阻断。
- `QualityRepairParams` 的问题编码契约、空问题过滤、修复状态与动作计数。
- 提示词开头景别短语的中英文确定性归一，以及景别探测器的运动词误判修复。

### ❌ Non-Goals

- 不实施 FR-091a（lighting 证据链独立），仍保留在 `docs/plans/0.4.6-spec-revisions.md`，转下一批。
- 不重做场景边界过渡镜头，不改过渡镜头时长策略。
- 不扩展服装颜色/款式回填，不处理剪影降级。
- 不新增片段级时长偏差明细，不重排 `issues_report` / `stage_statistics` 的报告结构。
- 不接入任何图像、视频、音频生成 API；不调用新的 LLM 能力。
- 不升版本号，不修改 0.5 路线图与边界文档。

---

## 3. 使用者与业务场景

- **下游生成执行方**：直接消费 `prompt_converter_result.json` 的 `prompt`、`image_prompt` 与首帧资产引用；任一地点或景别与镜头计划不一致，画面即偏离剧本。
- **质量审查**：需要让 `quality_auditor_result.json` 的告警与修复动作真实对应，而不是每轮固定“0 动作 / 人工项”。
- **回归验证**：在不联网的前提下，用上述两轮产物复现并验证三项修复。

## 4. 功能需求清单

> 编号从 FR-097 起为 0.4.7 暂定编号，合并前可按实际占用调整。

### 4.1 场景权威（FR-097 ~ FR-099）

- **FR-097** WHEN 片段所属镜头存在有效 `scene_id`，且契约中该场景存在场景资产 THEN 片段首帧场景资产 SHALL 由该 `scene_id` 决定；提示词或片段描述中出现的其他场景地点词 MUST NOT 触发首帧资产替换。
- **FR-098** WHEN 片段文本（`description` + 最终 `prompt`）出现非计划场景的地点词 THEN 系统 SHALL 在提示词转换阶段做确定性地点重写：仅替换地点短语（如 `classroom background` → `hallway background`、`教室记忆墙` → `走廊记忆墙`），保留动作、人物与构图细节；重写发生时 SHALL 记录 `scene_prompt_realigned` 及原词/替换词。
- **FR-098a** WHEN 地点短语重写后仍命中非计划场景地点词，或冲突子句包含计划场景无法承载的具体陈设（如走廊镜头中的“课桌椅与黑板”）THEN 该片段 SHALL 标记 `needs_manual_fix` 并阻断，MUST NOT 以 `ready` 状态或替换后的其他场景资产继续下游。
- **FR-099** 首帧资产自动替换 SHALL 仅允许在“计划场景缺失或契约无对应场景资产”时发生，并 SHALL 记录 `scene_anchor_source=plan_missing` 与告警；计划场景存在时，原 `auto_replace` 分支 MUST NOT 生效。
- **FR-099a** 契约一致性复核 SHALL 增加“计划场景 vs 首帧场景资产”校验：不一致时必须产生违规项，不得以提示词自洽为由判定通过。

### 4.2 修复链路（FR-100 ~ FR-103）

- **FR-100** `QualityRepairParams` SHALL 新增 `issue_codes`（规则编码，如 `shot_type_prompt_mismatch`、`scene_insufficient`），与现有 `issue_types` 并存；`issue_types` 继续作为 LLM 修复提示，`issue_codes` 作为确定性修复与人工项判定的依据。旧产物缺少该字段时按空列表兼容。
- **FR-101** 各阶段确定性修复入口（剧本解析、分镜生成、片段切分、提示词转换）SHALL 按 `issue_codes` 匹配策略；`issue_types` MUST NOT 作为策略命中依据。
- **FR-102** WHEN 某问题编码不存在对应修复策略 THEN 系统 SHALL 将其列入 `requires_manual_fix`，并 SHALL NOT 标记为可自动修复；`repair_status` SHALL 区分 `repaired` / `partial` / `manual_required` / `no_action_taken`，其中 `no_action_taken` 仅表示确定性与 LLM 修复均未执行任何动作。
- **FR-103** WHEN 提示词转换因 `issue_codes` 触发 LLM 重写 THEN 该次重写 SHALL 计入 `repair_action_count`；`post_repair_score` SHALL 以重写后的重新审查结果为准，不得沿用修复前分数。
- **FR-103a** `issue_code` 与 `issue_desc` 同时为空的问题 MUST NOT 进入违规列表、评分与修复参数；现有空 `other` 告警的根因若未定位，SHALL 在聚合入口统一过滤并记录 `debug` 日志。

### 4.3 景别口径（FR-104 ~ FR-106）

- **FR-104** 提示词转换完成后（含 `_apply_repair_params` 重写后），系统 SHALL 确定性归一提示词开头景别短语，使其与 `camera.shot_type`（以镜头计划 `source_shot_type` 为准）一致，英文段与中文对照段同步。归一 MUST 只改开头景别短语，MUST NOT 删除构图、动作、光线与镜头运动描述。
- **FR-105** 景别映射 SHALL 至少覆盖：`close_up` → `close-up shot` / `特写镜头`，`extreme_close_up` → `extreme close-up shot` / `极特写镜头`，`medium_shot` → `medium shot` / `中景镜头`，`wide_shot` → `wide shot` / `全景镜头`，`long_shot` → `long shot` / `远景镜头`，`two_shot` → `two-shot` / `双人中景镜头`，`over_shoulder` → `over-the-shoulder shot` / `过肩镜头`，`pov` → `POV shot` / `主观镜头`。提示词缺少开头景别短语时 SHALL 插入对应短语，不得改用其他景别。
- **FR-106** `detect_shot_type_from_text` SHALL 只识别景别短语，MUST NOT 把运镜词（`zoom`、`push-in`、`tracking`、`pan`、`tilt`、`dolly` 等）判为景别；规则审查与修复归一 SHALL 共用同一探测器与映射表。
- **FR-106a** WHEN `camera.shot_type` 为空或无法识别 THEN 系统 SHALL 跳过景别归一与告警，不得猜测景别。

## 5. 非功能性约束

- **确定性**：FR-097 ~ FR-099、FR-104 ~ FR-106 全部由规则实现，不新增 LLM 调用；单任务额外耗时 < 100ms。
- **兼容性**：`QualityRepairParams` 只新增可选字段；`prompt_converter_result.json` 只新增可选字段（如 `scene_prompt_realigned`）；旧产物仍可读取。
- **不变量**：任一 `ready` 片段的首帧场景资产与计划 `scene_id` 一致；提示词景别短语与 `camera.shot_type` 一致（`shot_type` 为空除外）。
- **日志**：地点重写、阻断、资产替换、编码匹配、空问题过滤、景别归一均需 `info` / `warning` / `debug` 日志，包含片段 ID 与原因。
- **安全**：不写入任何密钥；不新增外部请求。
- **可测试性**：三项均可离线验证；场景与景别类验收不得依赖真实 LLM 输出。

## 6. 边界与异常场景

- 计划场景存在但契约没有对应资产：允许沿用现有“提示词唯一命中其他场景”的替换逻辑，但必须记录 `plan_missing` 告警，并保持片段可追溯。
- 片段无 `scene_id` 或镜头缺失：维持既有行为，新增 `warning` 说明“计划场景缺失，场景权威降级”。
- 提示词同时提到计划场景与其他地点：视为不冲突，不重写。
- 引号内台词提到其他地点：沿用既有剔除引号内容的口径，不触发冲突。
- 地点短语重写涉及具体陈设（课桌椅、沙发等）且计划场景不含该陈设：按 FR-098a 阻断，不做语义替换。
- 特殊景别（`over_shoulder`、`pov`）不是景别大小：按 FR-105 映射保留，不降级为 `close_up` / `medium_shot`。
- 提示词开头是 `[Style: …]` 前缀：景别归一必须定位到前缀后的第一个景别短语，不得把风格词当景别。
- `camera.shot_type` 与 `camera.source_shot_type` 不一致：以镜头计划 `source_shot_type` 为准；两者都缺失时跳过。
- 空问题过滤后仍存在 `requires_manual_fix`：保留人工项，但不得计为“自动修复失败”。

- **AC-084** 两轮样本的 `quality_auditor_result.json` 中 MUST NOT 再出现 `issue_code` 与 `issue_desc` 同时为空的问题；评分只统计有效违规。

## 9. 风险与未决项

1. **确定性地点重写覆盖面有限**：LLM 提示词中的地点表述可能不固定；重写失败时按 FR-098a 阻断，可能让部分片段从 `ready` 降为人工项，需要接受这一保守结果。
2. **景别归一可能改动提示词措辞**：只改开头短语，但若下游依赖原始措辞做自定义解析，需要同步告知。
3. **`camera.shot_type` 本身可能来自不准确的镜头计划**：本批信任镜头计划，不修正计划本身；计划错误另案处理。
4. **空问题根因未定位**：FR-103a 只做聚合过滤；若根因在记忆键污染，仍需单独排查并记录后续任务。
5. **真实 E2E 未执行**：场景重写与景别归一的效果最终取决于真实 LLM 输出的提示词形态，上线前仍需联网跑一轮。
