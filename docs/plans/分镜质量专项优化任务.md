# Story-Shot-Agent 分镜质量专项优化任务

## 一、任务目标

请基于当前项目代码，针对《最后一班地铁》的分镜生成结果进行专项分析和修复。

本次任务不是重构整个项目，也不是简单修改 Prompt，而是解决当前分镜生成过程中存在的结构化数据不一致、资产引用不完整、视频生成前置条件不完整、镜头调度不合理、片段连续性不足等问题。

核心目标：

1. 提高剧本到分镜的转换质量。
2. 保证分镜规划数据结构完整、一致、可执行。
3. 建立可靠的角色、场景、道具资产引用链。
4. 改善镜头时长、动作拆分和摄影机调度。
5. 保证多个视频片段之间的角色、道具、场景和动作连续性。
6. 提高不同视频生成模型之间的适配能力。
7. 保留现有系统架构和已有功能，避免无必要的大规模重构。

**重要原则：不要为了让示例 JSON 看起来更合理而只修改输出结果，必须找到对应的业务逻辑、Prompt、数据模型或工作流节点，从源头修复。**

## 二、问题修复优先级

### P0：数据完整性和执行链路（必须优先完成）

#### 1. 统一镜头规划数据结构

目前存在镜头类型与实际描述不一致的问题。

例如：

- 原始镜头类型为 medium_shot。
- 某个适配结果将 shot_type 修改为 close_up。
- source_shot_type 仍然保留 medium_shot。
- camera 字段却为空。

需要：

- 建立统一的 ShotPlan 或完善现有镜头中间数据模型。
- 明确区分原始剧本镜头、规划镜头和模型适配后的镜头。
- 禁止不同节点各自修改镜头类型，导致数据冲突。
- 模型适配时必须保留原始镜头信息，并记录修改原因。

建议镜头结构至少包含：

```
class ShotPlan:
    shot_id: str
    source_shot_id: str | None

    shot_type: str
    camera_angle: str | None
    camera_motion: str | None

    subject_motion: str | None
    composition: str | None
    focus_target: str | None

    visual_description: str
    action_description: str

    duration: float
    transition: str | None

    character_refs: list[str]
    scene_refs: list[str]
    prop_refs: list[str]
```

以上为设计参考，优先复用项目现有模型，不要重复创建功能相同的数据结构。

特别注意：

- `camera_motion` 表示摄影机运动。
- `subject_motion` 表示人物或物体运动。
- `shot_type` 表示景别。
- `camera_angle` 表示摄影机角度。

这几个概念不能混用。

#### 2. 修复资产引用链

目前资产规划虽然能够识别角色、场景和道具，但部分资产没有正确关联到具体片段。

以《最后一班地铁》为例：

- 林晚：角色资产。
- 管理员：角色资产。
- 纸条：道具资产。
- 红围巾：人物服装特征，同时可以作为独立视觉参考资产。
- 地铁站台：场景资产。

需要：

1. 每个片段明确声明所需的角色、场景和道具。
2. 资产计划中的 usage.fragments 必须与实际片段引用一致。
3. 双向检查资产与片段之间的引用关系。
4. 不允许出现资产已定义但没有使用记录的情况，除非明确标记为未使用。
5. 不允许片段引用不存在的资产。
6. 不允许必需资产缺失时直接进入视频生成。

建议建立统一的资产引用校验：

```
def validate_asset_references(
    fragments,
    asset_plan,
) -> list[str]:
    """
    检查：
    1. 片段引用的资产是否存在
    2. 必需资产是否缺失
    3. 资产 usage.fragments 是否完整
    4. 资产与片段的双向引用是否一致
    """
```

注意：不要只校验 JSON 字段是否存在，还要校验引用关系是否真实正确。

#### 3. 完善 Image-to-Video 执行链路

目前部分片段已经指定使用 image_to_video，但首帧图片和角色参考资产还没有形成完整的执行依赖关系。

需要明确区分：

**阶段一：视觉资产准备**

- 生成角色参考图。
- 生成场景参考图。
- 生成必要的道具参考图。
- 生成片段首帧。
- 检查角色身份、服装、道具和场景一致性。
- 保存生成结果及其版本信息。

**阶段二：视频生成**

- 获取已确认的首帧图片。
- 获取必要的角色参考图。
- 获取必要的场景和道具参考图。
- 根据目标模型生成对应请求。
- 检查模型是否支持对应参考图输入方式。
- 执行视频生成。

必须明确：

- `image_prompt` 是生成图片的文本提示。
- `first_frame_instruction` 是首帧生成指导。
- 它们都不等于实际生成的首帧图片。
- 资产引用、文件路径、资源 ID 和生成状态需要明确区分。

建议为资产和片段增加明确的执行状态，例如：

```
PENDING
GENERATING
READY
FAILED
APPROVED
```

状态名称应优先复用项目已有枚举。

**未满足必需依赖的片段不得被标记为可执行。**

### P1：分镜导演能力优化

#### 4. 优化镜头时长计算

目前部分镜头存在动作过密、时长不足的问题。

例如：

- 管理员叹气、转身、走回值班室，被压缩在较短时间内。
- 林晚上车、回头、车门关闭，被压缩在约 2 秒内。
- 完整对白片段需要考虑实际语速和停顿。

不能简单使用固定时长，也不能仅根据文本长度估算。

建议综合考虑：

- 动作数量。
- 动作复杂度。
- 动作之间的先后关系。
- 人物移动距离。
- 对白字数和语速。
- 情绪停顿。
- 镜头建立时间。
- 视频模型允许的时长范围。

建议形成独立的 DurationPlan：

```
class DurationPlan:
    estimated_action_duration: float
    dialogue_duration: float
    emotional_pause_duration: float
    transition_duration: float
    recommended_duration: float
    duration_reason: str
```

以上仅作为设计参考。

要求：

- 不得为了满足模型时长限制而直接截断动作。
- 动作过多时，应优先考虑合理拆分镜头。
- 对白不能被压缩到不自然的语速。
- 时长调整必须保留原因，方便调试。

#### 5. 增强动作拆分与镜头调度

镜头拆分不能只是将原剧本机械地切成多个片段。

需要让分镜规划具备基本导演思维：

- 明确每个镜头的叙事目的。
- 确定观众应该关注什么。
- 判断是否需要建立镜头。
- 判断人物动作是否需要拆分。
- 判断是否需要反应镜头。
- 判断情绪变化是否需要停顿。
- 判断镜头之间是否存在空间关系。

例如《最后一班地铁》：

林晚拿着纸条，管理员询问她是否还在等人，林晚回答后管理员离开。

合理的镜头设计应考虑：

1. 管理员走出值班室。
2. 管理员停下并询问。
3. 林晚抬头回应。
4. 管理员听完后的反应。
5. 管理员转身离开。

不要求每个动作都独立生成镜头，应根据叙事价值和视频生成难度决定。

#### 6. 建立跨片段连续性管理

目前不能只依靠 Prompt 文本保证连续性。

建议建立 ContinuityState，统一管理：

```
class ContinuityState:
    characters: dict
    costumes: dict
    props: dict
    scene_state: dict
    lighting_state: dict
    previous_shot_id: str | None
    previous_shot_end_state: dict
```

重点解决：

- 人物在不同片段中的外貌、服装一致性。
- 红围巾的位置、状态和佩戴方式一致。
- 纸条从展开、阅读、揉皱到持握的状态变化。
- 人物在站台和候车区域中的空间位置。
- 列车到站前后场景和光照的一致性。
- 上一镜头结束状态与下一镜头开始状态的衔接。

每个镜头应具备：

- 起始状态。
- 动作变化。
- 结束状态。

下一镜头必须根据上一镜头结束状态进行规划。

注意：不要简单将上一镜头的完整 Prompt 拼接到下一镜头，应传递结构化状态。

### P2：音频和视觉风格优化

#### 7. 完善音频规划

明确区分：

- 人物对白。
- 人物旁白。
- 环境音。
- 音效。
- 背景音乐。

对白文本和 TTS Prompt 不应混为一体。

建议 AudioPlan 至少包含：

```
class AudioPlan:
    audio_id: str
    audio_type: str
    model: str | None

    prompt: str | None
    dialogue_text: str | None

    speaker_id: str | None
    emotion: str | None

    duration: float | None
    start_offset: float
    end_offset: float
```

要求：

1. 林晚和管理员拥有稳定的 speaker_id。
2. 同一角色跨片段保持声音身份一致。
3. 对白音频和环境音使用各自合适的模型。
4. 保证音频时长与视频片段时长协调。
5. 对白开始时间、结束时间和停顿时间可追踪。
6. 环境音能够跨片段合理延续。
7. 不要将广播对白误判为画面文字。

#### 8. 优化风格锚点提取

当前风格提取需要避免不同维度混淆。

建议拆分：

```
Genre
Mood
Lighting
Color Palette
Visual Style
Camera Language
Atmosphere
```

例如《最后一班地铁》：

- Genre：剧情 / 情感短片。
- Mood：孤独、忧伤、克制。
- Lighting：深夜地铁站冷白荧光灯。
- Color Palette：低饱和冷色调，红围巾作为视觉强调。
- Visual Style：电影感写实。
- Camera Language：克制的中近景、特写与适度运动。
- Atmosphere：空旷、安静、略带伤感。

注意：

- 不要将自然光、阴天光等模板词语强行套用到深夜室内场景。
- 不要仅凭情绪推断影片类型。
- 风格锚点应能够追溯到原剧本、用户指定风格或明确的推断结果。
- 无法确定时允许为空，不要为了填满字段而编造。

### P3：模型路由与质量评估

#### 9. 优化视频模型路由

目前模型路由不能只依赖固定模型、默认模型或简单的文本评分。

建议根据以下维度评估：

- 角色一致性。
- 人物动作表现。
- 镜头运动控制。
- 场景稳定性。
- 道具稳定性。
- 首帧参考图支持。
- 视频时长限制。
- 对白及音频工作流适配。
- 当前模型接口能力。

需要特别区分：

- 画面文字（Visual Text）。
- 人物对白（Dialogue Text）。
- 旁白（Narration Text）。
- 道具文字（Prop Text）。

例如，纸条上有文字，并不意味着必须使用擅长文字渲染的视频模型；广播对白也不代表需要生成画面文字。

模型能力评分必须能够追溯依据。

如果没有真实测试数据，应标记为启发式评分，不要将内部评分伪装成客观模型性能指标。

#### 10. 优化 Negative Prompt

避免所有片段重复携带相同的大量负面提示词。

建议分层管理：

- Global Negative：全局画面约束。
- Character Negative：人物相关约束。
- Scene Negative：场景相关约束。
- Shot Negative：当前镜头特殊约束。

根据目标模型的实际接口能力决定是否传递，不能假设所有模型都支持相同的负面提示词参数。

## 三、架构设计要求

本次优化应优先围绕统一的中间数据结构进行。

建议整体流程：

```
flowchart TD
    A[Original Script] --> B[Script Understanding]
    B --> C[Story & Shot Planning]
    C --> D[Unified ShotPlan]
    D --> E[Continuity Management]
    D --> F[Asset Management]
    E --> G[Audio-Visual Planning]
    F --> G
    G --> H[Model Routing]
    H --> I[Model-specific Adapter]
    I --> J[Validation]
    J --> K[Asset Preparation]
    K --> L[Video Generation]
    L --> M[Quality Evaluation]
```

核心要求：

1. 统一 ShotPlan 是分镜规划的核心数据结构。
2. 各个工作流节点应围绕统一数据结构进行读写。
3. 不同模型的差异通过 Adapter 处理。
4. 不要让 Kling、Runway 等模型适配器直接反向修改原始分镜规划。
5. 数据校验应独立于 Prompt 生成。
6. 资产准备和视频生成必须具有明确的依赖关系。
7. 保留 LangGraph 当前工作流中合理的节点划分，避免为了追求上述示意图而机械地增加节点。

## 五、测试与验收标准

以《最后一班地铁》作为第一份回归测试剧本。

### 必须通过的结构测试

- 所有片段具有唯一且稳定的 ID。
- 所有资产引用均能找到对应资产。
- 所有必需资产均已声明。
- 资产与片段之间的双向引用一致。
- 镜头类型、摄影机角度和摄影机运动不存在语义冲突。
- 不存在必需字段缺失却被标记为可执行的情况。
- image_to_video 必须具有满足目标模型要求的首帧和参考资产。
- 视频生成任务能够追溯到对应的分镜、资产和模型配置。

### 必须通过的质量测试

- 对白能够在合理时长内完成。
- 多动作镜头不会被不合理地压缩。
- 角色、服装和道具在相邻镜头中保持连续。
- 纸条状态变化符合剧情。
- 红围巾在相关镜头中保持视觉一致性。
- 夜间地铁站的灯光和色彩风格保持统一。
- 镜头拆分不会丢失原剧本中的关键情节。
- 不会因为模型路由而改变原始剧情含义。

### 扩展回归测试

后续至少增加以下类型的剧本：

1. 单场景情感短片。
2. 多人物对话。
3. 动作追逐。
4. 多场景剧情。
5. 多人物复杂剧情。

不能只针对《最后一班地铁》做特殊规则或硬编码。
