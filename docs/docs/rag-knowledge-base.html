知识库与检索

RAG 知识库、模板召回、分块、向量检索与跨剧本复用的当前实现。

更新 2026-11-14 约 26 分钟阅读

PenShot 0.4.4 的知识库与检索层分成两条独立链路：提示词模板按角色/场景锚点召回，默认阈值 0.80、单次取 2 条、最多注入 6 条，并在本剧本名额未满时只读补位其他剧本；剧本内容索引仍由 ScriptKnowledgeBase 承载，用手动余弦服务连续性检查。三层记忆是第三条链路，只在工作流节点与两者交界。

能力与接线状态

模板链路挂在提示词模板管理器 PromptTemplateManager（prompts/prompt_template_manager.py）之下，工作流节点不直接访问向量存储。下表给出各能力的实现位置与 0.4.4 的真实状态。

能力 实现位置 状态
模板沉淀与锚点召回 search_similar_detailed，_recall_patterns_by_anchors 已接线
跨剧本只读召回 _retrieve_global，include_global=true 已接线，默认开启
legacy 模板隔离 is_legacy_template 与迁移脚本 已接线，需手动执行迁移
召回诊断 metadata.anchor_recall 已接线
剧本内容索引与检索 ScriptKnowledgeBase，手动余弦 已接线
连续性相似场景检索 search_similar_scene，top_k=2 已接线
长剧本分块 LongScriptChunker 已实现，未接线
交叉编码器重排序 create_retriever_for_script 已装配，默认关闭，无生产调用方
知识路由器与混合检索 KnowledgeRouter 已实现，未接线
GraphRAG 图谱检索 无对应代码 未实现

知识库架构

索引层由两套相互独立的 LlamaIndex 向量索引组成，均以 SimpleVectorStore 为存储后端，并用 script_id 作为隔离键。模板索引保存通过入库策略的成功提示词，按剧本分目录；跨剧本召回不构建合并索引，而是扫描其他剧本的缓存并只读加载其持久化索引。剧本内容索引由内嵌的 ScriptKnowledgeBase（knowledge/llamaIndex/llama_index_knowledge.py）承载，保存场景与角色文档。两者判分口径与过滤规则不同，不能视为同一个检索入口。

ScriptKnowledgeBase 的构造参数为 (embeddings, script_id, storage_dir=None, chunk_size=512, chunk_overlap=20)，第二个参数必需；内部用 _indices、_vector_stores、_storage_contexts、_retrievers 四组字典按剧本 ID 隔离数据。模板管理器按 script_id 维护索引与缓存，跨剧本来源单独存放在 _global_sources，与本地索引分开，确保不写回、不参与重建。

模板入库同时把成功模式写入长期记忆的 successful_prompt_patterns（保留最近 200 条）。工作流转换节点会读取这批记忆并与召回结果合并，但记忆内容不会回填向量索引。三层记忆的写入与召回机制见记忆系统。

索引与分块

“分块”在代码里有两个互不相关的层次：入库时的文本切分，以及尚未接线的超长剧本分块。前者决定检索粒度，后者决定单次任务处理多少场景。

模板入库

save_successful_prompt(fragment_id, prompt_text, quality_score, script_id, additional_metadata, source, audit_status) 要求调用方显式传入 source 与 audit_status，方法本身不再推断来源。写入经 add_template 完成：超过 2000 字符的模板截断为 1997 字符加省略号，按哈希与全文双重去重，并用 _processing_stack 防止递归重入。

元数据先经 MetadataPolicy.sanitize 清洗，只允许白名单字段进入向量库：type、hash、script_id、timestamp、quality_score、fragment_id、scene、style、shot_type、duration、task_id、source、schema_version、audit_status；单字段超过 256 字符会被截断，提示词原文只写入 Document.text。缺少 schema_version 时写入当前契约版本 0.4.4，缺少 audit_status 时写入 unknown。模板用 SentenceSplitter 按 1024/20 切分为节点，因此接近 2000 字符的模板会占用多个节点，检索名额按节点而非模板计数。

剧本内容入库

调用 add_parsed_script(parsed_script, script_id) 时，剧本先被转成两类文档：每个场景一个 type=scene 文档，元数据含 scene_id、location、time_of_day、element_count；每个角色一个 type=character 文档，元数据含 character_name、gender、role。文档总数等于场景数加角色数，script_id 由入库方法逐文档注入；未传 script_id 时会按时间戳生成一个。

节点解析器的选择是一个条件分支：chunk_size > 1000 时使用 SentenceWindowNodeParser（窗口 3），否则使用 SentenceSplitter。默认 512/20，因此默认路径是 SentenceSplitter；调大分块参数会连带切换解析器。切分后的节点经嵌入模型向量化写入 SimpleVectorStore，并由 _save_storage 立即落盘，同时校验向量文件与 docstore 是否写盘成功。

flowchart TD
    A[ParsedScript 场景与角色] --> B[create_documents]

长剧本分块：LongScriptChunker

LongScriptChunker（continuity_guardian/long_script_chunker.py）把解析后的场景序列切成块，供逐块执行。参数为每块最多 30 个场景、单块预估时长上限 180 秒、块间重叠 3 个场景。

切分使用“或”条件，任一条件满足即封块；判断发生在场景入块之前，因此场景不会被从中间切开，单个超长场景会成为新块的起点。封块后保留上一块末尾 3 个场景作为新块开端，并重算时长预算。场景时长按 max(10.0, 元素数 × 4.0) 估算：不调用模型，带 10 秒下限，精度有限。

实现的策略只有“按场景切分”一种，代码中没有角色弧、情绪曲线或平衡分块的对应实现。全仓库没有生产调用方，ScriptChunk 的 entry_character_states、exit_character_states、continuity_anchors 三个字段只在数据类中声明、构建块时从不赋值，跨块状态传递尚未落地。超长剧本当前可用的做法是按叙事段落分段输入，逐段调用工作流。

flowchart TD
    A[遍历场景序列] --> B{场景数达 30 或 时长将超 180 秒}
    B -->|否| C[场景入块 累加预估时长]
    B -->|是| D[结算当前块]
    D --> E[保留末尾 3 个场景]
    E --> C
    C --> F[遍历结束 结算末块]

检索

生产链路上有两条规则不同的检索路径，分别服务模板召回与场景检索。

模板召回：本地优先，跨剧本补位

search_similar_detailed(query_text, script_id, top_k, min_score, include_global) 先检索本剧本索引，再按四道规则过滤：分数低于阈值（取 >=）丢弃，metadata.type 不是 prompt_template 丢弃，标记为 legacy 的节点丢弃，命中当前剧本 legacy 哈希集合的节点同样丢弃。结果截断到 top_k。

本剧本命中数少于 top_k、include_global=true 且嵌入模型可用时，才扫描其他剧本补足剩余名额。跨剧本来源按目录读取 templates_cache.json，整库都是 legacy 的剧本直接跳过；持久化索引以只读方式加载，检索后按分数排序，取剩余名额。过滤规则与本地一致，结果追加在本剧本命中之后，并带 source_scope=global 与 source_script_id。跨剧本来源不会写入当前剧本的缓存或索引。

生产默认值来自 settings.prompt_templates，由 WorkflowNodes 在构造管理器时注入：阈值 0.80、top_k=2、include_global=true、max_injected_patterns=6。直接构造 PromptTemplateManager 时类默认仍是 0.5 与 3，两条路径的默认值不同，应以配置为准。

配置项 默认值 说明
PENSHOT_PROMPT_TEMPLATES__MIN_SIMILARITY_SCORE 0.80 过滤阈值，按 0.4.4 实测基线校准
PENSHOT_PROMPT_TEMPLATES__TOP_K 2 每次查询返回条数，本地优先占用
PENSHOT_PROMPT_TEMPLATES__INCLUDE_GLOBAL true 本剧本名额未满时只读补位其他剧本
PENSHOT_PROMPT_TEMPLATES__MAX_INJECTED_PATTERNS 6 跨片段去重后可交给转换器的召回条数上限

诊断结果随每次检索返回，含 status、attempted、retrieved、hits、local_hits、global_hits、min_score、max_score、threshold、kb 与 last_repair。状态枚举共 11 个，避免用空列表同时表示“空库”“索引不可用”“分数不达标”。

状态 含义
hit 本剧本有命中
hit_global 本剧本无命中，跨剧本补位命中
first_run_no_history 完全首次运行，无历史模板也无跨剧本命中
first_run_global_hit 本剧本无活跃模板，但跨剧本命中
empty_templates 有历史缓存，但活跃模板为 0（全部 legacy）
index_unavailable 存在活跃模板但没有可用索引
index_load_failed 索引加载失败且无可用索引
cache_index_mismatch 缓存与索引文档数不一致，且本次无命中
embeddings_unavailable 嵌入模型不可用
all_below_threshold 检索到节点，但全部低于阈值
retrieval_error 检索过程抛出异常

剧本内容检索：手动余弦

ScriptKnowledgeBase.query() 不走 LlamaIndex 检索器。它用 embed_query_vector 编码查询，遍历向量存储的 embedding_dict，逐个计算余弦相似度，按分数降序截断 top_k（默认 5），再从 docstore 取回文本与元数据。复杂度为 O(N)，没有近似索引；单剧本几十到几百个节点时开销可以接受，规模上万后查询延迟会随文档数线性上升。

这条路径不做任何分数过滤，低分结果同样会占满名额。签名中的 search_type、use_rerank、rerank_model 三个参数从未被读取；search_similar_scene 内部传了 use_rerank=True，同样不产生重排序行为。函数对缺参和缺索引做早退：未指定 script_id 时返回带 error 字段的空结果，索引或向量存储未就绪时同样返回结构化错误，不会跨剧本检索；模长为零时相似度按 0 处理。

两条路径的评分与过滤规则不同：模板路径先取候选再按阈值、类型与 legacy 规则筛选，内容路径是无阈值的全量余弦排序，两者的分数不宜直接横向比较。

    subgraph Template[模板召回 search_similar_detailed]
        T1[查询文本] --> T2[本剧本 as_retriever]
        T2 --> T3[阈值 0.80 与 type 过滤]
        T3 --> T4[排除 legacy 与 legacy 哈希]
        T4 --> T5{名额未满且 include_global}
        T5 -->|是| T6[其他剧本只读检索 按分数补位]
        T5 -->|否| T7[返回本地命中]
        T6 --> T8[本地在前 全局在后]
    end
    subgraph Content[剧本内容检索 query]
        Q1[查询文本] --> Q2[embed_query]
        Q2 --> Q3[遍历 embedding_dict 计算余弦]
        Q3 --> Q4[降序截断 top_k 默认 5]
        Q4 --> Q5[无阈值过滤]
    end

空结果与索引自愈

检索返回空通常不是阈值问题，而是索引恢复、迁移状态或数据本身的问题。优先读 anchor_recall.status 与 kb 快照，再按下表排查。

原因 现象 处理
未执行 0.4.4 迁移 0.4.3 缺陷模板没有 legacy 标记，仍参与召回 先 dry-run 再执行 migrate_prompt_templates_044.py --apply
索引恢复不完整 retrieve() 返回 0 条；from_vector_store 报 Cannot initialize from a vector store that does not store text 用 StorageContext.from_defaults(persist_dir=...) 加载，再以 VectorStoreIndex(nodes=[], storage_context=...) 构造
缓存与索引不一致 状态为 cache_index_mismatch 写入或检索前会自动重建一次；仍有问题则检查 index_store/
docstore 文本缺失 有向量但取不到文本 向量、docstore、索引三件套一起恢复，不单独加载向量文件
未传 script_id 返回带 error 的空结果或空列表 调用方检查返回值并补齐剧本 ID
嵌入模型或维度不一致 不报错，分数失真 更换模型后重建索引
库中无数据 状态为 empty_templates 或 first_run_no_history 确认剧本已入库；长期记忆需先积累达标样本
阈值过高 状态为 all_below_threshold 用内容检索查看原始分数，或下调 MIN_SIMILARITY_SCORE

模板索引在检索或写入前由 _ensure_index_ready 校验：索引缺失或文档数与活跃模板数不一致时，从缓存全量重建一次，同一管理器实例内不重复重建，并把修复前后数量写入 last_repair。legacy 条目不参与重建。

剧本内容索引的向量文件损坏时，_recreate_vector_store 会把损坏文件备份为 *_corrupted_{时间戳}，清理 docstore.json 与 index_store.json，再重建空存储。损坏前的数据保留在备份文件中，恢复后需要重新入库。

重排序

重排序的实现只有一处：ScriptKnowledgeBase.create_retriever_for_script。它支持 similarity 与 mmr 两种检索模式（mmr_threshold=0.6），在触发条件下装配 SentenceTransformerRerank：模型选择链为本地路径、配置名、BAAI/bge-reranker-large，top_n 取 3 与 similarity_top_k 的较小值，以节点后处理器方式挂到检索器上。启用重排序时会用 as_retriever 重建检索器且不携带查询模式，因此 mmr 会被覆盖，两者不能叠加。

状态是“已装配，未生效”：触发条件为 use_rerank or retriever_config.rerank_enabled，而 rerank_enabled 默认为 false；唯一会调用它的 KnowledgeRouter 本身没有生产调用方；生产路径上的 query() 又不读取 use_rerank。上述三点同时成立才会真正执行重排序。

配置项 默认值 说明
PENSHOT_RETRIEVER__RERANK_ENABLED false 重排序总开关
PENSHOT_RETRIEVER__RERANK_MODEL_NAME BAAI/bge-reranker-large 本地路径不可用时的回退名
PENSHOT_RETRIEVER__RERANK_MODEL_LOCAL_PATH data/models 默认指向父目录；应指向含模型文件的目录
PENSHOT_RETRIEVER__SEARCH_TYPE similarity 检索模式
PENSHOT_RETRIEVER__SIMILARITY_TOP_K 5 初筛候选数

默认路径 data/models 只通过存在性检查，模型文件位于其子目录，加载失败时异常被捕获并降级为无重排序。要让重排序真正生效，需要同时满足：开关打开、本地路径指向模型目录、调用走检索器装配路径而非 query()。交叉编码器输出的是相关性分数，与余弦分数不同口径；接线后若沿用现有阈值，需要重新校准。

flowchart TB
    A[use_rerank 或 rerank_enabled] -->|任一为真| B[create_retriever_for_script]
    B --> C[模型链 本地路径 配置名 BAAI/bge-reranker-large]
    C --> D[SentenceTransformerRerank top_n 取 3 与 k 的较小值]
    D --> E[as_retriever 挂载 node_postprocessors]
    E --> F[重排序结果]
    G["默认 rerank_enabled=false"] -.->|默认不满足| A
    H[KnowledgeRouter 未接线] -.->|唯一调用方| B

入库策略与提示词转换

入库判定

质量审计完成后，节点用 decide_ingestion(audit_status, quality_score, active_template_count, severities) 对整批片段判定一次，再对所有片段应用同一结论。判定顺序与结果如下。

条件 结果 source
没有审计结果 拒绝，pre_audit 空
问题含 major 或 critical 拒绝，severe_violations 空
本剧本活跃模板数为 0 允许，cold_start（放宽分数门槛，但不放宽严重缺陷） cold_start_seed
审计状态为 passed 允许，audit_passed quality_audit_passed
分数 ≥ 90 允许，score_threshold quality_audit_score
其余 拒绝，below_threshold；产物照常输出并标记 quality_gate 空

审计结果的 metadata.quality_gate 会记录 status（判定原因）、score、blocking=false、ingestion_allowed 与 audit_status。未达入库门槛不等同于任务失败：产物仍会输出，只是携带“仅供预览”的标记。

锚点召回与注入

0.4.4 的提示词转换节点不再对整段提示词调用 enhance_prompt，而是逐片段构建锚点查询：主角色的名称与契约外观锚点，加上所属场景的地点与时间；无契约或无角色/场景锚点的片段计入 queries_skipped，不发查询。每条查询调用一次 search_similar_detailed（top_k=2），命中结果跨片段去重后截断到 max_injected_patterns=6，再追加长期记忆中的成功模式，通过 apply_historical_context 交给转换器。

召回统计写入 instructions.metadata.anchor_recall：fragments、queries、queries_skipped、attempted、hits、injected、status、kb、min_score、max_score、top_k、error，发生索引重建时另有 rebuilt。多片段查询的状态按“有命中优先、失败按严重度”聚合。

注入规模有上限，但渲染仍保守：LLM 转换路径的 history_hint 当前只取首条召回文本的前 100 字符作为“参考成功模式”。因此 anchor_recall.injected 记录的是交给转换器的条数，不等于模型实际读到的全文条数。enhance_prompt、get_best_match 仍保留为管理器公开方法（后者等价于 top_k=1 的检索），但 0.4.4 生产链路没有调用方。

flowchart TD
    A[片段集合与一致性契约] --> B{片段有角色或场景锚点?}
    B -->|否| S[计入 queries_skipped]
    B -->|是| C[构建锚点查询]
    C --> D[search_similar_detailed top_k=2]
    D --> E[本地命中 不足则跨剧本补位]
    E --> F[跨片段去重]
    F --> G[截断到 6 条]
    G --> H[合并长期记忆成功模式]
    H --> I[apply_historical_context]
    I --> J[写入 anchor_recall 统计]

工作流调用点

四个调用点均在 workflow_nodes.py：剧本解析节点入库（add_parsed_script），提示词转换节点锚点召回（search_similar_detailed），质量审计节点按入库策略沉淀（save_successful_prompt），连续性守护节点为每个问题检索相似场景（search_similar_scene，top_k=2）。场景检索前先检查 is_script_kb_available()（要求已有剧本入库），命中结果写入问题对象的 historical_solutions，并受 hasattr 守卫。属性名 self.knowledge_manager 的类型就是 PromptTemplateManager，属于历史命名。

节点的完整职责见工作流节点，连续性问题的判定与修复见一致性策略。

flowchart LR
    N1[剧本解析] --> N2[分镜生成] --> N3[视频分割] --> N4[提示词转换] --> N5[质量审计] --> N6[连续性守护] --> N7[结果生成]
    N1 -.-> I1[add_parsed_script]
    N4 -.-> I2[search_similar_detailed 锚点召回]
    N5 -.-> I3[decide_ingestion 与 save_successful_prompt]
    N6 -.-> I4[search_similar_scene top_k=2]
    I1 --> H[PromptTemplateManager]
    I2 --> H
    I3 --> H
    I4 --> H

数据流

阶段执行遵循“开工读历史、执行查知识库、收工写归档”：四个处理节点开工前从三层记忆按固定键读取历史上下文（短期问题、中期统计、长期模式），收工后由 WorkflowMemory.after_stage_completion 分三层写入；知识库侧则是解析结果入库、锚点召回与模板沉淀三条线。记忆的键名与分层规则见记忆系统，工作流整体结构见技术架构。

flowchart LR
    P[剧本解析] -->|add_parsed_script| V[(剧本向量索引)]
    P --> PR[(parsed_results JSON)]
    V -->|query 手动余弦| C[连续性守护]
    T[(模板索引)] -->|search_similar_detailed| E[提示词转换]
    T2[(其他剧本模板索引 只读)] -.->|名额未满时补位| E
    A[质量审计] -->|入库策略通过 save_successful_prompt| T
    W[(三层记忆)] -.->|历史上下文| P
    W -.->|成功模式| E
    P -->|阶段写入| W
    A -->|阶段写入| W
    E -->|阶段写入| W

持久化与恢复

模板库存放在 data/embedding/prompt_templates/{script_id}/ 下的 templates_cache.json 与 index_store/；剧本内容索引存放在 data/embedding/script_kb/{script_id}/，包含 default__vector_store.json（兼容读取旧名 vector_store.json）、docstore.json、index_store.json，解析结果单独存放在同目录的 parsed_results/{script_id}.json。目录中的 graph_store.json 与 image__vector_store.json 是 LlamaIndex 持久化的空占位，不承载数据。

加载是分层的：构造 ScriptKnowledgeBase 时只扫描剧本目录、把解析结果 JSON 读入内存，向量索引延迟到首次访问时由 _ensure_script_index 从 persist_dir 恢复；模板索引与缓存在首次访问该剧本时加载。跨剧本来源同样延迟加载，且只读。进程重启后三类文件各自恢复，互不依赖；长期记忆中的模板不会回填模板索引。

flowchart TB
    subgraph Runtime[运行时]
        R1[本剧本模板索引]
        R2[跨剧本只读索引]
        R3[剧本内容索引]
        R4[解析结果结构]
    end
    subgraph Disk[磁盘 按剧本隔离]
        D1[(prompt_templates/script_id/templates_cache.json 与 index_store)]
        D2[(script_kb/script_id/default__vector_store.json docstore.json index_store.json)]
        D3[(parsed_results/script_id.json)]
    end
    R1 -->|_save_index_for_script| D1
    D1 -->|首次访问加载| R1
    D2 -->|首次访问恢复| R3
    D1 -.->|只读扫描其他剧本| R2
    R4 -->|构造时 _load_all_scripts| D3
    R3 -->|_save_parsed_result| D3

0.4.4 模板迁移

迁移脚本 scripts/migrate_prompt_templates_044.py 处理两件事：把 0.4.3 已入库的缺陷模板移入隔离清单，把缺少 schema_version 的旧模板标记为 legacy。默认是 dry-run，只打印统计；加 --apply 才写入，--script-id SID 可限定单个剧本。

python scripts/migrate_prompt_templates_044.py                    # 全库 dry-run
python scripts/migrate_prompt_templates_044.py --script-id SID     # 单剧本 dry-run
python scripts/migrate_prompt_templates_044.py --apply             # 全库写入

写入前会把 templates_cache.json 与 index_store/ 备份到 backups/044_{时间戳}/{script_id}/；被隔离的模板完整写入 quarantine_044.json 而不是删除；未隔离但缺少版本的模板标记 schema_version=legacy 与 audit_status=unknown，随后按迁移结果重建索引，无活跃模板时清空索引目录。执行后生成 migration_044_report.json。不执行迁移时，旧模板没有 legacy 标记，仍会参与召回。

当前限制

限制 影响
手动余弦全量扫描 无近似索引，节点数上万后查询延迟线性上升
两条路径口径不一致 模板有 0.80 阈值与类型/legacy 过滤，内容检索无阈值，分数不可比
召回渲染保守 最多注入 6 条，但 history_hint 只展示首条前 100 字符
逐片段检索 每个有锚点的片段各发一次查询，片段多时检索次数线性增长
重排序未生效 use_rerank 为哑参数，配置默认关闭，装配入口无生产调用方
知识路由器未接线 混合检索与 MMR 均不参与生产链路
长剧本分块未接线 超长剧本需分段输入，块状态字段未填充
GraphRAG 未实现 无实体抽取、图存储与图遍历
跨剧本只读 只能补足本剧本未满名额，命中不会沉淀回当前剧本索引
旧模板需迁移 未执行 0.4.4 迁移时，缺陷模板仍以活跃状态参与召回
一致性无校验 嵌入模型或维度变化后不报错，分数失真
诊断不主动告警 空库与首次运行可区分，但只写入元数据，不产生告警

需要核对具体行为时，以仓库源码的当前版本为准；接口、默认值与接线状态可能随版本变化。安装与首次运行见快速开始。
