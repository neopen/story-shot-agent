将任意长度的剧本，拆分为 N 个 5 秒的、视觉连贯的视频片段脚本单元

PenShot 是一个基于 LangGraph 的多智能体协作系统，能够将任意格式的剧本（自然语言/标准格式/AI 分镜）自动拆分为符合 AI 视频模型（Sora/Runway Gen-2/Pika/Veo 等）时长限制的片段序列，同时保证角色、场景、动作的视觉连贯性。支持同步/异步调用、MCP 协议集成、向量记忆检索、质量审查与自动修复。适用于短视频创作、影视预可视化、游戏剧情制作等场景。

一、产品概述与核心价值

剧本分镜智能体能将用户提供的原始自然语言剧本，自动拆分为多个 n 秒长度的短视频片段脚本，并确保画面连贯性、角色一致性、动作延续性，适用于主流 AI 视频生成模型（Runway Gen-2、Sora、Veo、Pika、Stable 等，定义于源码 VideoModelType 枚举）。

PenShot 之所以有价值，源于一个真实的工程痛点：

  • 需求描述：假如我有一段预估两分钟左右的剧本，想通过 AI 模型生成对应的短视频。

  • 技术受限：目前的各种模型仅支持一次生成 5-10 秒长度的视频，想要生成两分钟长度的视频，只能通过"拼接"的方式，将多个 5 秒的片段合成为一个视频。

  • 任务&挑战点：要实现视频拼接，第一步就需要拆分原剧本，拆分后的剧本尽量接近 5-10 秒时长（取决于模型），且每个视频片段还必须要保持连贯性，不然生成的视频片段合成后会导致场景、动作、人物等衔接不上。

    且剧情中的动作、语速等会影响时长，所以需要考虑多种情景，比如：老人动作慢、生气怒吼时语速会较快、跑比走要快等等。

这便是本智能体需要完成的任务，用户只需要给出剧本，而后根据各种技术拆解，最后将拆解完成的剧本片段返回，用户只需要将其交给模型（Runway、Pika、Sora、Wan、Stable Video 等）生成即可，最后再利用相关技术将片段合成为完整视频。

用一句话概括：PenShot 补齐了"从剧本到可分镜头 AI 视频片段"这段 DIY 拼接链条上最繁琐、最易出错的一环。

核心挑战

  • 角色、场景、道具的一致性保证

  • 动作的连贯性

  • 对话内容和语音支持、口型矫正

  • 背景和画外音支持

  • 与剧本的偏差度质量验证

核心能力

  • 自动化转换：实现剧本→AI 视频指令的端到端自动化流程

  • 智能分段：智能处理 5 秒限制，保证叙事连贯性

  • 连续性保障：基础的角色、场景、道具一致性维护

  • 高质量输出：生成专业级的 AI 视频生成提示词

二、关键要点拆解

2.1 能力矩阵

能力 说明
🎭 剧本解析 自动识别场景、角色、对话、动作，支持多种格式
🎬 镜头拆分 智能划分镜头单元，合理估算时长
✂️ 视频分段 双模式切分：超阈值镜头由 LLM 在动作停顿处分割，其余按 2.5 秒均分
📝 指令转换 生成模型适配的文生视频/音频提示词
✅ 质量审查 规则+LLM双重审查，自动修复问题
🔗 连续性守护 跨阶段一致性检查，确保视觉连贯

解读：这条链路（解析→拆分→分段→指令转换→质量审查→连续性守护）就是 PenShot 的"六段式"核心工作流，对应源码 PipelineNode 枚举中的 6 个核心节点（parse_script、segment_shot、split_video、convert_prompt、audit_quality、continuity_check）。

两个流传较广的说法需要精确化：

  • "优先在动作静止点切割"是 LLM 模式下的语义规则，不是无条件行为。video_splitter 有规则与 LLM 两个实现：镜头时长 ≤ 5.5 秒时走规则分割（按 2.5 秒左右均分，不判断语义边界）；超过阈值的镜头才交给 LLM，由提示词约束"分割点在动作自然停顿处、对话句号/省略号后、情绪转折处"。"短镜头省成本、长镜头保语义"的双模式，是成本与质量之间的直接取舍。

  • "规则 + LLM 双重审查"背后是一条检测→修复→重跑的闭环：视频分段先做 7 类规则检测（片长越界、时间间隙、时间重叠、元素关联缺失等），发现的问题由修复逻辑就地处理（时间轴重排、描述回填等），避免整条工作流从头再来。

3.2 环境配置

创建 .env 文件：

# ================= LLM默认配置 =================
# 系统支持的厂商（openai, qwen, deepseek, ollama）
PENSHOT_LLM__DEFAULT__BASE_URL=https://api.openai.com/v1
PENSHOT_LLM__DEFAULT__API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PENSHOT_LLM__DEFAULT__MODEL_NAME=gpt-4-turbo-preview

# ================ 嵌入模型默认配置 ================
# 系统支持的厂商（openai, qwen, HuggingFace, ollama）
PENSHOT_EMBED__DEFAULT__BASE_URL=https://dashscope-intl.aliyuncs.com/api/v1
PENSHOT_EMBED__DEFAULT__API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PENSHOT_EMBED__DEFAULT__MODEL_NAME=text-embedding-v4

########################## Redis 配置 ##########################
PENSHOT_REDIS_URL=redis://:123456@localhost:6379/0

配置说明：PENSHOT_LLM__DEFAULT__* 用于对话/解析类任务，PENSHOT_EMBED__DEFAULT__* 用于文本向量化（记忆与语义检索），PENSHOT_REDIS_URL 用于短期记忆缓存。注意 Redis 属于可选依赖：未配置或连接失败时，短期记忆会自动降级为内存存储加文件持久化（short_term_memory.py 的 _check_redis_availability()），任务不会中断，但多实例场景下各实例的记忆互不可见。

3.3 基础使用

from penshot.api import create_penshot_agent

agent = create_penshot_agent()

script = """
场景：现代办公室，下午3点
人物：小李（程序员）
动作：小李正在写代码，突然接到电话，表情惊讶
"""

# 同步调用（内部为"提交任务 + 等待结果"封装，默认等待 300 秒，超时返回 None）
result = agent.breakdown_script(script)
if result and result.success:
    print(f"片段数: {len(result.data['instructions']['fragments'])}")

# 异步调用（推荐长剧本）
task_id = agent.breakdown_script_async(script)
result = agent.wait_for_result(task_id)  # 同样返回 Optional，注意判空

何时用同步、何时用异步：breakdown_script() 内部实为"提交任务 + wait_for_result()"的封装，默认等待 300 秒，超时会返回 None——短剧本可以同步等待，但调用方需判空；长剧本（LLM 调用次数多、耗时长）推荐异步：提交后立即拿到 task_id，便于在 Web 场景轮询进度、断点恢复，避免超时。

3.4 自定义 LLM 配置

ShotConfig 采用嵌套配置结构：对话模型与嵌入模型分别由 LLMBaseConfig / EmbeddingBaseConfig 描述；且配置需要在创建 Agent 实例时注入——breakdown_script() 本身不接受 config 参数。

from penshot import ShotConfig
from penshot.config.config_models import LLMBaseConfig

config = ShotConfig(
    llm=LLMBaseConfig(
        model_name="gpt-4",
        base_url="https://api.openai.com/v1",
        temperature=0.3,   # 默认 0.1，分镜类任务建议保持低温
        max_retries=3,     # LLM 调用失败后的重试次数（默认 3）
    )
)

agent = create_penshot_agent(config=config)  # 配置在创建时注入
result = agent.breakdown_script(script)

五、输入输出详解

5.1 处理流程

阶段 输入 输出 关键处理

5.2 输入剧本示例

以下是一个完整的《雨中的约定》输入示例，它遵循"标题→时长→场景→角色→[场景段]（镜头+动作+台词）"的自然语言结构，正文与描述性标注并存：

{

}

输入要点：剧本中"风格""核心冲突"等描述性信息可以帮助 LLM 统一全局视觉基调；[开场]/[镜头切换]/[特写]/[结尾] 等分节标记则有助于场景/镜头边界识别。

六、工程边界与当前不足

只讲优点的总览会误导架构决策。基于对 v0.3.x 源码的逐项核验，以下边界值得在生产选型时评估：

  1. 规则模式是"时长均分"，语义切分只在 LLM 模式下发生：仅当 enable_llm=True 且镜头时长超过 5.5 秒阈值时，才调用 LLM 做语义分割；其余镜头由规则分割器按 2.5 秒左右均分，不判断动作/对话边界。关闭 LLM 可换来零 API 成本与确定性输出，代价是割点可能落在动作中间——这是成本与质量之间的显式取舍。

  2. 时长校验存在三层标准：提示词建议单段不低于 1.5 秒、总时长误差小于 0.5 秒；而代码强校验区间为 1.0–5.0 秒，总时长偏差 1.0 秒只告警、超过 2.0 秒才按比例缩放。阈值未完全对齐，落在"告警区间"内的输出会被原样放行。

  3. 输出的是"分镜提示词包"，不是视频：视频合成、口型对齐不在当前流水线内，需要交由外部视频模型生成后自行拼接；该能力在路线图中属于 v0.7"AI Video Production"阶段。

  4. LLM 分割决策缓存是进程内缓存：split_cache 以"镜头 ID + 时长 + 描述哈希"为键缓存在单进程字典中，多副本部署时各副本独立、无法共享命中——单机部署无感，横向扩展前需要知晓。

以上边界不影响"剧本 → 分镜提示词"主链路的可用性，但属于生产化前应当评估的部分。更完整的 30 维度测评见《PenShot 源码级测评：分镜 Agent 的架构成色、工程短板与演进路线》。

七、总结与建议

PenShot 的价值可以归结为三层：

  1. 破解"5 秒时长魔咒"：通过自动拆分，让两分钟甚至更长的剧本也能交给只能生成 5–10 秒片段的模型，再拼接成完整视频。

  2. 守护"拼接连贯性"：角色、场景、道具、动作、光影的一致性由系统层保障，避免人工手写 100 多个分镜提示词时出现前后矛盾。

  3. 全链路工程化：支持同步/异步与批量调用、内置 MCP Server（A2A 提供示例级集成路径）、向量记忆检索、质量审查与自动修复，可直接嵌入生产流程。

使用建议：新用户从《快速开始》文档与 create_penshot_agent() 同步调用入手；做 Web 服务或长剧本生产时切到异步模式，并按需配置 Redis 记忆；对接 Claude/Cursor 等工具链时启用 MCP Server。想深入原理，可继续阅读下面的核心文档与技术专题。
