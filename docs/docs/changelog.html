v0.4.5 · 2026-11-14

分镜缺陷修复与资产链收口。无破坏性 API 变更，SDK 调用方式保持不变。

分镜生成

  • 片段时长改为按动作节点确定性推算，并输出片段总时长报告；只有与镜头计划实质偏离时才告警。
  • 新增同镜头重复片段的检测、合并与超长重切，重编号后片段引用保持一致。
  • 首帧提示词清洗中文镜头词、action:、广播与音效标记，保留英文景别；纯音频片段使用空镜兜底。
  • 新增剧本语言推断与音频提示词归一，输出 dialogue_language。

资产与风格一致性

  • 风格锚定证据扩展到环境音与打光；无信号时回退到 mood / lighting / palette，并写入 provenance。
  • 服装材质词表扩展，剧本中给出的材质优先回填；资产声明与回填形成闭环，缺失项可见、可补。
  • 服装关键字段缺失的资产要求降级为剪影或背影，不再阻断片段。

质量门禁与 P0 修复

  • 场景锚定不匹配时自动替换或阻断片段，路由重建时保留阻断状态。
  • 修复环节零动作必须报错并标记，检测分数与修复分数分列。
  • below_threshold 放行时写入 quality_gate 标记，便于下游区分“通过”与“降级放行”。
  • 质量审查采信契约校验结果；critical_text 只按可读文字判定；景别以镜头计划为准并保留 POV；楼道/走廊同义归一。

升级与兼容

  • 新增的 degraded_assets、dialogue_language、quality_gate 标记等字段均为可选，旧产物仍可解析。
  • 无需执行数据迁移；如需使用新的质量标记，升级后重新运行任务即可。

v0.4.4 · 2026-11-11

连续性闭环与首帧语义加固，是本阶段行为变化最集中的版本。

连续性与修复回路

  • 跨场景切换改为确定性插入过渡镜头，修复 scene_jump 重试仍反复重跑分镜、问题无法消解的问题。
  • 外观连续性单轮比较改为主体服装集合，配饰与鞋履增删不再被误报为“外观变化”。
  • 角色外观锚点只保留自由文本中的外观子句，按字段白名单取首值，避免情绪、动作词与半截词污染锚点。
  • 风格维度按题材/氛围补齐六维前缀，互斥打光只保留一个家族，题材别名归一化并输出溯源。

首帧与资产引用

  • 角色三视图与道具静帧不再作为首帧，asset_ref 只代表片段首帧；回填 usage.fragments 并与路由引用保持一致。
  • 场景已登记场景资产时，图生视频路由不再退化为文生视频；无主角色的片段同样以场景首帧走两段式生成。
  • 修复旧产物首帧提示词拼出“of 无”的残句；非角色占位名归一为空。

提示词、模板与质量规则

  • 修复模板索引加载以旧文件名判空导致零命中、单文档索引覆盖既有索引的问题；新增结构化检索诊断与只读召回快照。
  • 模板入库统一质量审查与记忆层的策略，写入 source / audit_status，旧缺陷模板默认排除在召回之外。
  • 新增四条质量规则：外观锚点污染、景别与提示词不一致、互斥打光并存、资产使用范围缺失；违规记录带可定位的 fragment_id / asset_id。
  • 景别一致性以最终提示词为准，保留来源景别与原始值溯源。

升级与迁移

  • CONTRACT_SCHEMA_VERSION 提升至 0.4.4，与 asset_plan、asset_manifest 和路由契约保持一致；新增字段均为可选。
  • 0.4.3 已入库的缺陷模板需执行一次迁移：python scripts/migrate_prompt_templates_044.py 默认 dry-run，确认后加 --apply 写入；--script-id 可限定单剧本。
  • 迁移会先备份各剧本的 templates_cache.json 与 index_store/；缺陷模板只做隔离标记，不删除底层数据，完成后从活跃缓存全量重建索引。
  • 召回阈值默认 min_similarity_score=0.80、top_k=2、max_injected_patterns=6，可通过 PENSHOT_PROMPT_TEMPLATES__* 覆盖。
  • 下游若把 asset_ref 当作角色三视图或道具图使用，需要改为读取片段首帧引用，否则会拿到空值或场景首帧。

v0.4.3 · 2026-11-09

新增模型路由与结构化相机控制，提示词生成与目标模型决策解耦。

  • 登记 runway_gen4、kling_3、luma_dream、sora_2、pika_2 五个模型的能力：时长上限、是否支持图生视频、镜头控制、一致性与风格倾向。
  • 按可读文字、镜头复杂度、角色一致性需求、风格倾向与时长生成路由决策，输出到 instructions.route_plan，并为每个片段生成模型专属提示词包。
  • 关键文字或高一致性片段可走“静态首帧 + 动作驱动”的两段式图生视频；首帧引用只来自资产清单，不回退契约旧引用。
  • 路由失败只记录告警，route_plan 置为 null，不阻断主流程；未通过质量门的片段进入 blocked_fragments。
  • 修复 time_gap 反复重试与连续性节点崩溃。

v0.4.2 · 2026-11-06

引入声明式资产计划与下游交接，PenShot 默认不调用任何文生图接口。

  • asset_plan 以 character_sheet、prop、scene 三类资产描述“要生成什么”，包含提示词、负向词、尺寸、视角与状态。
  • 片段通过 references 复用资产，角色区分 identity_reference 与首帧引用；usage.fragments 标明每个资产被哪些片段使用，支持按需生成。
  • 下游完成资产生成后可回传 asset_manifest（bindings、asset_id_map），把真实资产引用接回 PenShot，并跳过重复生成。
  • 人工干预节点新增 [7] EDIT_ASSET：可修改资产提示词并回到资产节点重建，编辑记录累计在 execution.asset_prompt_edits。
  • 资产状态包含 pending、generated、failed、skipped；清单只覆盖已有资产，不新增或删除资产规格。

v0.4.1 · 2026-11-05

连续性前置约束收尾与报告加固。

  • 连续性前置约束收尾：把约束提前到生成阶段，减少“生成完成后再返工”的无效循环。
  • 连续性修复回路与 continuity_report.json、repair_history.json 落盘，报告补充累计检测问题统计。
  • 修复连续性报告异步落盘无法等待的问题。

v0.4.0 · 2026-11-03

新增目标模型适配层并接入主链路。

  • 提示词转换结果统一为 AIVideoInstructions，由适配层按目标模型重写风格前缀、负向词、镜头字段、分辨率与运动参数。
  • 模型适配与提示词生成分离，后续版本在此基础上增加按片段自动选型。

升级与兼容

升级前先固定版本号并保留一次可回放的旧产物；涉及契约变化时，按下表处理。

升级路径需要处理
0.4.4 → 0.4.5无需改动；按需读取 degraded_assets、dialogue_language 与 quality_gate 标记
0.4.3 → 0.4.4执行模板迁移脚本（先 dry-run 再 --apply）；核对下游 asset_ref 语义；质量审查新增四条规则，需检查告警消费逻辑
0.4.2 → 0.4.3读取 instructions.route_plan；处理 null 与 blocked_fragments；如需图生视频，接入场景首帧引用
0.4.1 → 0.4.2资产节点默认只输出 asset_plan，不会生成图片；需要接入下游资产生成与 asset_manifest 回填
0.4.0 → 0.4.1无接口变更，建议重新运行一次任务以生成新的连续性报告
0.3.x → 0.4.x先升级到 0.4.4 并完成模板迁移，再按需启用资产计划与模型路由；旧 0.3.x 模板不会自动具备 0.4.4 的 audit_status

版本号与文档策略

  • 0.x 阶段：次版本号用于向下兼容的功能新增，修订号用于兼容修复；尚未承诺 1.0 级别的 API 稳定性。
  • 破坏性变更、默认行为变化与数据迁移会同时出现在本页与对应 Release Notes 中，升级前应逐条核对。
  • 站点只维护一份最新文档，不按版本复制页面；正文标注的源码基线用于说明“这批描述对应哪次复核”。
  • 安装包以 PyPI 为准，容器镜像以 Docker Hub 为准。
