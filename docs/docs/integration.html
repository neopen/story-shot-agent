集成与接口

集成指南

Python SDK、REST API、MCP 与 LangGraph/A2A 的接入方式。

更新 2026-10-31 约 15 分钟阅读 在 GitHub 编辑

PenShot 对外提供 Python SDK、REST API 与 MCP Server 三条官方接入路径，仓库 examples 目录另含 LangGraph 与 A2A 封装示例。环境准备与第一个任务见 快速开始。

接入路径

路径适用场景入口
Python SDK嵌入自有 Python 服务，需要回调、批量或动态并发penshot.api.PenshotFunction
REST API前后端分离、跨语言调用，或直接作为内部服务/api/v1，17 个端点
MCP Server挂载到 Claude Desktop、Cursor 等 MCP 客户端7 个工具，stdio 或 HTTP
LangGraph / A2A更大工作流中的编排示例examples/，非产品内置协议
 
flowchart LR
    A["业务代码"] --> B["Python SDK"]
    A --> C["REST API"]
    D["MCP 客户端"] --> E["MCP Server"]
    E --> B
    B --> F["TaskFactory 任务池"]
    C --> F
    F --> G["工作流编排"]
    G --> H["PenshotResult / JSON 结果"]

SDK、REST 与 MCP 最终都进入同一套任务模型，差异在协议适配层。REST 与 MCP 不需要额外编写业务逻辑；需要自定义鉴权、计费或路由时，再用 SDK 嵌入自有服务。

安装与配置

pip install penshot

# 通义千问
pip install dashscope

# 本地 Ollama
pip install langchain-ollama

最小配置写在项目根目录的 .env，导入 penshot.config 时自动加载。对话模型必填，嵌入模型在使用记忆或语义检索时需要；Redis 仅用于多进程任务记录共享。

变量组用途必需性
PENSHOT_LLM__DEFAULT__*BASE_URL、API_KEY、MODEL_NAME必需
PENSHOT_LLM__FALLBACK__*主模型不可用时的备用厂商可选
PENSHOT_EMBED__DEFAULT__*嵌入模型地址、密钥与模型名记忆功能需要
PENSHOT_REDIS_URL多进程任务记录与短期记忆共享多进程必需

变量层级用双下划线表示，DEFAULT 与 FALLBACK 是两个模型 profile。完整键位、厂商示例与 ${ENV_VAR} 引用方式见快速开始的配置章节。

Python SDK

构造与实例

参数类型默认值说明
configShotConfigNone流程参数，None 时使用默认配置
languageShotLanguageZH输出语言，支持 ZH 与 EN
max_concurrentint10最大并发任务数

create_penshot_agent(config=None, language=ZH, max_concurrent=10, queue_size=1000) 是等价便利函数。实例创建后会启动后台事件循环线程，进程退出前应调用 shutdown()。

13 个公开方法

方法关键参数与默认值返回

script_id 是调用方自定义的关联 ID，同属一个剧本的多次请求可传相同值；真实 task_id 由提交方法返回。优先级取自 TaskPriority：LOW=1、NORMAL=2、HIGH=3、CRITICAL=4。

同步与异步

from penshot import ShotLanguage
from penshot.api import create_penshot_agent

agent = create_penshot_agent(language=ShotLanguage.ZH, max_concurrent=5)
try:
    task_id = agent.breakdown_script_async(script, script_id="demo-001")
    result = agent.wait_for_result(task_id, timeout=600.0)
finally:
    agent.shutdown()

breakdown_script_async() 只负责提交并立即返回，不会阻塞；wait_for_result_async() 才是协程。在 asyncio 环境中直接 await wait_for_result_async(task_id)，不要对提交方法加 await。回调参数是一个接收 PenshotResult 的普通函数，在任务完成时触发。

breakdown_script() 是“提交 + 等待”的同步封装，默认等待 300 秒，超时返回 None；任务本身仍受 workflow_timeout（默认 1800 秒）约束。同步等待上限应小于任务总预算，避免外层已返回、内层仍在运行。

结果对象

字段类型说明
task_idstr任务 ID，前缀为 TSK
successbool是否成功
statusTaskStatus任务状态枚举，不是普通字符串
datadict业务结果，分镜数据入口为 data["instructions"]
errorstr 或 None失败原因
processing_time_msint处理耗时，单位毫秒

分镜结果的主要字段位于 data["instructions"]：metadata、project_info 与 fragments。fragments 中每个片段包含 fragment_id、prompt、negative_prompt、duration、model、style 与可选的 audio_prompt；metadata.repair_history 记录提示词截断等修复动作。

任务状态

状态值含义
PENDINGpending已提交，等待处理
PROCESSINGprocessing处理中
SUCCESSsuccess成功终态
FAILEDfailed失败终态
CANCELLEDcancelled取消终态
NOT_FOUNDnot_found任务不存在或已过期
TIMEOUTtimeout任务超时
UNKNOWNunknown未知状态

成功终态是 SUCCESS，不存在 COMPLETED。轮询应以 success、failed、cancelled 结束，并对 not_found 停止重试。TaskStatus 是字符串枚举，TaskStatus.SUCCESS == "success" 成立，但比较时建议统一取 .value 或直接与枚举成员比较。

get_task_status() 返回的 progress 按阶段权重累加：解析 0–15、拆分 15–30、分段 30–50、转换 50–70、审查 70–85、连续性 85–95、输出 95–100。stages_progress 以阶段名为键，包含阶段级 progress 与 status；阶段级 completed 只表示该阶段结束，与任务状态枚举无关。

REST API

内置 REST 服务由 FastAPI 实现，路由前缀固定为 /api/v1。启动后可直接访问 /docs 查看交互文档，无需另写包装层。

story-shot-agent serve-rest --host 0.0.0.0 --port 8000

# 等价入口
python -m penshot.http_server --port 8000

提交请求的字段为 script（剧本正文，必填）、script_id、style、language、config 与 callback_url。异步接口返回 status="pending" 与 task_id；批量接口的 scripts 最多 50 条。

curl -X POST http://localhost:8000/api/v1/storyboard \
  -H "Content-Type: application/json" \
  -d '{"script":"现代办公室，小李正在写代码，突然接到电话。","language":"zh","script_id":"demo-001"}'

curl http://localhost:8000/api/v1/status/TSK2026xxxx
curl http://localhost:8000/api/v1/result/TSK2026xxxx

/tasks 当前只返回分页骨架，任务明细应通过 /status/{task_id} 或 /pending-tasks 获取。/result/{task_id} 在任务未结束时仍返回 200，message 会提示当前状态；判断成败以 status 为准。

MCP Server

MCP Server 把 SDK 封装为 7 个工具：提交、查询状态、获取结果、取消、列表、队列状态与统计。支持 stdio 与 HTTP 两种传输，供 Claude Desktop、Cursor 等客户端调用。启动参数、工具契约、JSON-RPC 交互与客户端配置见 MCP 服务。

REST 与 MCP 是并列的协议入口，不需要同时启用。已经通过 HTTP 暴露服务时，MCP 只增加面向 LLM 客户端的工具描述，不改变任务执行链路。

LangGraph 与 A2A

examples/workflow/01_langgraph_integration.py 与 examples/integrations/a2a_integration.py 属于示例层代码，不是产品内置能力，也不随 SDK 契约提供兼容承诺。

LangGraph 示例把调用拆成提交节点与等待节点：提交节点是同步函数，直接取得 task_id；等待节点使用 await wait_for_result_async()。轮询模式会设置 60 次上限，避免无密钥或上游卡死时无限循环。

def submit_node(state):
    task_id = agent.breakdown_script_async(script_text=state.script, script_id=state.script_id)
    return {"task_id": task_id}

async def wait_node(state):
    result = await agent.wait_for_result_async(state.task_id, timeout=900.0)
    return {"result": result}

A2A 示例演示的是封装方式，不是 A2A 协议实现。它把 A2A 层任务 ID 作为 script_id 传入，后端返回的 task_id 单独保存用于轮询，从而避免两套 ID 混用。示例还包含 round_robin 与 least_loaded 两种分发策略，可按需改造。

ShotConfig 配置

ShotConfig 承载流程参数，不承载模型连接信息。LLM 与嵌入模型的地址、密钥、模型名通过 PENSHOT_LLM__* 与 PENSHOT_EMBED__* 注入，位于继承自 AIConfig 的嵌套 llm、embed 对象中。

字段默认值说明
enable_llmTrue关闭后使用规则解析与拆分
max_total_loops20工作流最大总循环次数
max_shot_duration / min_shot_duration / default_shot_duration60.0 / 1.0 / 3.0镜头时长上限、下限与默认值，单位秒
llm_confidence0.6低于该置信度触发规则修正
duration_split_threshold5.5片段超过该秒数触发再分割
max_fragment_duration / min_fragment_duration5.0 / 1.0分割片段时长区间
video_model / audio_modelrunway_gen2 / XTTSv2写入提示词的生成模型标识
max_prompt_length / min_prompt_length200 / 20提示词单词数上下限
human_intervention_modeinteractiveauto / interactive / callback
workflow_timeout1800工作流总超时，单位秒
checkpoint_modeautoauto / memory / sqlite / postgres
max_checkpoints_per_script10单剧本保留的检查点数量

AIConfig 还提供 cinematic_knowledge、pacing_principles 两个默认开启的影视知识开关，以及默认关闭的 enable_llm_cache（缓存 TTL 300 秒）。构造时会校验时长与长度区间，max 不大于 min 会直接抛出 ValueError。

接入检查清单

  1. 通过 create_penshot_agent() 或 REST 启动服务，确认 /api/v1/health 返回 healthy。
  2. 轮询条件使用 success、failed、cancelled，不要写 completed。
  3. 同步等待为 None 时按超时处理，并为异步任务保留 workflow_timeout 预算。
  4. 多进程或容器多副本部署时配置 Redis，确保提交与查询看到同一份任务记录。
  5. 结果读取统一走 result.data["instructions"]，不要假设顶层直接存在 fragments。
  6. 长剧本按章节分批提交，复用 script_id 关联同一剧本；需要恢复时固定 checkpoint_mode。

接口与默认值以当前源码为准；工作流内部实现见 开发指南，检查点与恢复见 检查点与恢复，版本记录以 GitHub 仓库 为准。
