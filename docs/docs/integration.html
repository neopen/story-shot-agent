PenShot（剧本分镜智能体）对外提供三条官方接入路径：Python SDK（PenshotFunction）、内置 REST API（/api/v1 前缀，17 个端点）与 MCP Server（7 个工具，面向 Claude Desktop / Cursor）；此外仓库 examples 目录还提供 LangGraph 与 A2A 的封装示例。本文以源码与 examples 为准绳，逐条考证各路径的真实用法：哪些方法必须 await、哪些参数并不存在、任务状态到底有几个终态、ShotConfig 究竟配置什么，都会给出可验证的答案。
文中代码分两类：标注为官方 SDK / REST / MCP 的片段来自 src/penshot 产品源码；标注为示例层的片段来自 examples 目录（可运行，但不是产品内置能力）。

一、速成指南

本章面向想先把链路跑通的读者：每节只保留一条最短可用路径，环境变量只列必填项，代码省略错误处理与并发调优细节；运行环境准备（Python 3.10+，Redis 可选）可先阅读《三分钟快速使用指南》。

先给结论：三条官方路径中，Python SDK 适合嵌入自有服务；内置 REST API 适合前后端分离部署（/api/v1 下 17 个端点，开箱即用，无需自己包装）；MCP Server 适合把分镜能力挂给 Claude Desktop / Cursor 这类支持 MCP 的客户端。仓库 examples 目录中的 LangGraph / A2A 封装属于示例层代码，可作模板参考。

详细使用方法与完整示例代码，可参照 GitHub 示例目录：story-shot-agent/examples

1. 安装依赖

# 直接安装
pip install penshot

# 使用千问
pip install dashscope

  1. 复制示例文件：cp .env.example .env

# ================= LLM默认配置 =================

PENSHOT_LLM__DEFAULT__BASE_URL=https://api.openai.com/v1
PENSHOT_LLM__DEFAULT__API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PENSHOT_LLM__DEFAULT__MODEL_NAME=gpt-4o

# ================ 嵌入模型默认配置 ================

PENSHOT_EMBED__DEFAULT__BASE_URL=https://dashscope-intl.aliyuncs.com/api/v1
PENSHOT_EMBED__DEFAULT__API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PENSHOT_EMBED__DEFAULT__MODEL_NAME=text-embedding-v4

########################## Redis 配置 ##########################
# 单节点 URL 形式（也可拆成 host/port/db/password 配置，见第四章）
PENSHOT_REDIS_URL=redis://:123456@localhost:6379/0

Redis 在单进程模式下并非硬依赖，但多进程（workers > 1）部署时必须配置：主程序在检测到多进程且 Redis 不可用时会打印警告——任务状态会分裂在各个进程内，详见第四章。

3. 作为 Python 库使用（最简接入）

from penshot.api import create_penshot_agent

agent = create_penshot_agent()

# 同步调用：提交并等待完成（超时会返回 None，注意判空）
result = agent.breakdown_script(script, wait_timeout=600.0)

# 异步调用：breakdown_script_async 是普通函数（不是协程），返回 str 类型的 task_id
task_id = agent.breakdown_script_async(script, script_id="my-script-001")

# 等待结果 / 查询状态
result = agent.wait_for_result(task_id, timeout=600.0)
status = agent.get_task_status(task_id)

# 使用完毕后释放后台事件循环
agent.shutdown()

两个最容易踩的坑：(1) breakdown_script_async 不是协程，await agent.breakdown_script_async(...) 会直接报 TypeError——需要异步等待时用 await agent.wait_for_result_async(task_id)；(2) 参数名是 script_id（调用方自定义的关联 ID），不是 task_id——真实 task_id 由方法返回值提供。

4. 集成到 Web 应用

如果只是要把分镜能力暴露成 HTTP 服务，优先直接用项目内置的 REST 服务（启动后路由前缀为 /api/v1），不需要自己写包装层：

# 提交任务（异步）
curl -X POST http://localhost:8000/api/v1/storyboard \
  -H "Content-Type: application/json" \
  -d '{"script_text": "现代办公室，小李正在写代码，突然接到电话。", "language": "zh"}'

# 轮询状态与结果
curl http://localhost:8000/api/v1/status/{task_id}
curl http://localhost:8000/api/v1/result/{task_id}

在自己已有的 FastAPI 服务里嵌入 SDK 时（示例层写法，来自 examples/integrations/fastapi_web_app.py）：

from penshot.api import create_penshot_agent

agent = create_penshot_agent()

@app.post("/api/generate")
async def generate(request: ScriptRequest):
    # 立即返回 task_id，前端轮询状态接口
    task_id = agent.breakdown_script_async(request.script_text, script_id=request.script_id)
    return {"task_id": task_id, "status": "pending"}

@app.get("/api/status/{task_id}")
async def get_status(task_id: str):
    return agent.get_task_status(task_id)

5. MCP Server 集成

Penshot MCP Server 支持 Claude Desktop、Cursor 等 MCP 兼容客户端。

启动服务

python -m penshot.mcp_server --max-concurrent 5 --queue-size 500

Claude Desktop 配置

{
  "mcpServers": {
    "penshot": {
      "command": "python",
      "args": ["-m", "penshot.mcp_server"]
    }
  }
}

支持的工具（共 7 个）

工具 功能
breakdown_script 提交剧本拆分
get_task_status 查询任务状态
get_task_result 获取任务结果
cancel_task 取消任务
list_tasks 列出任务
get_queue_status 获取队列状态
get_stats 获取统计信息

排坑：当前版本的 get_tools_list 将所有工具的参数 schema 统一返回为空的 {"type": "object", "properties": {}}，客户端（LLM）看不到 script、language、wait 等参数名，只能凭 description 猜测。接入后若工具调用参数不符合预期，可对照 mcp_server.py 中各 _handle_* 方法实际读取的键名（script / language / wait / timeout / task_id）在提示词中自行约束。

MCP 是什么：Model Context Protocol 是让 LLM 客户端与外部工具通信的开放协议。接入 MCP 后，Claude Desktop / Cursor 就可以把 PenShot 当作一个工具直接调用，而不需要你写业务代码，适合把分镜能力挂进 Agent 工作流。stdio 模式下协议走 stdout，服务日志统一走 stderr——调试时不要把业务 print 混入服务端。

6. 集成到 LangGraph（示例层）

来自 examples/workflow/01_langgraph_integration.py 的真实节点写法。关键区别：提交节点是同步函数（breakdown_script_async 返回 task_id 字符串，不需要 await），只有等待节点才 await：

from penshot.api import PenshotFunction

class StoryboardWorkflowNodes:
    def __init__(self):
        self.agent = PenshotFunction(max_concurrent=5)

    def submit_task_node(self, state) -> dict:
        # 同步方法：立即返回真实 task_id
        task_id = self.agent.breakdown_script_async(
            script_text=state.script_text,
            script_id=state.script_id,      # 关联 ID，不是轮询 ID
            language=ShotLanguage.ZH,
        )
        return {"task_id_assigned": task_id, "stage": "parsing"}

    async def wait_for_result_node(self, state) -> dict:
        # 协程：直接 await，建议显式传入 timeout
        result = await self.agent.wait_for_result_async(state.task_id_assigned, timeout=900.0)
        return {"result": result}

真实示例还包含一个轮询模式工作流：轮询 get_task_status 并按 TaskStatus 终态路由，超过 60 次轮询即失败退出，避免无 key 等场景下死循环。

7. A2A 集成（示例层）

仓库中的 examples/integrations/a2a_integration.py 是 A2A 封装示例，不是产品内置协议实现。它的核心设计是把 A2A 层任务 ID 与 Penshot 后端 task_id 分离：

async def _execute(self, task: A2ATask) -> None:
    language = ShotLanguage.ZH if task.language == "zh" else ShotLanguage.EN
    # A2A ID 作为关联 ID（script_id），真实轮询 ID 用返回值
    backend_id = self.penshot.breakdown_script_async(
        script_text=task.script_content,
        script_id=task.a2a_id,
        language=language,
    )
    task.backend_task_id = backend_id
    result = await self.penshot.wait_for_result_async(backend_id, timeout=900.0)
    if result.success:
        task.status = A2ATaskStatus.SUCCESS

示例同时给出 A2AOrchestrator（round_robin / least_loaded 两种分发策略）、process_task（阻塞）与 process_task_async（后台协程，立即返回）的完整实现，可作为多代理编排的脚手架。

priority 取值来自 TaskPriority 枚举：LOW=1 / NORMAL=2 / HIGH=3 / CRITICAL=4。批量任务与单任务共用同一套任务池，队列语义由 TaskFactory 统一管理。

任务状态：8 态枚举

TaskStatus 是 str 枚举（定义于 penshot.neopen.task.task_models），共 8 个成员：

状态 值 说明
PENDING pending 等待处理
PROCESSING processing 处理中
SUCCESS success 成功终态
FAILED failed 失败终态
CANCELLED cancelled 已取消终态
NOT_FOUND not_found 任务不存在
TIMEOUT timeout 超时
UNKNOWN unknown 未知

重点纠偏：成功终态是 SUCCESS（值 "success"），不存在 COMPLETED。由于是 str 枚举，TaskStatus.SUCCESS == "success" 成立，但更稳妥的写法是显式取 .value 或直接与枚举成员比较。常见错误是写 if status == "completed"——永远不会命中，轮询会一直空转。

任务阶段：进度不是黑盒

TaskStage 定义了带权重（weight）的处理阶段，get_task_status() 返回的 stages_progress 按这些权重推进：

阶段区间 权重范围 阶段区间 权重范围
解析剧本 0 → 15 质量审查 70 → 85
拆分镜头 15 → 30 连续性检查 85 → 95
视频分段 30 → 50 输出生成 95 → 100
提示词转换 50 → 70 COMPLETE 终态 100

每个阶段内部还有 start/in-progress/complete 三个子状态（如 segment_start / segmenting / segment_complete），因此前端进度条可以直接由 stages_progress 驱动。

PenshotResult

字段 类型 说明
task_id str 任务 ID（格式 TSK + 剧本码 + 时间戳 + 随机数）
success bool 是否成功
status TaskStatus 任务状态（枚举，非普通字符串）
data Dict 结果数据（契约入口为 data["instructions"]）
error Optional[str] 错误信息
processing_time_ms int 处理耗时（毫秒）

错误响应结构

内置 REST 服务的统一异常处理器返回如下结构：

{"error": "任务不存在: TSKxxx", "status_code": 404, "path": "/api/v1/result/TSKxxx"}

  • HTTPException：透传状态码与 detail（常见 400/404）

  • 未捕获异常：统一 500，返回 {"error": "Internal server error", "detail": "...", "path": "..."}

接入排坑速查

症状 根因与解法
TypeError: object str can't be used in 'await' expression breakdown_script_async 是同步方法，去掉 await；需要异步等待时用 await wait_for_result_async(task_id)
TypeError: breakdown_script() got an unexpected keyword argument 'task_id' 参数名是 script_id（调用方关联 ID），真实 task_id 用返回值
轮询永远不结束 判断条件写了 "completed"；真实成功终态是 "success"
wait_for_result 返回 None 等待超时（默认 300 秒），核对 wait_timeout 与 workflow_timeout（默认 1800 秒）
MCP 客户端调用参数不符预期 工具参数 schema 为空，对照 _handle_* 方法实际读取的键名约束提示词
多进程部署后任务查不到 未配置 Redis，任务状态分裂在各 worker 进程

三、配置与部署建议

ShotConfig：真实字段（流程参数，不是模型连接配置）

分组 字段 默认值 说明
流程控制 enable_llm True 关闭后走规则解析
流程控制 max_total_loops 20 最大总循环次数
镜头拆分 max_shot_duration / min_shot_duration / default_shot_duration 60.0 / 1.0 / 3.0 镜头时长区间与默认值
镜头拆分 llm_confidence 0.6 置信度阈值，低于则触发规则修正

ShotConfig.__post_init__ 会校准时长的区间关系（如 max_fragment_duration > min_fragment_duration），区间写反会在构造时直接抛 ValueError。

澄清：LLM / Embedding 的连接信息（base_url、api_key、model_name）不在 ShotConfig 顶层，而是通过环境变量（PENSHOT_LLM__DEFAULT__*、PENSHOT_EMBED__DEFAULT__*）注入配置系统；ShotConfig 继承的 AIConfig 只承载 llm / embed 两个嵌套配置对象、影视知识注入开关（cinematic_knowledge、pacing_principles）与默认关闭的 LLM 缓存开关。早期文档把 model_name / api_key 等写成 ShotConfig 的直接字段，是不准确的。

部署建议（依据真实参数）

  1. 并发与队列：max_concurrent 默认 10、queue_size 默认 1000，按 LLM 供应商的 RPM 限额调整；运行中可用 set_max_concurrent() 动态调整。

  2. 超时分层：单次等待（wait_timeout）应小于任务总预算（workflow_timeout=1800），否则会出现外层已超时、内层还在跑的悬空任务——尤其同步接口 + 长剧本场景。

  3. 多进程必配 Redis：多 worker 部署且未配置 Redis 时，任务提交与查询可能落到不同进程，表现为刚提交就任务不存在；主程序会在启动时打印明确警告。

  4. 检查点模式：长剧本或需要人机干预的场景，建议将 checkpoint_mode 从 auto 固定为 sqlite / postgres，保证中断可恢复。

  5. 超长剧本：当前版本没有自动分块能力（可参考《分块策略》一文的源码考证），长剧本应按章节分批提交，并用相同的 script_id 关联同属一个剧本的多次请求。

4.3 作为 Python 库使用（完整示例）

参考：examples/sdk/01_sync_breakdown.py（同步）与 examples/sdk/02_async_submit_poll.py（异步+回调+轮询）。下面是提炼后可直接复用的代码。

同步调用：

from penshot import ShotLanguage
from penshot.api import PenshotFunction
from penshot.neopen.agent.base_models import VideoStyle

# PenshotFunction 用 TaskFactory 统一管理任务队列、并发与生命周期
agent = PenshotFunction(language=ShotLanguage.ZH, max_concurrent=5)

try:
    result = agent.breakdown_script(
        SAMPLE_SCRIPT,
        script_id="sdk-sync-001",        # 同属一个剧本的多次请求可传相同 ID，便于关联
        style=VideoStyle.CINEMATIC,       # 视频风格（可选）
        wait_timeout=600.0,               # 同步等待超时（秒）
    )
    print(f"成功: {result.success}, 状态: {result.status.value}")  # 枚举取 .value

    # 结果契约：result.data["instructions"]
    data = result.data or {}
    instructions = data.get("instructions", {})
    fragments = instructions.get("fragments", [])
    project_info = instructions.get("project_info", {})
    print(f"片段数: {project_info.get('total_fragments', len(fragments))}")
    print(f"总时长: {project_info.get('total_duration', 0.0):.1f} 秒")
    for i, frag in enumerate(fragments[:3], 1):
        print(f"[{i}] {frag.get('fragment_id')}: {str(frag.get('prompt', ''))[:70]}...")
finally:
    agent.shutdown()                     # 释放后台任务线程/事件循环

异步提交 + 回调 + 轮询 + 异步等待：

import time
from penshot import ShotLanguage
from penshot.api import PenshotFunction
from penshot.neopen.task.task_models import TaskStatus

TERMINAL_STATUS = {
    TaskStatus.SUCCESS.value, TaskStatus.FAILED.value, TaskStatus.CANCELLED.value,
}  # 终态：success / failed / cancelled

agent = PenshotFunction(language=ShotLanguage.ZH, max_concurrent=5)

# 1) 异步提交：普通函数（不是协程），立即返回 task_id 字符串
task_id = agent.breakdown_script_async(
    SCRIPT_A,
    script_id="sdk-async-001",
    language=ShotLanguage.ZH,
    callback=lambda r: print(f"[回调] 任务 {r.task_id} 完成, success={r.success}"),
)

# 2) 轮询状态（get_task_status 返回的 status 是 TaskStatus 枚举，需 .value）
while True:
    status = agent.get_task_status(task_id)
    if not status:
        break
    print(f"[轮询] {status['stage_name']} | {status['status'].value} | {status['progress']}%")
    if status["status"].value in TERMINAL_STATUS:
        break
    time.sleep(2)

# 3) 三种取结果方式，按场景任选
result = agent.wait_for_result(task_id, timeout=600.0)            # 阻塞等待
# result = await agent.wait_for_result_async(task_id, timeout=600.0, poll_interval=1.0)  # asyncio 环境
# result = agent.get_task_result(task_id)                          # 已终态时直接取

agent.shutdown()

4.5 集成到 LangGraph 节点（示例层）

参考：examples/workflow/01_langgraph_integration.py（281 行，含两种工作流与轮询上限保护）。

该示例构建了两种模式：等待模式（提交 → await 等待结果）与轮询模式（提交 → 轮询状态直到终态，超过 60 次失败退出）。三个关键写法值得照抄：

1. 提交节点是同步函数

breakdown_script_async 返回 task_id 字符串，不是协程，不该 await：

def submit_task_node(self, state: StoryboardState) -> Dict[str, Any]:
    task_id = self.agent.breakdown_script_async(
        script_text=state.script_text,
        script_id=state.script_id,  # 关联 ID，不是轮询 ID
        language=self._language(state),
    )
    return {"task_id_assigned": task_id, "stage": WorkflowStage.PARSING, "progress": 10.0}

2. 轮询节点按 TaskStatus 终态路由

示例先定义了一个终态归一函数，避免写出不存在的 "completed"：

def terminal_status(status) -> Optional[str]:
    """把任务状态归一为终态字符串：success / failed / cancelled；未结束返回 None"""
    if status in (TaskStatus.SUCCESS, "success"):
        return "success"
    if status in (TaskStatus.FAILED, "failed"):
        return "failed"
    if status in (TaskStatus.CANCELLED, "cancelled"):
        return "cancelled"
    return None

轮询节点还设置了次数上限（poll_count >= 60 即失败退出），避免无 key、上游卡死等场景下无限循环。

3. 等待节点显式传 timeout

async def wait_for_result_node(self, state: StoryboardState) -> Dict[str, Any]:
    result = await self.agent.wait_for_result_async(state.task_id_assigned, timeout=900.0)
    if result.success:
        return {"stage": WorkflowStage.COMPLETED, "result": result, "progress": 100.0}
    return {"stage": WorkflowStage.FAILED, "error": result.error, "progress": 0}

结果取数与第二章一致：仍是 result.data["instructions"] 契约。

LangGraph 接入思路：把 PenShot 封装成提交节点、轮询/等待节点后插进 LangGraph 有向图，即可让分镜生成成为更大智能体工作流的一环。两种模式二选一即可：等待模式链路短但节点会阻塞到任务结束；轮询模式对图引擎更友好，但要自己做次数上限与退避。

4.6 集成到 A2A 系统（示例层）

参考：examples/integrations/a2a_integration.py（286 行）。这是一个示例层封装：PenShot 本身不是 A2A 协议实现，示例演示了如何把手里的 PenshotFunction 包装成可被编排的分镜代理。

核心设计：双层任务 ID 分离。A2A 层的任务 ID 由调用方指定（用于跨代理编排），调用 PenShot 时作为 script_id 关联，真正用于轮询/等待的后端 task_id 用返回值：

async def _execute(self, task: A2ATask) -> None:
    language = ShotLanguage.ZH if task.language == "zh" else ShotLanguage.EN
    backend_id = self.penshot.breakdown_script_async(
        script_text=task.script_content,
        script_id=task.a2a_id,          # A2A ID 作为关联 ID
        language=language,
    )
    task.backend_task_id = backend_id   # 真实轮询 ID
    result = await self.penshot.wait_for_result_async(backend_id, timeout=900.0)
    if result.success:
        task.status = A2ATaskStatus.SUCCESS
        task.result = result
    else:
        task.status = A2ATaskStatus.FAILED
        task.error = result.error

示例还包含：

  • A2ATaskStatus：pending / processing / success / failed / cancelled（与 Penshot 语义对齐，同样没有 completed）

  • process_task（阻塞式）与 process_task_async（asyncio.create_task 后台执行，立即返回）

  • A2AOrchestrator：多代理注册 + 两种分发策略（round_robin / least_loaded）

  • cancel_task：先取消后端任务，再取消本地后台协程

A2A 层与 Penshot 层的状态、优先级、取消语义都是各自独立的（示例中的 A2ATaskPriority 与 Penshot 的 TaskPriority 是两套枚举）。跨层映射由你的编排逻辑负责，示例的写法是：A2A 负责编排与分发，Penshot 负责执行。

五、接入小结

三条官方路径 + 两个示例层封装，按场景选择：

场景 选择 关键点
脚本、内部工具 Python SDK 同步接口 breakdown_script 超时返回 None
高并发服务 SDK 异步 + 轮询/回调 breakdown_script_async 不加 await
前后端分离、快速上线 内置 REST API /api/v1 17 个端点开箱即用
Claude / Cursor 工具链 MCP Server 注意空参数 schema，需约束提示词
更大 Agent 工作流 LangGraph / A2A 示例 示例层代码，需自行维护

生产接入前的检查清单：

  1. 确认回调/轮询判断用的是 success 而不是 completed；

  2. 为 wait_for_result 处理 None 返回（超时）；

  3. 多进程部署配置 Redis，否则任务状态分裂；

  4. 用 get_queue_status() / get_stats() 接入监控；

  5. 超长剧本分批提交并复用 script_id 关联。

一句话总结：PenShot 的三条官方接入路径都已经产品化（pip 包 + 内置 REST + MCP Server），开箱可用；LangGraph / A2A 则是 examples 里的脚手架，适合拿来改。真正需要小心的不是接不上，而是文档与示例中流传的几处错误习惯（await 同步方法、task_id 参数、completed 终态）——它们不会在编译期报错，只会在运行时静默出问题，本文的排查清单可对照使用。
