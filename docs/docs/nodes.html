核心设计

工作流节点

逐个拆解八个业务节点：输入、规则、LLM 调用、资产计划与模型路由。

更新 2026-11-27 约 32 分钟阅读

PenShot 的八段工作流由 LangGraph 编排：每个业务节点完成一次内容生产，经决策函数返回八种状态之一，再进入下一节点、重试、修复或转人工。

节点总览

业务节点按“解析→资产计划→拆分→切割→转换→模型路由→审计→守护”顺序执行；拆分、切割、转换、路由成功后先经过 LOOP_CHECK，错误处理与人工干预为全局兜底。

决策语义与路由表见技术架构。节点内部失败不直接抛异常，而是转为问题列表或错误对象，由决策函数决定重试、修复、人工或中止。

各节点产物统一挂在 state.domain，键名与阶段对应；片段 ID 以 frag_ 开头，元素缺失 ID 时按 elem_{场景序号}_{元素序号} 补全。节点只读取上游产物与属于自己的修复参数，不修改其他节点的键。

剧本解析 PARSE_SCRIPT

将任意格式剧本统一为结构化中间表示，只提取语义元素，不写入时间信息；时长完全交给下游镜头拆分。

flowchart LR
    subgraph Input
        A[原始剧本文本]
    end

    subgraph Process[解析流程]
        B[格式识别<br/>正则规则] --> C[匹配对应系统提示词<br/>六种格式分流]
        C --> D[LLM语义解析]
        D --> E[构建Pydantic模型<br/>ID生成/字段补全]
        E --> F[五维完整性评分]
    end

    subgraph Output
        G[结构化剧本<br/>ParsedScript]
    end

    A --> B --> G
输入 输出
原始剧本文本（自然语言、标准剧本、AI 分镜等） ParsedScript：metadata、title、characters、scenes、global_metadata、stats

格式识别

_detect_script_format 用正则按优先级分类，命中后选择对应的系统提示词；全部不命中时退回通用提示词，不报错。

优先级 判定规则 结果
1 INT. / EXT. / 内景 / 外景 / 场景N： STANDARD_SCRIPT
2 镜头N / shot N / 分镜N / 画面描述： AI_STORYBOARD
3 场景： / 地点： / 时间： / 角色： STRUCTURED_SCENE
4 角色：台词 行数占比 > 70% DIALOGUE_ONLY
5 句号 / 感叹号 / 问号数量 > 冒号 / 引号数量 NATURAL_LANGUAGE
6 以上均不命中 MIXED_FORMAT

质量评估与校验

_evaluate_completeness 给出五维加权分：场景 0.25、角色 0.25、对话 0.20、动作 0.20、总体覆盖率 0.10；再按 min(0.2, 问题数 × 0.05) 扣分。元素 sequence 汇总后校验是否为 1…N，不连续只记 Warning，不阻断流程；缺失 id 时按 elem_{场景序号}_{元素序号} 补全。

解析阶段同时写入全局风格锚点与溯源信息（style_anchor_provenance），供资产计划与提示词转换复用。失败与降级：结果为空或完整性过低时，decide_after_parsing 路由回本节点重试；正则漏判退回 MIXED_FORMAT 通用提示词；没有原文偏移量回溯，sequence 的正确性依赖 LLM 输出质量。

资产计划 GENERATE_ASSETS

把角色、道具、场景转换为可复用的资产锚点规格，默认只产出声明式计划，不调用任何外部文生图服务；同时接受下游回填的资产清单，把声明式 asset_id 绑定到真实资产引用。字段、两种接入方式与人工编辑流程见资产计划与交接。

每个资产以 AssetSpec 描述：asset_id、asset_type、owner_name、正负提示词、尺寸、视角、使用范围、连续性约束（identity_lock、preferred_view、建议 seed）与状态。计划整体序列化为 AssetPlanDocument，带 schema_version、style_anchor 与资产列表，写入 asset_plan.json。

报告 AssetGenerationReport 记录 mode（plan / manifest / generated）、供应商、总数、成功/失败/待生成/跳过数量、回填应用数量与错误。无论是否启用出图，asset_plan.json 与 asset_generation_report.json 都会落盘；资产失败不阻断主流程，由下游首帧指令兜底。真实出图默认关闭（image.default.enabled=false），开启后由 ImageClientExecutionAdapter 调用文生图客户端。

回填清单 AssetManifest 支持 bindings 与 asset_id_map（下游改名映射），并兼容下游直接写 assets 的格式。绑定包含 asset_id、view、asset_ref、model、seed、checksum、revision 与错误信息；引用会做格式校验，非法引用降级为警告。

失败与降级：计划生成失败或未启用出图时，资产保持 pending 并继续拆分；同一角色只保留首值外观锚点，后续服装变化进入 outfit_sequence，不会覆盖首次身份特征。

镜头拆分 SEGMENT_SHOT

把场景中的元素序列划分为视觉独立的镜头，并给出景别与时长。LLM 与规则两种实现共享 ShotSequence 输出，由 ShotSegmenterFactory 按 enable_llm 选择。

flowchart LR
    subgraph Input
        A[结构化剧本]
    end

    subgraph Process[拆分流程]
        B[场景遍历] --> C[元素序列分组]
        C --> D{合并判断}
        D -->|连续对话且同角色| E[合并进当前镜头]
        D -->|连续动作（默认不合并）| F[创建新镜头]
        D -->|对话后短动作<3秒| E
        E --> G[镜头类型判定]
        F --> G
        G --> H[时长估算器覆写]
        H --> I[增强器后处理]
    end

    subgraph Output
        J[镜头序列JSON]
    end

    A --> B --> J
输入 输出
ParsedScript 的场景与元素 ShotSequence：镜头 id、scene_id、description、start_time、duration、shot_type、main_character、element_ids

规则模式

判断 条件 结果
连续对话 两个 DIALOGUE 且角色相同 合并进同一镜头
连续动作 两个 ACTION 且角色相同 默认不合并（merge_consecutive_actions=False）
对话后短动作 DIALOGUE 后紧跟 <3.0 秒的 ACTION 合并

景别判定：组内含对话→特写 close_up；含场景描述→全景 wide_shot；其余→中景 medium_shot。ShotType 枚举共 13 种，提示词列出 8 种使用场景供 LLM 选择。

时长估算

LLM 给出的时长只作草案，拆分完成后 estimator_factory.estimate_sequence() 会覆写 shot.duration。动作估算器按中景基准 2.8 秒起算，叠加描述复杂度、速度关键词、场景情绪、角色特征，再与 ActionDurationEstimatorTool 结果按 0.4 : 0.6 加权，最后 clamp 到景别区间。DurationEnhancer 负责边界校准、情感特写至少 3.0 秒、开场/结尾 ×1.2、连续同型镜头错开 0.3 秒。

时长估算后还会做一轮分镜自检：镜头类型是否单一、是否存在相邻重复镜头、角色是否都有镜头覆盖。角色覆盖不仅看 main_character，也统计镜头内元素归属的角色；画外音或电话另一端等“仅声音角色”按台词元素计入，不再被误报为缺席（character_not_in_shots）。

失败与降级：估算器是关键词与固定系数规则，不感知语义；merge_consecutive_actions=False 会把连续动作拆成多个镜头；增强器中 climax / transition 的节奏系数尚未被引用，当前仅 opening / ending 生效。

片段切割 SPLIT_VIDEO

把超长镜头切分为符合单段时长上限的片段，并把镜头级连续性信息写入片段注释。

flowchart LR
    subgraph Input
        A[镜头序列]
    end

    subgraph Process[分段流程]
        B[镜头遍历] --> C{时长判断}
        C -->|≤阈值5.5秒| D[直接成段]
        C -->|>阈值 且 LLM模式| E[LLM语义切分]
        C -->|>阈值 且 规则模式| F[数学均分<br/>最多3段]
        E --> G[校验与时长微调]
        F --> G
        D --> H[连续性注解]
        G --> H
    end

    subgraph Output
        I[片段序列JSON]
    end

    A --> B --> I
输入 输出
ShotSequence FragmentSequence：frag_*、shot_id、element_ids、start_time、duration、description、continuity_notes
配置 默认值 作用
duration_split_threshold 5.5 秒 超过才触发切分，留 0.5 秒容差
max_fragment_duration 5.0 秒 单片段目标上限
min_fragment_duration 1.0 秒 提示词进一步要求不低于 1.5 秒

镜头 ≤5.5 秒直接成段；超过阈值进入 LLM 语义切分，切点取动作完成瞬间、转身前、视线转移时，或对话句号 / 省略号后、情绪转折处。多段时长分配为“建立 30% → 发展 40% → 收束 30%”，并要求台词结束点与片段结束点对齐。规则切分按 num_segments = min(3, int(时长 / 2.5) + 1) 均分，零 Token、确定性输出。

continuity_notes 由分段节点写入：规则路径含 main_character、location（固定为 场景{scene_id}）、main_action、split_type；LLM 路径另含 continuity_id、prev_fragment、split_reason、segment_part、continuity_hints 等字段。

分段完成后会做疑似重复合并与超长重切，结果写入 metadata：dedupe_report.summary 统计候选数、合并数、重切数与截断数，manual_review_required 标记是否有人工复核项；fragment_id_map 记录重编号前后的片段 ID。合并后仍超上限时回退为截断单片段，并把丢弃的尾部画面写入 truncation_report（含 dropped_duration_total 与逐片段的 fragment_id、dropped_duration、truncate_reason），便于下游与人工按片段核对。

失败与降级：LLM 切分抛异常时记录日志并自动降级为规则均分。LLM 模式下 _should_use_llm_split 末尾为无条件 return True，复杂镜头与对话关键词分支实际是死代码；规则均分最多 3 段，超长镜头仍可能超过 5.5 秒；去重合并不可行时会截断尾部画面，需结合 truncation_report 复核。

提示词转换 CONVERT_PROMPT

把片段序列转换为面向视频模型与音频模型的提示词包，并召回可复用的模板；模型适配与路由交给下一节点，转换阶段不改写目标模型。

flowchart LR
    subgraph Input
        A[片段序列]
    end

    subgraph Process[转换流程]
        B[组装上下文<br/>全局元数据/场景/角色JSON/音频语境] --> C[模板召回<br/>RAG 相似度过滤]
        C --> D[注入修复与历史提示<br/>repair_hint / history_hint]
        D --> E[LLM 单次调用<br/>视频 + 音频同批生成]
        E --> F[双语拼装<br/>英文提示词 + 原语言提示词]
        F --> G[构造 AIVideoPrompt<br/>挂载关联音频对象]
    end

    subgraph Output
        H[AI视频指令 JSON]
    end

    A --> B --> H
输入 输出
FragmentSequence、global_metadata、场景与角色信息、修复参数 AIVideoInstructions：fragments[]（prompt、negative_prompt、audio、duration、model、style）、global_settings、execution_suggestions

  • 双语提示词拼为单字段：combined_prompt = f"{english_prompt}\n\n{original_prompt}"，英文在前、原语言在后。

  • 负面提示词取 LLM 返回的 negative_prompt，缺失时用默认值 blurry, distorted, low quality, cartoonish, bad anatomy。

  • 音频与视频同批生成：台词 / 旁白默认 XTTSv2，背景声可用 AudioLDM_3，并以 previous_audio_id 串联音色。

  • 模板召回按相似度阈值、Top-K 与最多注入条数过滤，跨剧本模板只读复用；命中模板作为参考，不直接复制。

  • 片段时长沿用分段结果，转换阶段不重新估算，也不改变片段数量。

  • 视频片段补齐固定 seed：显式 ShotConfig.video_seed 优先，未配置时对剔除 metadata / stats 的解析剧本做 SHA-256 派生，保证同一剧本重复运行得到同一值，并随 AIVideoPrompt.seed 透传到模型适配参数。

失败与降级：转换阶段不做格式强校验，合规性交给下游审计；模板召回失败时退化为无模板生成，不阻断任务。AIAudioPrompt 字段名为 voice_character，但 get_model_specific_config() 引用了不存在的 voice_id，调用该方法会抛 AttributeError。

模型路由 ROUTE_MODEL

在提示词生成之后独立执行“目标模型适配 → 规则路由 → 路由计划落盘”，使提示词重建与路由决策解耦。路由失败不阻断主流程，只记录告警。能力表、特征抽取与兜底策略见模型路由；首帧构建与场景阻断见首帧与图生视频。

flowchart LR
    subgraph Input
        A[AI视频指令]
        B[一致性契约 + 资产计划/清单]
    end

    subgraph Process[路由流程]
        C[能力适配<br/>时长/镜头/模式] --> D[图生视频优先<br/>挂载资产引用与首帧指令]
        D --> E[规则匹配<br/>priority 从高到低]
        E --> F[回填资产 usage<br/>重写 asset_plan.json]
        F --> G[Gate 1 检查<br/>阻断不可用片段]
    end

    subgraph Output
        H[RoutePlan + AdaptedPromptPackage]
    end

    A --> C
    B --> D
    G --> H
优先级 规则 条件 目标模型 模式
100 critical_text has_critical_text kling_3 image_to_video
90 high_consistency character_consistency_need=high kling_3 image_to_video
80 complex_motion motion_complexity=high sora_2 text_to_video
70 anime_style style_bias=anime kling_3 text_to_video
60 cinematic_long_take style_bias=cinematic 且 min_duration=8.0 runway_gen4 text_to_video

所有规则都不命中时使用 routing.default_model（默认 kling_3）；未注册的模型会被跳过。目标模型超出片段时长时，按“时长上限 ≥ 片段时长且一致性最高”回退。能力注册表当前收录 runway_gen4、kling_3、luma_dream、sora_2、pika_2，记录最大时长、是否支持图生视频、镜头控制、一致性与风格倾向。

输入 输出
AIVideoInstructions、GlobalConsistencyContract、asset_plan、asset_manifest RoutePlan：source_model、decisions[]、adapted_packages[]、warnings、blocked_fragments

  • 图生视频优先：能从资产清单解析到首帧引用的片段，先挂载 asset_ref、image_prompt 与首帧指令，再由规则覆盖目标模型与模式。

  • 适配包保留原提示词、负向词、时长、风格与镜头控制，并追加目标模型参数；OVERRIDABLE_FIELDS 允许覆盖提示词与参数，但资产身份字段不可覆盖。

  • 路由后回填资产 usage，重写 asset_plan.json 与 prompt_converter_result.json，保证两份计划的使用范围一致。

  • Gate 1 检查把结构/逻辑问题写入 plan.warnings；场景锚定无法唯一匹配、状态为 needs_manual_fix 的片段进入 blocked_fragments，不进入下游渲染队列。

  • 服装关键信息不足的角色资产，引用片段自动追加剪影/背影降级约束，并记录 degraded_assets。

失败与降级：路由异常时 route_plan 置空，决策层记录告警并继续审计；能力注册表为静态数据，新模型需要扩展注册表后重新部署。

质量审计 AUDIT_QUALITY

对提示词包做最后一道程序化检查：11 项硬规则、按严重度判定状态并按检查通过率评分，再合并 LLM 深度审查，输出放行、修复或人工三种走向。规则版实现为 RuleQualityAuditor。

flowchart TD
    A[AI指令序列 + 路由结果] --> B[逐项执行 11 项检查]
    B --> C[违规项记入 violations<br/>按严重度判定状态]
    C --> D[合并 LLM 审查报告]
    D --> E{严重度规则}
    E -->|有 ERROR| F[FAILED]
    E -->|有 CRITICAL| G[CRITICAL_ISSUES 重试/人工]
    E -->|≥2 MAJOR 或 MAJOR+2 MODERATE| H[MAJOR_ISSUES 修复]
    E -->|有 MODERATE| I[MODERATE_ISSUES 修复]
    E -->|有 WARNING 或通过率<90%| J[MINOR_ISSUES]
    E -->|全清| K[PASSED 放行]
输入 输出
AIVideoInstructions、route_plan、资产计划 QualityAuditReport：status、checks[]、violations[]、stats（pass_rate、failed_check_names）、score / detection_score、post_repair_score、conclusion、suggestions
检查项 判定条件 严重度
片段时长（上限） 时长 > 5.5 秒 ERROR
片段时长（下限） 时长 < 1.0 秒 WARNING
提示词内容 提示词为空 ERROR（PROMPT_EMPTY）
提示词长度 超出 max_prompt_length 或低于 min_prompt_length WARNING
片段数量 无任何片段 ERROR（FRAGMENT_MISSING）
模型支持 模型名经能力注册表 parse_model_name / get_capability 无法识别 WARNING（kling_3、runway_gen4 等已注册模型不再误判）
外观锚点污染 提示词写入资产锚点外的外观描述，或锚点缺失 MAJOR（带 asset_id）
契约违规 角色、场景或道具违反一致性契约 MAJOR
景别一致性 提示词景别与镜头 shot_type 不符 WARNING
镜头运动一致性 提示词镜头运动与控制字段不符 WARNING
风格光照冲突 风格与光照描述互相冲突 WARNING
资产使用 片段使用了计划外资产，或必需资产缺失 MAJOR（带 fragment_id / asset_id）

状态由严重度规则判定，优先级从上到下：有 ERROR → FAILED；有 CRITICAL → CRITICAL_ISSUES；≥2 个 MAJOR 或 MAJOR+2 个 MODERATE → MAJOR_ISSUES；有 MODERATE → MODERATE_ISSUES；有 WARNING 或检查通过率 <90% → MINOR_ISSUES；全清 → PASSED。

评分为“检查通过率减去违规扣分”：以 passed_checks / total_checks 为基础分（0–1），按 INFO 1%、WARNING 5%、MODERATE 15%、MAJOR 30%、CRITICAL 50%、ERROR 100% 逐项扣减并按数量封顶（INFO/WARNING 最多 5 条，其他最多 3 条），下限 0；乘 100 后写入 score 与 detection_score。结论文本会同时列出警告数与未通过检查名（failed_check_names），避免出现“0 个警告问题”却未通过的矛盾描述。

决策映射：PASSED → SUCCESS；MINOR_ISSUES 违规 ≤3 个 → VALID，超过则修复；MODERATE_ISSUES / MAJOR_ISSUES → 回 CONVERT_PROMPT；CRITICAL_ISSUES 重试或转人工；FAILED 但分数 ≥80 仍按 VALID 放行，≥60 且可重试则重试。若中度问题全部落在 requires_manual_fix（无自动策略），记录告警并继续执行，不再反复修复直至循环超限。

报告中的违规项按 PipelineNode 转成修复参数，写入 state.domain.repair_params；下一轮 CONVERT_PROMPT 只读取属于自己的键，应用成功后可调用 clear_repair_params() 清理。修复后 repair_issue_count 与 repair_action_count 分列，repair_status 取 repaired / partial / manual_required / no_action_taken；只有真正执行的修复动作才通过规则复检更新 post_repair_score，否则保持等于 detection_score。LLM 深度审查失败时不阻断规则审查结论。

失败与降级：5.5 秒同时作为分段触发阈值与审查红线，分段漏切会在此处直接报 ERROR；规则检查只覆盖可程序化判定的是非问题，合规但平庸的提示词仍可通过。模型支持检查走能力注册表，kling_3、runway_gen4 等已注册模型不再被误判。规则版审查不调用模型，LLM 不可用时仍能给出时长、空值与结构结论。

连续性守护 CONTINUITY_CHECK

跨阶段检查角色、场景、动作、风格、时间、道具六类问题，并在其上叠加契约级检查。基础实现为关键词与数值规则（ContinuityGuardianChecker），主链入口 check_with_contract 再追加结构化锚点、长剧本跨块校验与风格漂移检测，不是 LLM 语义审查；检查结果会驱动上游修复。

flowchart LR
    subgraph Input
        A[解析/拆分/分段/指令<br/>各阶段产物 + 契约]
    end

    subgraph Process[六项基础检查]
        B[角色连续性<br/>出现对照+外观/配色] --> C[场景连续性<br/>跳转占比]
        C --> D[动作连续性<br/>相邻同角色动作]
        D --> E[风格连续性<br/>风格种类数]
        E --> F[时间连续性<br/>起止时间差]
        F --> G[道具连续性<br/>持有/释放]
    end

    subgraph Contract[契约级叠加]
        K[角色缺席 / 场景角色] --> L[结构化锚点]
        L --> M[跨块校验]
        M --> N[风格漂移检测]
    end

    subgraph Dedup[后处理]
        H[签名去重] --> I[描述截断 500 字符]
    end

    subgraph Output
        J[问题列表<br/>含严重度+来源阶段+可修复标记]
        O[状态快照<br/>snapshot_id / fragment_count]
    end

    A --> B --> K
    N --> H --> J
    A --> O
输入 输出
parsed_script、shot_sequence、fragment_sequence、instructions（有则查，无则跳过） ContinuityCheckResult：问题类型、严重度、fragment_id、source_stage、auto_fixable、suggestion
检查 判定方式 触发与严重度
角色 角色出现在场对照（含画外音/仅声音角色按台词元素归属）；服装词与配色变化 有对话无镜头→CHARACTER_MISSING（MAJOR）；外观/配色变化→CHARACTER_APPEARANCE_CHANGE / COLOR_INCONSISTENT（WARNING）
场景 相邻镜头 scene_id 变化，统计跳变占比；过渡镜头、同景别切点与已尝试修复的固有切换不重复上报 单次跳变→SCENE_JUMP（WARNING）；占比 >30%→SCENE_TOO_FREQUENT（MODERATE）
动作 动作词表（走/跑/跳/转身/坐下/站起/拿起/放下）按角色追踪，仅比较相邻且同一主角镜头 同角色相邻动作词变化→ACTION_BREAK（MODERATE，无自动修复）
风格 AIVideoPrompt.style 去重种类数 种类数 >2→STYLE_INCONSISTENT（MODERATE）
时间 片段 start_time 与前段“起始 + 时长”的差值 正差 >0.1 秒→TIME_GAP（MAJOR）；负差→TIME_OVERLAP（ERROR）
道具 按元素追踪持有状态；放下/交给/撞倒/脱下后清空；台词提到的道具视为话题不计持有 持有道具变化→PROP_CHANGE（WARNING，无自动修复）

六项基础检查之上，check_with_contract 叠加契约级校验：角色长期缺席（结构性，不可自动修复）、场景角色一致性（契约 characters_in_scene 对比镜头实际角色）、build_anchors_from_contract 生成的角色外观 / 场景 / 风格 ContinuityAnchor 比对，以及 CrossChunkValidator 的长剧本块间过渡检查。工作流随后调用 PromptStyleGuardian.detect_style_drift：关键词重叠度 <0.3 判风格漂移（MODERATE）、<0.6 告警（WARNING）。

每轮检查前执行 take_snapshot，快照记录角色外观与当前片段进度，并通过 check_result.metadata.snapshot 回写 snapshot_id、时间戳与累计快照数；StateTimeline.get_snapshot_at_time 返回时间最近的快照，get_latest_snapshot 取最新。快照用于观测与回溯，不驱动状态回滚。

通过判定：任一 CRITICAL，或 MAJOR 超过 3 个，即 passed=False；其余级别不改变结论。问题签名由“类型 + 片段 + 场景 + 严重度 + 位置 + 描述前 100 字”组成，同一位置同类问题只报一次；描述超过 500 字符截断。

修复回流：节点把可修复问题写入 domain.repair_params，并设置 needs_continuity_repair 与来源阶段；决策函数据此返回阶段节点名，路由回解析、拆分、切割或转换。修复最多 3 轮（max_continuity_retries），轮次耗尽或存在未定位来源的问题时转人工。

失败与降级：词表法会把“拿手机→握手机”判为道具变化，“转头”不在动作词表；上下文缺失时对应检查直接跳过。检查只做词表与数值判断，不理解语义，因此适合发现显性漂移，无法判断隐喻或叙事层面的连贯性。

限制按节点归集，跨节点的路由与计数问题见技术架构的“当前限制”。

节点级限制

节点 限制 影响
PARSE_SCRIPT 只校验 sequence 连续性，无原文偏移回溯 顺序正确性依赖 LLM
GENERATE_ASSETS 默认只声明计划，真实出图默认关闭 资产 asset_ref 需下游回填
SEGMENT_SHOT 时长估算基于关键词与固定系数 语义微妙的描述误差较大
SPLIT_VIDEO 规则均分最多 3 段；LLM 失败即降级 超长镜头可能仍超 5.5 秒
CONVERT_PROMPT 音频模型的 voice_id 字段引用不存在 调用音频模型配置方法会抛异常
ROUTE_MODEL 能力注册表为静态数据；路由失败不阻断 新模型需改代码；失败时无路由结果
CONTINUITY_CHECK 词表与数值规则，语义判断有限 隐性漂移可能漏检
