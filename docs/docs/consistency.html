核心设计

一致性策略

三层记忆、快照与连续性检查，如何压制跨片段的角色与场景漂移。

更新 2026-10-31 约 14 分钟阅读 在 GitHub 编辑

PenShot 的一致性依赖五条已接线的通道：全局元数据传递、连续性注释、提示词约束、规则检查与检索增强；快照回滚、修复参数回流与固定种子尚未接通。

这些通道都在主链内部完成，不额外引入生成模型：元数据与注释是文本透传，规则检查是确定性判定，检索只读取已有向量库。因此一致性保障的边际成本主要是提示词长度，而不是额外推理调用。

策略构成

通道 实现位置 作用
全局元数据 PARSE_SCRIPT → CONVERT_PROMPT 跨场景传递道具、服装、地点、声音
连续性注释 SPLIT_VIDEO 写入 continuity_notes 记录片段的主角、地点、动作与切分原因
提示词约束 CONVERT_PROMPT _format_global_context 把元数据与注释拼入每个片段的提示词
规则检查 AUDIT_QUALITY、CONTINUITY_CHECK 程序化发现时长、角色、场景等违规
检索增强 KnowledgeManager 两个知识库 复用成功模板与历史解决方案
种子建议 execution_suggestions 提示执行层固定随机种子

    subgraph Parse[剧本解析节点]
        P1[提取 global_metadata<br/>character_outfits / key_props / key_locations]
        P2[角色与场景清单] 
        P3[检索剧本知识库<br/>ScriptKnowledgeBase]
    end

    subgraph Segment[分镜生成节点]
        S1[镜头序列与 main_character]
        S2[分镜提示词模板<br/>shot 格式全局上下文]
    end

    subgraph Split[视频分段节点]
        F1[写入 continuity_notes<br/>main_character / location / main_action / split_type]
        F2[时长控制与降级切分]
    end

    subgraph Convert[指令转换节点]
        C1[拼装全剧上下文<br/>_format_global_context]
        C2[消费修复参数<br/>apply_repair_params]
        C3[检索成功提示词模板<br/>PromptTemplateKB]
        C4[生成双语提示词]
    end

    subgraph Audit[质量审查节点]
        A1[五项规则检查]
        A2[加权评分与状态决策]
        A3[生成修复参数]
    end

    subgraph Continuity[连续性守护节点]
        G1[六项词表规则检查]
        G2[签名去重与问题分级]
        G3[生成修复参数并路由<br/>回流未接通]
        G4[检索历史解决方案<br/>search_similar_scene]
    end

    Parse --> Segment --> Split --> Convert --> Audit --> Continuity

全局元数据与连续性锚点

解析节点从全剧提取 global_metadata，它是跨场景一致性的事实来源；下游只读不改。

字段 内容 消费方
key_props 关键道具及 appears_in 场景列表、重要度 提示词“本场景关键道具”
character_outfits 角色在各场景的服装、发型、配饰 提示词“角色服装要求”
key_locations 地点名称、appears_in、视觉特征 提示词“本场景地点”
continuity_notes 全剧级连续性提醒 提示词“连续性要求”
audio_atmosphere 整体音频氛围 音频提示词
recurring_sounds 反复出现的环境声、音效 音频提示词 
flowchart LR
    subgraph Parse[剧本解析]
        A[global_metadata<br/>key_props / character_outfits<br/>key_locations]
    end

    subgraph Segment[分镜生成]
        B[ShotInfo.main_character]
    end

    subgraph Split[视频分段]
        C[VideoFragment.continuity_notes<br/>main_character / location<br/>main_action / split_type]
    end

    subgraph Convert[指令转换]
        D[_format_global_context<br/>拼装全剧上下文]
        E[提示词模板引用<br/>角色服装/道具/地点]
    end

    A --> D
    B --> C
    A --> C
    C --> E

片段级注释由分段节点生成，规则路径与 LLM 路径字段不同：

路径 字段
规则切分 main_character、location（固定为 场景{scene_id}）、main_action、split_type
LLM 切分 另含 continuity_id、prev_fragment、split_reason、segment_part、continuity_hints

代码中存在结构化锚点模型 ContinuityAnchor（anchor_id、anchor_type、name、value、start_time、end_time、fragment_range、priority、metadata，并提供 is_active_at()），但没有任何节点或检查器引用它。当前实际生效的“锚点”是上述两段文本通道，不是可查询的时间区间对象。

提示词约束

转换节点在每个片段提示词中注入四段上下文，来源均为 global_metadata 与片段的 continuity_notes。

flowchart LR
    subgraph Source[数据来源]
        A[ParsedScript.global_metadata<br/>key_props / character_outfits<br/>key_locations / continuity_notes]
    end

    subgraph Format[运行时格式化]
        B[_format_global_context<br/>按场景过滤]
        C[【本场景关键道具】<br/>无命中降级为全量]
        D[【角色服装要求】<br/>全量输出]
        E[【本场景地点】<br/>无命中降级为全量]
        F[【特别注意，连续性要求】]
    end

    subgraph Inject[模板注入]
        G[提示词模板<br/>【全剧上下文】区块]
        H[【重要约束】生成指令<br/>与全局上下文保持一致]
    end

    A --> B
    B --> C & D & E & F
    C & D & E & F --> G --> H
段落 生成规则
【本场景关键道具】 按 appears_in 过滤当前场景；无命中时退回全量道具，重要道具加标记
【角色服装要求】 全量输出角色服装，不按场景裁剪
【本场景地点】 按 appears_in 过滤；无命中时退回全量地点
【特别注意，连续性要求】 原样拼接片段 continuity_notes，不做语义改写

四段内容装入模板的【全剧上下文】区块，并在生成指令中追加【重要约束】：人物外观、道具、场景与上下文保持一致。冲突时以上下文为准，而非模型自由发挥。提示词中另有 _format_global_metadata 的 prompt / split / shot 三种变体，分别用于转换、分段与分镜阶段，并按场景裁剪以控制长度。

场景过滤的依据是 appears_in；该字段缺失或没有命中时，段落退回全量列表，宁可多给上下文也不省略约束。服装段落不做场景裁剪，因为同一角色在不同场景的换装信息需要同时可见。

六项规则检查

连续性守护节点以关键词和数值规则检查六个维度，不调用 LLM。

flowchart LR
    subgraph Check[六项检查（关键词/数值规则）]
        V1[角色：出现在场对照<br/>外观三类词表]
        V2[场景：相邻 scene_id 跳变<br/>跳变占比阈值]
        V3[动作：动作词表按镜头描述追踪]
        V4[风格：style 去重种类数]
        V5[时间：起止时间差]
        V6[道具：道具动词表]
    end

    subgraph After[后处理]
        R1[签名去重] --> R2[通过判定<br/>critical>0 或 major>3] --> R3[分级与修复建议]
    end

    Check --> After
维度 判定 违规类型
角色 有对话的角色是否出现在镜头；服装 / 发型 / 配饰词表 CHARACTER_MISSING（MAJOR）、外观变化（WARNING）
场景 相邻镜头 scene_id 跳变及占比 SCENE_JUMP（WARNING）、SCENE_TOO_FREQUENT（>30%，MODERATE）
动作 走/跑/跳/转身/坐下/站起/拿起/放下 按角色追踪 ACTION_BREAK（MODERATE）
风格 AIVideoPrompt.style 去重种类数 种类 >2 → STYLE_INCONSISTENT（MODERATE）
时间 片段起点与前段“起点 + 时长”的差值 正差 >0.1 秒 → TIME_GAP（MAJOR）；负差 → TIME_OVERLAP（ERROR）
道具 拿/举/抱/提/端/持/握 按角色统计 PROP_CHANGE（WARNING）

通过条件为 critical_count == 0 且 major_count ≤ 3；任一 CRITICAL 或 MAJOR 超过 3 个即不通过，其余级别只记录。问题签名由类型、片段、场景、严重度、位置与描述前 100 字组成，同一位置同类问题只报一次；描述超过 500 字符截断。每条问题带 source_stage、auto_fixable 与 suggestion，供后续修复使用。

误报边界：词表法会把“拿手机→握手机”判为道具变化，“转头”不在动作词表；缺少分镜或片段时对应检查直接跳过。

RAG 检索

KnowledgeManager 维护两个知识库，均按 script_id 隔离，不跨剧本复用。

flowchart LR
    subgraph KM[KnowledgeManager 内部]
        A[PromptTemplateKB<br/>成功提示词模板] 
        B[ScriptKnowledgeBase<br/>剧本级知识检索]
    end

    subgraph Store[存储机制]
        C[SentenceSplitter<br/>chunk 512 / overlap 20]
        D[SimpleVectorStore<br/>prompt_vector_store.json]
        E[data/embedding/prompt_templates/<br/>按 script_id 隔离]
    end

    subgraph Query[检索入口]
        F[search_similar_prompts<br/>top_k=3，min_score=0.6]
        G[query 手动余弦检索<br/>search_similar_scene 等入口]
        H[query_character / query_scene<br/>解析结果字典直查]
    end

    A --> C --> D --> E
    B --> G
    F & G & H --> I[检索结果注入生成或问题增强]
知识库 存储与检索
PromptTemplateKB LlamaIndex + SimpleVectorStore；SentenceSplitter(chunk_size=512, chunk_overlap=20)；落盘 data/embedding/prompt_templates/{script_id}/prompt_vector_store.json；search_similar(top_k=3, min_score=0.6)，get_best_match(min_score=0.7)
ScriptKnowledgeBase 手动余弦扫描；query_character / query_scene 走解析结果字典直查；use_rerank 参数被接收但未使用

检索结果用于三处：生成阶段参考历史成功模板（Document 元数据含 type、fragment_id、scene、style、quality_score）；连续性问题补充 historical_solutions（top_k=2）；为剧本背景与角色设定提供事实。向量库为空或检索异常时返回空列表，不阻断主流程。

BAAI/bge-reranker-large 只出现在 create_retriever_for_script 中，调用它的 KnowledgeRouter 尚未接线，因此实际检索没有重排阶段。

工作流在调用剧本知识库前会先判断 is_script_kb_available()；索引未初始化、依赖缺失或检索异常时均返回空结果，不抛错、不阻断生成。检索是增强项，不是主链的前置条件。

种子建议

global_settings 只包含 style_consistency: True 与 use_common_negative_prompt: True，没有种子字段。execution_suggestions 输出三条执行建议：按顺序生成片段、保持相同种子值以获得一致性、生成后检查片段衔接。种子需要执行层在调用视频模型时自行注入；PenShot 侧若要支持固定种子，需新增字段并透传到 AIVideoPrompt，当前未实现。

建议文案不进入模型请求，也不会被校验。执行层若固定种子，应在同一任务内复用同一值，并自行记录以便复现；跨任务沿用同一值只会重现画面风格，不能保证内容正确。

一致性工作流

主链在转换后先过质量审查，再过连续性守护；审查的修复路由已接通，守护的修复路由未接通。

flowchart TB
    subgraph Real[真实主链（已接线）]
        Start([输入原始剧本]) --> Parse[剧本解析<br/>提取 global_metadata]
        Parse --> Segment[分镜生成]
        Segment --> Split[视频分段<br/>写入 continuity_notes]
        Split --> Convert[指令转换<br/>全剧上下文 + 模板参考]
        Convert --> Audit[质量审查<br/>五项检查→加权评分→修复参数]
        Audit -->|通过| Continuity[连续性守护<br/>六项词表检查→修复参数]
        Audit -.->|NEEDS_REPAIR：已接通| Convert
        Continuity -.->|四阶段修复路由：未接通| Parse
        Continuity --> FinalOutput[最终输出<br/>AIVideoInstructions]
    end

审查扣分从 100 起算，warning 5、moderate 10、major 25、critical 40、error 60；≥90 PASSED、≥75 MINOR_ISSUES、≥60 MODERATE_ISSUES、≥40 MAJOR_ISSUES、≥20 CRITICAL_ISSUES，否则 FAILED。PASSED 直接放行，MINOR 违规不超过 3 个也放行；MODERATE / MAJOR 带修复参数回到 CONVERT_PROMPT；CRITICAL 重试或转人工。

审查的 NEEDS_RETRY 与 NEEDS_REPAIR 都回到 CONVERT_PROMPT，因为审查本身不产生内容，重跑审查无法改变结果。连续性守护的修复目标虽配置为 CONVERT_PROMPT，但决策恒为 SUCCESS，实际只记录问题，不会触发回炉。

当前限制

限制 现状与影响
快照未接入 take_snapshot 无调用方；get_snapshot_at_time(t) 取第一个不早于 t 的快照，而非时间最近者
连续性修复回流未接通 决策读取顶层 state.continuity_issues，实际字段在 state.domain，恒判 SUCCESS；NEEDS_RETRY 也不在条件边映射中
无固定种子 只在 execution_suggestions 中给出文字建议，代码与数据结构均无 seed
结构化锚点未启用 ContinuityAnchor、GlobalConsistencyContract、process_with_contract、check_with_contract、CrossChunkValidator 均无调用方
关键词误报 近义动作、道具动词变化会被判为不一致，需要人工忽略
风格守护未实例化 PromptStyleGuardian 未创建，initialize_style() 调用的 search_similar_style 不存在
知识库按剧本隔离 同一 script_id 之外无法复用成功模板与历史方案

节点级输入输出与失败降级见工作流节点；全局编排与路由见技术架构；知识库构建细节见RAG 知识库。
