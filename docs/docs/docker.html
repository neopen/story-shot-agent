开始使用

Docker 部署

官方镜像与 Compose 启动 REST 服务，含 Redis、持久化与健康检查。

更新 2026-11-14 约 10 分钟阅读

PenShot 提供官方容器镜像，把 REST 服务、任务池与工作流打包为单一进程。镜像默认监听 8000 端口，内置健康检查；需要跨进程共享任务与短期记忆时，再接入 Redis。

镜像与容器

项说明
镜像neotems/penshot:latest（Docker Hub）；ghcr.io/neopen/penshot:latest（GHCR 镜像）
基础镜像python:3.11-slim，非 root 用户 appuser（uid 1000）
端口8000，容器内固定监听 0.0.0.0
入口python -m scripts.entrypoint start，转交 main.py 启动
健康检查curl -f http://localhost:8000/health，间隔 30 秒
标签latest 跟随 main；正式版本使用语义化版本标签

两个仓库发布同一镜像。生产环境应固定版本标签，避免 latest 随 main 漂移。容器内只运行 REST 服务，不含反向代理、TLS 与鉴权；对外暴露前应放在网关之后，MCP 协议客户端也不能直连 8000。

快速启动

先准备 .env，至少包含对话模型；使用记忆或语义检索时再补嵌入模型：

PENSHOT_LLM__DEFAULT__BASE_URL=https://api.deepseek.com
PENSHOT_LLM__DEFAULT__API_KEY=sk-xxxxxxxx
PENSHOT_LLM__DEFAULT__MODEL_NAME=deepseek-chat

PENSHOT_EMBED__DEFAULT__BASE_URL=https://dashscope-intl.aliyuncs.com/api/v1
PENSHOT_EMBED__DEFAULT__API_KEY=sk-xxxxxxxx
PENSHOT_EMBED__DEFAULT__MODEL_NAME=text-embedding-v4

docker pull neotems/penshot:latest

docker run -d --name penshot \
  -p 8000:8000 \
  --env-file .env \
  --restart unless-stopped \
  neotems/penshot:latest

curl http://localhost:8000/health

健康检查返回 {"status":"healthy"} 只表示进程就绪，不代表模型密钥可用。模型配置错误时容器仍会启动，失败发生在任务执行阶段，错误写入日志。首次部署建议提交一个短剧本，验证从提交到结果的完整链路。

直接传环境变量

不想维护 .env 时，可以在 docker run 中用 -e 逐个注入配置。PowerShell 使用反引号换行：

docker run -d `
  --name penshot `
  -p 8000:8000 `
  -e PENSHOT_LLM__DEFAULT__BASE_URL="https://api.deepseek.com" `
  -e PENSHOT_LLM__DEFAULT__API_KEY="sk-xxxxxxxxxxxxxx" `
  -e PENSHOT_LLM__DEFAULT__MODEL_NAME="deepseek-v4-flash" `
  -e PENSHOT_EMBED__DEFAULT__BASE_URL="https://dashscope-intl.aliyuncs.com/api/v1" `
  -e PENSHOT_EMBED__DEFAULT__API_KEY="sk-xxxxxxxxxxxxxx" `
  -e PENSHOT_EMBED__DEFAULT__MODEL_NAME="text-embedding-v4" `
  -e PENSHOT_REDIS_URL="redis://:123456@host.docker.internal:6379/0?protocol=2" `
  neotems/penshot:latest

Linux / macOS 将行尾反引号换成 \。PENSHOT_REDIS_URL 可以省略：没有外部 Redis 时，单容器使用进程内任务池与记忆；使用外部 Redis 时，无密码写成 redis://host:6379/0，有密码写成 redis://:PASSWORD@host:6379/0，密码不要放在用户名位置。host.docker.internal 适用于 Docker Desktop，Linux 需加 --add-host=host.docker.internal:host-gateway，或改用容器网络中的服务名。

直接写在命令里的密钥会进入 shell 历史，也能通过 docker inspect 读取；长期运行仍建议使用 --env-file 或容器平台的 Secret 管理。

Docker Compose

仓库自带的 Compose 从本地源码构建镜像，并启动一个 Redis 7 实例：

git clone https://github.com/neopen/story-shot-agent.git
cd story-shot-agent
cp .env.example .env
# 编辑 .env，填入 LLM 与嵌入模型配置

docker compose up -d --build
docker compose ps
docker compose logs -f story-shot-agent

应用会等待 Redis 健康后启动。Redis 默认密码为 123456，docker-compose.yml 中的 --requirepass 与应用的 PENSHOT_REDIS_PASSWORD 必须同步修改；数据写入 redis_data 卷。应用侧限制 2 CPU / 2 GB，日志按 10 MB × 3 轮转。停止用 docker compose down，追加 -v 会连同 Redis 数据一起删除。

Compose 中的 image: penshot:latest 配合 build: . 表示本地构建，不会拉取官方镜像。只想使用发布镜像时，改用上面的 docker run，或删除 build 并把 image 改为 neotems/penshot:latest。

部署拓扑

flowchart LR
    C["调用方 / 前端"] -->|"HTTP :8000"| A["penshot 容器<br/>FastAPI /api/v1"]
    A --> T["TaskFactory 任务池"]
    T --> W["工作流编排"]
    W --> L["LLM / Embedding API"]
    A -.->|"任务与会话共享"| R[("Redis 7")]
    A -.->|"/app/data"| D[("检查点 / 本地记忆")]
    M["docker compose"] -.-> A
    M -.-> R

单容器即单进程：任务池、并发计数与 split_cache 都在容器内。多副本部署时各副本独立，必须共享 Redis 才能共享任务状态与短期记忆。检查点当前只写不读（见检查点与恢复），把检查点目录放到共享存储也不会带来跨副本续跑能力。

数据与持久化

镜像工作目录为 /app。解析结果、模板缓存、SQLite 检查点与本地记忆默认写在 /app/data；Compose 没有挂载该目录，容器重建后这些数据会丢失，只有 Redis 卷保留。需要保留时挂载数据目录：

mkdir -p data

docker run -d --name penshot \
  -p 8000:8000 \
  --env-file .env \
  -v "$PWD/data:/app/data" \
  neotems/penshot:latest

容器以 uid 1000 运行，Linux 上需保证挂载目录可写：sudo chown -R 1000:1000 data。Docker Desktop 的绑定挂载通常无需额外处理。Redis 使用独立的 redis_data 卷，其余缓存不持久化，重建容器后重新生成。

以上路径对应默认的 development 配置。环境配置文件由 ENVIRONMENT 变量选择（默认 development，可选 production），不是 PENSHOT_APP__ENVIRONMENT。切到 production 后，输入、输出、缓存与模型目录改用 /data/script-to-shot，日志写到 /var/log/script-to-shot，临时文件写到 /tmp/script-to-shot；嵌入索引、模板缓存、记忆与检查点仍取 ./data/...，落在 /app/data 下。两类目录都要挂载，否则容器重建后数据丢失。

启动与健康检查

flowchart TD
    A["docker run / compose up"] --> B["scripts.entrypoint start"]
    B --> C["读取 PENSHOT_API__HOST / PORT<br/>默认 0.0.0.0:8000"]
    C --> D["启动 FastAPI 与任务池"]
    D --> E{"/health 返回 200?"}
    E -->|"是"| F["容器 healthy"]
    E -->|"否"| G["查看 docker logs<br/>检查 .env、端口与依赖"]

docker ps --filter name=penshot
docker logs -f penshot
docker inspect --format '{{.State.Health.Status}}' penshot

/health 与 /api/v1/health 都可用，容器健康检查使用前者。健康状态只覆盖进程与 HTTP 监听，不校验 LLM、嵌入模型或 Redis 是否可用。

更新与扩容

更新镜像后重建容器，数据卷保持不变：

docker pull neotems/penshot:latest
docker rm -f penshot

docker run -d --name penshot \
  -p 8000:8000 \
  --env-file .env \
  -v "$PWD/data:/app/data" \
  neotems/penshot:latest

Compose 场景执行 git pull && docker compose up -d --build。横向扩容时，每个副本都要连接同一 Redis，否则任务与短期记忆互不可见。检查点只有 memory 与 sqlite 两种模式，没有 PostgreSQL 后端；把 checkpoint_mode 指向共享 SQLite 路径也不能承担多副本并发写与断点续跑，因为执行时 thread_id 不稳定且没有读取入口。容器内的任务队列不会跨副本调度，任务失败后仍会从头执行。

常见问题

现象原因与处理
容器启动后立即退出.env 路径错误或必填变量缺失；查看 docker logs penshot，核对 --env-file 与键名
状态一直 unhealthy应用启动失败或 8000 被占用；查看日志，确认容器内端口未被覆盖
LLM 返回 401 / 403BASE_URL、API_KEY、MODEL_NAME 不属于同一供应商，三者一起核对
Redis 连接失败容器内的 localhost 指向容器自身；Compose 用服务名 redis，宿主机用 host.docker.internal，Linux 需加 --add-host=host.docker.internal:host-gateway
/app/data 写入失败挂载目录对 uid 1000 不可写；chown 后重启容器
MCP 客户端连不上8000 提供 REST，不是 MCP 传输；覆盖入口运行 stdio：docker run --rm -i --env-file .env --entrypoint python neotems/penshot:latest -m penshot.mcp_server

部署边界

边界说明
单进程任务池多副本需共享 Redis；检查点仅写不读，不能用于续跑，split_cache 不跨副本
无鉴权与 TLS只适合内网或网关之后，不要直接暴露公网
数据默认不持久化挂载 /app/data，否则容器重建即丢失
健康检查不校验模型/health 通过不代表 API Key 或嵌入模型可用

镜像与 Compose 的当前定义以仓库 Dockerfile、docker-compose.yml 为准；环境变量与调用参数见快速开始与集成指南。
