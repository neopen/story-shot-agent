# PenShot 开源发展路线报告 (2024-2025)
**项目定位**：面向 AIGC 时代的工业级剧本分镜与提示词生成引擎
**报告目的**：明确 PenShot 从“文本解析工具”向“短剧/AI视频核心解析中枢”的演进路径，打通从剧本创意到视频模型可用 Prompt 的全链路，支撑 HelpEnX Studio 及更广泛的开源生态。

---

## 一、 核心愿景与架构定位

在 HelpEnX Studio 的版图中，PenShot 是整个生成流水线的**“大脑与翻译官”**。
未来的 PenShot 不能仅仅是一个“把文字转成 Prompt 的 API”，而必须具备**“视听语言结构化”**与**“跨镜头一致性守护”**的能力。

**演进原则**：
1. **数据总线契约**：持续优化输出的 `fragment JSON` 结构，使其成为上下游（PenGen, PenClip 等）唯一信任的标准化契约。
2. **视觉化思考**：不仅解析文本，更要精准翻译“景别、机位、运镜、光影、情绪”，让 AI 视频模型真正“听懂”导演的意图。
3. **局部敏捷**：支持极小粒度的修改与重解析，为对话式交互和 Agent 协作提供底层支撑。

---

## 二、 阶段发展路线图 (Roadmap)

### 阶段一：夯实解析底座 (V1.0 - V1.5) —— *当前重点*
**目标**：强化对短剧、小说等长篇文本的结构化解析，完善输出契约，提升提示词的模型适配度。

*   **[P0] 结构化输出契约升级**
    *   **痛点**：下游 TTS（如 PenDub）和视频生成（PenGen）需要更明确的数据字段。
    *   **功能**：在 `fragment` 中剥离出独立的 `dialogue` 数组，明确绑定 `{character_id, text, emotion}`，方便下游精准分角色配音；增加 `shot_metadata` 字段（机位、景别、运镜等）。
*   **[P0] 分镜粒度控制 (Shot Density Control)**
    *   **痛点**：电影长片与短剧的镜头节奏完全不同（短剧通常 2-3 秒一个反转）。
    *   **功能**：开放 `shot_density` 参数（如 `fast`, `normal`, `cinematic`），允许上游系统（如 NeoTask）根据不同业务场景，强制调整分镜切分的细碎程度。
*   **[P1] 提示词模板热插拔**
    *   **功能**：内置针对 Sora/Veo/可灵/Vidu 等主流模型的 Prompt 优化模板，支持通过配置文件动态加载新模型模板，无需修改代码即可适配新模型。

### 阶段二：深度一致性守护 (V2.0 - V2.5) —— *短剧场景的生死线*
**目标**：解决跨镜头的视觉与叙事连贯性问题，让生成的片段能真正拼成一部戏。

*   **[P0] 多级记忆与视觉锚点生成**
    *   **功能**：在原有的 RAG 文本记忆基础上，增加**“角色/场景视觉指纹”**输出。PenShot 自动为频繁出场的角色输出一段固定的 `character_prompt_block`（特征描述块），并结合首帧图生成接口，确保不同镜头里的角色长相稳定。
*   **[P0] 智能长镜头拆分与动作连贯**
    *   **功能**：对于复杂的连续动作，自动拆解为“起始帧-发展帧-结束帧”的连贯 Prompt，确保分镜之间（Fragment A 与 Fragment B）的物理逻辑不断裂（如角色服装未变、道具位置连贯）。
*   **[P1] 情感与节奏推演**
    *   **功能**：接入剧本情感分析，自动调整 `fragment.duration` 的时长估算，在情绪激烈的冲突戏自动增加镜头切换频率，在抒情戏拉长镜头。

### 阶段三：Agent 协作与生态扩展 (V3.0) —— *面向未来的 AI 导演*
**目标**：从被动解析工具进化为具备导演思维、可随时与人类对话的智能 Agent。

*   **[P0] 局部重解析 (Targeted Re-parsing)**
    *   **功能**：支持传入“剧本原文 + 目标镜头的 ID/场次 + 修改指令”，仅输出被修改的那一个或几个 `fragment`。这将直接驱动 Studio 里的“对话式微调”体验（如：“把第 3 场第 2 镜改成仰拍”）。
*   **[P1] 剧本-画面双向追溯机制**
    *   **功能**：为每个输出的 Fragment 生成置信度评分（Confidence Score），并向源头剧本做双向溯源映射。当导演觉得画面不好时，Agent 可借助溯源链，迅速定位是剧本描述太模糊，还是 Prompt 翻译不到位。
*   **[P1] 全协议无缝接入**
    *   **功能**：深化 MCP (Model Context Protocol) 支持，让外部 IDE 或其它 LangGraph Agent 可以开箱即用地调用 PenShot 能力。

## 三、 面向 HelpEnX Studio 的系统集成建议

*   **微服务独立部署**：由于集成了较重的 LangChain / LlamaIndex / Chroma 等库，强烈建议在 Studio 架构中，将 PenShot 作为独立的微服务（Docker）运行，通过 REST API 或 MCP Server 被 NeoTask 调用。
*   **数据格式强约束**：PenShot 输出的 `JSON Schema` 应在 NeoTask 和 Studio API 层进行强校验，一旦 PenShot 升级了 Schema，下游可平滑兼容（遵循向后兼容原则）。

## 四、 总结与近期行动 (Action Items)

PenShot 在当前 Studio 的“6 个 Pen”矩阵中处于**“迭代中”**，是整个系统的枢纽。当前不宜盲目扩张功能，而应抓准核心痛点。

*   **下一步行动 (Next Sprint)**：
    1. 梳理一版标准的 `fragment.schema.json`，在 GitHub 上向社区公开讨论。
    2. 引入 `shot_density` 参数，并针对短剧（3分钟以内）剧本进行一次跑测，评估输出的碎度与台词绑定准确率。
    3. 在示例代码（examples）中补充一个“直接对接可灵/Vidu API”的完整生成案例。
