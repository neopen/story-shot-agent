当一个片段需要稳定的人物身份，或画面里必须出现清晰可读的文字，直接文生视频往往不够可控。PenShot 会把这类片段改为两段式生成：先生成一张静态首帧，再用它驱动视频。这样身份、构图和文字都在首帧阶段锁定，视频模型只负责动作。

本页对应 v0.4.4 源码。PenShot 只输出首帧提示词、动作提示词与资产引用，不调用图片或视频接口。

30 秒了解

问题两段式的做法
人物长相容易漂移用角色三视图作身份参考，首帧再写死外观锚点
招牌、字幕、信件文字糊掉关键文字片段改走“先出图、再动起来”，让静态阶段渲染文字
首帧混入后续动作按动作线索把描述切成“静态截面”和“动作序列”，首帧只保留前者
纯音效片段首帧没内容剔除广播、画外音等非视觉子句，必要时用空镜兜底
片段场景和首帧资产对不上唯一匹配时自动替换场景资产，无法唯一匹配时阻断并转人工

快速上手：判断并消费首帧

from penshot.api import create_penshot_agent

result = create_penshot_agent().breakdown_script(script_text)
route_plan = result.data["instructions"]["route_plan"]

for package in route_plan["adapted_packages"]:
    if package["fragment_id"] in route_plan["blocked_fragments"]:
        continue

    if package["mode"] != "image_to_video":
        video_service.text_to_video(package["prompt"], duration=package["duration"])
        continue

    # 只有 as_first_frame=true 的引用是首帧，角色三视图不是
    first = next(
        (ref for ref in package["references"] if ref["as_first_frame"]),
        None,
    )
    frame = generated.get(first["asset_id"]) if first else None
    if not frame:
        # 场景首帧还没回填：按 image_prompt 现生成一张
        frame = image_service.generate(prompt=package["image_prompt"])

    video_service.image_to_video(
        prompt=package["motion_prompt"] or package["prompt"],
        first_frame=frame,
        duration=package["duration"],
    )

如果下游不自己生成首帧，也可以直接执行 first_frame_instruction，它已经把“先生成还是直接使用”写成了完整指令。

哪些片段会走两段式

路由节点在规则选型之前先做两段式判定。满足以下任一条件即可触发：

条件判定细节
关键文字提示词明确要求呈现可读文字，如招牌、字幕、书信、报纸、手写地址
角色外观锚点片段主角在全局契约中登记了 appearance_anchors
场景锚点覆盖片段所属场景已有对应的场景资产，具备可用的首帧视觉锚点

只有外观锚点、既没有关键文字也没有场景首帧时，还要求契约中已声明该角色的三视图；否则无法兑现身份约束，片段保持文生视频。注意“已声明”不等于“已生成”，状态为 pending 的角色资产同样可以支撑两段式，由下游负责生成。

文字判定使用固定词表：中文包含“文字、字迹、地址、手写、字幕、招牌、标牌、海报、书名、报纸、书信、标题”；英文按整词匹配 text、readable、address、handwriting、subtitle、newspaper、poster、menu、title。英文按词边界匹配，避免把 texture、context 误判成文字需求。

flowchart LR
    F[片段提示词] --> T{关键文字?}
    T -->|是| I2V[两段式生成]
    T -->|否| A{角色外观锚点?}
    A -->|是| C{有场景首帧或角色三视图?}
    C -->|是| I2V
    C -->|否| T2V[文生视频]
    A -->|否| S{场景锚点覆盖?}
    S -->|是| I2V
    S -->|否| T2V

首帧提示词怎么拼

首帧提示词由首帧构建器按固定顺序拼装，与角色三视图的“棚拍 turnaround”结构不同，因此不会直接复用三视图提示词。

顺序内容来源
1景别短语，如 medium shot、close-up shot结构化相机参数优先，回退片段景别，默认中景
2角色与白名单外观锚点，如 medium shot of 林然 (发型: ..., 服装: ...)片段主角 + 契约角色锚点
3场景地点，如 at 小巷片段所属场景
4时间，如 night lighting场景 time_of_day
5天气；晴天等中性天气不重复声明场景 weather
6动作开始前的静态截面清洗后的片段描述
7风格锚点全局契约风格

示意输出（外观值为示例）：

medium shot of 林然 (发型: 黑色短发, 服装: 黑色西装),
at 小巷, night lighting, rain,
林然站在霓虹灯下,
neo-noir, cinematic, moody lighting

如果清洗后完全没有视觉内容，首帧会追加 empty scene, no people，避免画面只剩声音描述。纯广播、纯画外音片段通常落在这里。

静态截面与动作序列

首帧只能承载“动作开始之前”的画面，否则文字模型和视频模型都会收到互相矛盾的信息。构建器会把片段描述切成两段：

输出字段内容
image_prompt景别、角色、场景、天气与第一个动作线索之前的静态内容
motion_prompt从第一个动作线索开始的动作序列，供图生视频驱动画面

“驶入、打开、回头、关门、转身、抬头、渐黑、随后、然后”等时间序列词会触发切分；“没有回头”这类否定表述会被识别为静止状态，不会被误切。对白引号内的内容不受标点切分影响；广播、画外音、音效等纯音频子句会被整句剔除；“固定镜头”“镜头越过肩膀”等运镜描述也会被移除，因为景别已经由第一段表达。

示例：片段描述“林然站在霓虹灯下，雨水顺着伞沿落下，随后他转身走进小巷”。第一个动作线索是“落下”，因此静态截面只保留“林然站在霓虹灯下”，后续内容全部进入 motion_prompt。如果片段本身就是动作开头，静态截面为空，首帧由景别、角色与场景构成。

资产引用的三种角色

roleas_first_framerequired用途
identity_referencefalsetrue角色三视图，锁定身份，不直接作为首帧
first_frametruetrue场景锚点，图生视频的唯一首帧来源
propfalsefalse道具静帧，带可选 state（如 crumpled、balled）

首帧语义有三条硬约束：

  • 只有 as_first_frame=true 的引用用于首帧，角色三视图与道具静帧不再承担首帧职责；
  • references[].asset_id 始终是 PenShot 规范 ID，下游改名必须走 asset_id_map；
  • asset_ref 只承载下游回填清单中的场景首帧引用，不会写入角色三视图的图片地址，也不会回退使用契约中的旧引用。

first_frame_instruction 的两种形态

场景指令
清单已回填场景首帧Use reference image {asset_ref} as the first frame; animate: {动作序列}
场景首帧尚未回填Generate first frame with prompt: {image_prompt}; then use it as the first frame and animate: {动作序列}
路由改判为图生视频、未经过片段级首帧构建first_frame_instruction 直接等于 image_prompt，动作序列由 motion_prompt 承载

第二种形态是声明式指令：PenShot 不生成图片，只把“先生成、再驱动”的完整步骤交给下游。下游若已有自己的首帧生成策略，也可以忽略这段文字，直接使用 image_prompt 与 motion_prompt。

场景锚定：自动替换与阻断

片段所属场景是按“片段 → 镜头 → 契约场景”解析的，但文本里可能明确写了另一个地点。首帧资产与文本场景不一致时，路由会做一次确定性校验；对白引号内的内容不参与判断，场景地点词表覆盖常见中英文别名与同义称呼。

判定处理
文本提到了当前首帧场景不动作，保留原资产
只命中另一个场景资产auto_replace：替换首帧资产，并按新场景重建 image_prompt，同时写入告警
命中多个场景资产ambiguous：status=needs_manual_fix，片段进入阻断列表
出现其他场景词但没有对应资产no_asset：同样阻断，等待人工指定场景

自动替换时首帧提示词必须与替换后的资产同源，否则会出现“资产是教室、提示词写走廊”的自相矛盾。阻断片段会出现在 route_plan.blocked_fragments，下游不得将其放入渲染队列。

路由阶段的检查

路由完成后，Gate 1 对提示词包做结构与逻辑检查，资产约束检查再补充服装降级要求。片段级问题写入 package.warnings 并置位 requires_special_attention；跨片段问题写入 route_plan.warnings。这些告警默认不阻断渲染，只有场景锚定失败会把状态改为 needs_manual_fix。

检查项判定
首帧静态性image_prompt 中不得出现动作线索，否则告警“首帧提示词包含动作序列”
关键文字证据关键文字片段的首帧必须明确要求呈现可读文字
景别一致性结构化景别与来源镜头景别必须一致
时长收敛片段时长被目标模型上限收敛时如实标注
对白语言视频提示词中的对白语言应与台词语言一致
道具引用完整性引用集合与 usage.fragments 必须互为子集，缺失或越界都会告警
服装降级角色服装关键字段缺失时，引用片段必须降级为剪影或背影，并写入 degraded_assets

排查常见问题

现象原因与处理
image_prompt 里仍有“转身、走进”动作线索未被识别或写在否定结构里；调整片段描述，让静态画面先于动作出现
有外观锚点却仍是文生视频契约中没有该角色的三视图资产，且片段没有场景首帧；先确认资产计划包含该角色
片段被阻断文本场景与首帧资产无法唯一匹配；查看 warnings 中的候选场景，人工指定或补充场景资产
首帧是空镜片段只有广播、音效或画外音，没有可入画对象；这是兜底行为，补充视觉描述即可
asset_ref 为空清单未回填场景首帧，或清单声明了该资产但引用为空；按 image_prompt 生成，或提交新的 asset_manifest
关键文字片段没有文字证据首帧提示词缺少招牌、字幕等要求；在剧本或提示词中明确写出需要呈现的文字内容
