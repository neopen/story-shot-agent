以下是从安装、配置到跑通第一个分镜任务的最小链路，示例使用 Python SDK；REST 与 MCP 调用见 集成指南，容器部署见 Docker 部署。当前版本 v0.4.4。

前置条件

组件 要求 说明
Python 3.10 及以上 与 pyproject.toml 中的 requires-python 一致
Redis 6.0 及以上，可选 短期记忆会话与多进程任务记录共享
Docker 20.10 及以上，可选 容器部署；使用 Compose 时另需 Compose v2
内存 建议 8GB 以上 长剧本与并发任务时按需增加
存储 建议 2GB 以上 缓存、记忆文件、资产计划与结果落盘

Redis 未配置或连接失败时，短期记忆自动降级为本地文件（data/memory/{script_id}/），任务不会中断；单进程 SDK 场景可以不装，多实例部署时各实例记忆互不可见。

安装

pip install penshot

# 使用通义千问（DashScope）或本地 Ollama 时，安装可选能力
pip install "penshot[full]"

# 或使用官方镜像
docker pull neotems/penshot

核心依赖包含 langchain-openai，OpenAI 与 DeepSeek 的 OpenAI 兼容接口可直接使用；Ollama 与 DashScope 分别在 [full] / [docker] 可选组中。[full] 还包含本地重排序依赖。缺少对应厂商 SDK 时请求会直接报错，不会静默切换模型。镜像的启动参数、Compose 与持久化配置见 Docker 部署。

配置

在项目根目录创建 .env，最少配置对话模型、嵌入模型与可选的 Redis。对话侧支持 OpenAI、通义千问（DashScope）、DeepSeek 与 Ollama 四类厂商，API_KEY 支持 ${ENV_VAR} 形式间接引用环境变量：

# 对话 / 解析 / 审查
PENSHOT_LLM__DEFAULT__BASE_URL=https://dashscope-intl.aliyuncs.com/api/v1
PENSHOT_LLM__DEFAULT__API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PENSHOT_LLM__DEFAULT__MODEL_NAME=qwen-plus

# 嵌入模型（记忆与语义检索）
PENSHOT_EMBED__DEFAULT__BASE_URL=https://dashscope-intl.aliyuncs.com/api/v1
PENSHOT_EMBED__DEFAULT__API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PENSHOT_EMBED__DEFAULT__MODEL_NAME=text-embedding-v4

# 短期记忆（可选）
PENSHOT_REDIS_URL=redis://:123456@localhost:6379/0
键组 用途 是否必需
PENSHOT_LLM__DEFAULT__* 对话、剧本解析、提示词转换与审查 必需
PENSHOT_EMBED__DEFAULT__* 文本向量化，供记忆与语义检索使用 使用记忆或模板召回时需要
PENSHOT_REDIS_URL 短期记忆会话与多进程任务记录 可选

.env 无需手动加载：导入 penshot.config 时会按当前目录、上两级父目录、用户配置目录、包安装目录、开发模式项目根目录的顺序搜索。需要覆盖已有变量时调用 load_dotenv(override=True)。完整键位参考仓库 .env.example，其中还包含 FALLBACK 备用厂商、检索器与 Redis 连接池配置。默认模型不可用时，可将 PENSHOT_LLM__FALLBACK__* 指向备用厂商；本地 Ollama 将 BASE_URL 指向 http://localhost:11434/v1 即可。

最小调用

准备一段短剧本，按“场景 → 角色 → 动作 → 台词”组织：

script = """
场景：城市街角咖啡店外，雨天，傍晚
角色：林小雨（女，20 岁，学生）
动作：林小雨蹲在长椅旁擦拭被雨淋湿的诗集，神情焦急
台词：林小雨（自语）：明明说好今天还书的……
"""

格式不强制，但以下信息越完整，跨片段的一致性越好：场景写明地点、时间与天气；动作写明角色、动作与情绪；台词单独成行并标注说话人；道具的颜色、材质与当前状态尽量具体。含糊描述会在提示词阶段被放大为片段之间的差异。

同步调用

from penshot.api import create_penshot_agent

agent = create_penshot_agent()
result = agent.breakdown_script(script)

if result and result.success:
    instructions = result.data["instructions"]
    fragments = instructions["fragments"]
    print(f"片段数: {len(fragments)}")
    print("路由模型:", instructions.get("metadata", {}).get("video_model"))

breakdown_script() 内部是“提交任务 + 等待结果”的封装，wait_timeout 默认 300 秒，超时返回 None，调用方必须判空。短剧本可以同步等待，长剧本推荐异步。

异步调用

import asyncio

from penshot import ShotLanguage
from penshot.api import PenshotFunction

async def main():
    # 并发与队列上限在构造时确定（默认 max_concurrent=10、queue_size=1000）
    agent = PenshotFunction(language=ShotLanguage.ZH, max_concurrent=5)
    try:
        task_id = agent.breakdown_script_async(
            script,
            callback=lambda r: print(f"完成: {r.task_id}"),
        )
        print(agent.get_task_status(task_id)["status"])

        # 协程，必须在事件循环内 await
        result = await agent.wait_for_result_async(task_id)
        print(result.success, result.status.value)
    finally:
        agent.shutdown()

asyncio.run(main())
  • breakdown_script_async() 是普通函数，提交后立即返回 task_id，不要加 await。
  • wait_for_result_async() 是协程；普通脚本中改用同步的 wait_for_result(task_id)。
  • 必须调用 shutdown() 释放后台事件循环与线程，否则进程可能不退出。

资产回填

如果资产已由外部生成，可在提交任务时带上 asset_manifest，让片段直接引用首帧资产；批量方法对应 asset_manifests 参数。

manifest = {
    "schema_version": "0.4.4",
    "bindings": [
        {
            "asset_id": "char_001",
            "view": "front",
            "asset_ref": "https://cdn.example.com/assets/char_001.png",
            "model": "flux-1.1-pro",
            "seed": 42,
        }
    ],
    "asset_id_map": {},
}

task_id = agent.breakdown_script_async(script, asset_manifest=manifest)

未回填或回填失败的资产保持 pending，不阻断主流程；路由节点会把无法唯一匹配场景锚点的片段写入 blocked_fragments，供下游跳过渲染。

同步与异步的选择

场景 建议 原因
短剧本、脚本调试 同步 代码简单，但需处理 300 秒等待超时返回 None
长剧本、Web 服务 异步 立即拿到 task_id，可轮询进度、避免阻塞请求
多任务并发 异步 + 任务池 用 max_concurrent 与 queue_size 控制并发和排队

同步封装的 300 秒只是调用方等待上限；异步任务本身的执行超时取 InputState.timeout，默认 600 秒。ShotConfig.workflow_timeout（默认 1800 秒）仅在未传 timeout 时作为兜底。

任务状态与回调

  • get_task_status(task_id) 返回字典，含 status、stage、current_stage、progress 等字段，可用于轮询进度。
  • callback 在任务完成时触发，参数为结果对象，可用于通知或落盘。
  • 任务进入终态后，可用 get_task_result(task_id) 直接取结果；任务池满时新任务进入队列，queue_size 为排队上限。

自定义配置

from penshot import ShotConfig

config = ShotConfig(
    max_fragment_duration=5.0,
    video_model="runway_gen2",
)
config.llm.temperature = 0.2  # 默认 0.1

agent = create_penshot_agent(config=config)

配置在创建 Agent 时注入，breakdown_script() 本身不接受 config 参数。LLM 采样参数位于嵌套的 config.llm，记忆容量位于记忆模块的 MemoryConfig，两者不在 ShotConfig 顶层。资产出图与模型路由由 settings.yaml 的 image 与 routing 段控制，不在 ShotConfig 中。

  • prompt 为英文描述加中文对照，同一实体的措辞在片段间复用；negative_prompt 排除卡通、畸变手部、水印等瑕疵。

样例落盘文件中的音频字段名为 audio_prompt，当前 AIVideoPrompt 模型的字段名为 audio；编写解析代码时以模型定义为准。失败时 success 为 false，message 字段给出原因。

阶段 节点 产出 要点
剧本解析 parse_script 场景、角色、对话、动作、风格锚点 输出解析置信度、完整度与一致性契约

片段切割 split_video 约 5 秒的视频片段 规则与 LLM 双路径
提示词转换 convert_prompt 双语正向词、负向词、音频提示词 逐片段调用 LLM，附带模板召回
模型路由 route_model 目标模型、生成模式、首帧指令 默认 5 条规则，能力注册表 5 个模型
质量审计 audit_quality 违规条目与修复参数 11 项规则 + LLM 审查
连续性守护 continuity_check 校验结论与修复路由 六项检查，最多 3 轮修复

split_video 的分割路径由镜头时长决定：不超过 5.5 秒的镜头通常直接成为片段，不判断语义边界；超过阈值且 enable_llm=True 时交给 LLM，在动作停顿、句末或情绪转折处切分。关闭 LLM 时，超阈值镜头由规则路径按 2.5 秒左右等分；规则路径确定性强、无 API 成本，代价是割点可能落在动作中间。

全链路耗时取决于 LLM 调用次数与模型响应速度，而非剧本字数。提示词转换与模型路由通常是最耗时的一环；资产出图默认关闭，开启后会额外产生文生图调用。

质量审计的 11 项规则检查覆盖片段时长、提示词内容与长度、片段数量、模型支持、外观锚点污染、契约违规、景别/镜头运动一致性、风格光照冲突与资产使用，另加 LLM 深度审查。评分从 100 分起按 warning 5、moderate 10、major 25、critical 40、error 60 扣减；存在 critical 或 major 超过 2 条时置位 needs_human_review。修复参数会回到提示词转换节点，连续性问题的修复目标按来源阶段动态决定，形成闭环。

三层记忆的默认参数：短期保留 20 条消息、TTL 3600 秒；中期摘要上限 500 tokens；长期检索 k=3、相似度阈值 0.7。跨片段的角色与道具衔接主要来自一致性契约、资产锚点、镜头时间轴与 continuity_notes，记忆系统提供的是增强而非唯一来源。

故障排查

现象 可能原因 处理
返回 None 或结果为空 同步等待超过 300 秒，或未配置 LLM Key 改用异步并轮询；核对 .env 与剧本格式
缺少厂商 SDK 报错 未安装可选依赖 pip install "penshot[full]"
Redis 连接失败 服务未启动或 URL 错误 redis-cli ping 确认；或忽略，短期记忆会降级
片段明显超过目标时长 阈值或上下限配置不当 核对 max_fragment_duration 与 duration_split_threshold
割点落在动作中间 规则分割不判断语义 确认镜头超过 5.5 秒且 enable_llm=True
route_plan 为空 路由异常或目标模型未注册 检查 settings.yaml 的 routing.rules 与能力注册表
部分片段出现在 blocked_fragments 场景锚定无法唯一匹配，或资产需人工修复 补齐 asset_manifest 或人工编辑资产提示词
提示词被截断 输出 token 上限偏低或长度约束过紧 调整 config.llm.max_tokens 与 max_prompt_length
进程不退出 后台事件循环与线程未释放 在 finally 中调用 agent.shutdown()
多进程查不到任务 未配置 Redis，任务记录在进程内 配置 PENSHOT_REDIS_URL，或改用单进程
