PenShot 是一个基于 LangGraph 的开源剧本分镜智能体：输入任意长度的剧本，输出可直接交给 Sora、Runway、Veo 等视频模型逐段生成的分镜提示词包。

功能定位

主流视频模型单次通常只能生成 5–10 秒画面，更长的成片需要先拆分剧本、逐段生成再拼接。PenShot 处理其中最容易出错的一步：把剧本拆成符合时长限制的片段，并让片段之间在角色、场景、道具和动作上保持衔接。

输入可以是自然语言剧本、标准剧本或已有分镜文本；输出是片段序列，以及每个片段的正向提示词、负向提示词、目标模型、时长与音频提示词。视频生成、拼接与口型对齐由下游工具完成。典型用途包括短视频批量分镜、影视预可视化与游戏过场动画原型。

提示词面向的模型由枚举定义：VideoModelType 覆盖 Runway Gen-2、Sora、Veo、Pika、Midjourney、Stable、DALL·E 等，共 8 种；AudioModelType 覆盖 XTTSv2、AudioLDM_3、Bark、ElevenLabs、Azure TTS、OpenAI TTS，共 6 种。

六阶段工作流

flowchart LR
    subgraph Input["输入层"]
        A[原始剧本<br/>自然语言 / 标准剧本]
    end
    
    subgraph Core["核心处理链（六个节点）"]
        B[剧本解析<br/>parse_script]
        C[分镜拆分<br/>segment_shot]
        D[片段分割<br/>split_video]
        E[提示词转换<br/>convert_prompt]
    end
    
    subgraph Control["质量与控制层"]
        F[质量审查<br/>audit_quality]
        G[连续性检查<br/>continuity_check]
    end
    
    subgraph Output["输出层"]
        H[分镜序列 + 双语提示词<br/>+ 音频提示词]
    end
    
    A --> B --> C --> D --> E --> F --> G --> H
    F -->|发现问题| I[生成修复参数<br/>打回上游重跑]
    F -->|严重问题| J[人工干预 / 错误处理]

六个核心节点对应 PipelineNode 枚举中的六个值；输出、修复与人工干预属于辅助节点。质量审查发现问题时生成修复参数并打回上游，严重问题转入人工干预。连续性检查节点受循环上限约束，最多循环 5 次、重试 2 次，避免问题片段无限返工。

阶段 节点 输入 → 输出 关键行为
剧本解析 parse_script 原始文本 → 结构化剧本 提取场景、角色、对话、动作，给出置信度
镜头拆分 segment_shot 结构化剧本 → 镜头序列 按内容划分镜头，标注景别与时长
片段分割 split_video 镜头序列 → 视频片段 规则或 LLM 切分，继承连续性约束
提示词转换 convert_prompt 片段 → 提示词 逐片段生成双语正向词、负向词与音频提示词
质量审查 audit_quality 提示词 → 审查报告 规则检查与 LLM 连贯性检查
连续性检查 continuity_check 全阶段产物 → 校验结论 视觉、角色、场景、动作四类校验，按来源路由修复

核心能力

能力 说明
剧本解析 识别场景、角色、对话与动作，输出结构化元素及解析置信度
镜头拆分 按内容划分镜头，标注景别、时长与主角色
双路径分段 ≤5.5 秒的镜头直接映射为片段，超阈值镜头交由 LLM 在语义边界切分；关闭 LLM 时按 2.5 秒左右等分
提示词工程 逐片段生成中英双语正向词、负向词与音频提示词，措辞跨片段复用
质量审查 5 项规则检查加 1 项 LLM 连贯性检查，输出违规条目与修复建议
连续性守护 按视觉、角色、场景、动作四类校验，问题可路由回对应上游阶段
工程接入 同步、异步与批量调用，任务池、检查点、三层记忆与 MCP Server

输出形态

结果是单个 JSON 包，顶层为 task_id、success 与 data.instructions；instructions 下分 metadata、project_info、fragments、global_settings 与 execution_suggestions。每个片段自带模型与风格字段，可独立投喂下游生成服务。

{
  "task_id": "HL202603061716542571",
  "success": true,
  "data": {
    "instructions": {
      "metadata": {
        "video_model": "runway_gen2",
        "audio_model": "XTTSv2",
        "total_prompts": 13
      },
      "project_info": { "total_fragments": 13, "total_duration": 48.0 },
      "fragments": [
        {
          "fragment_id": "frag_001",
          "prompt": "Cinematic wide shot: ...\n\n全景镜头：...",
          "negative_prompt": "cartoon, anime, ...",
          "duration": 4.0,
          "model": "runway_gen2",
          "style": "cinematic realism, ...",
          "audio_prompt": {
            "audio_id": "audio_001",
            "prompt": "Natural rainfall ...",
            "model_type": "AudioLDM_3",
            "voice_type": "narration",
            "previous_audio_id": null
          }
        }
      ],
      "global_settings": { "style_consistency": true }
    }
  }
}

project_info 汇总片段数与总时长；execution_suggestions 是通用执行建议文本，不是强制参数。prompt 为英文描述加中文对照；negative_prompt 排除卡通、畸变手部、水印等常见瑕疵；audio_prompt 用 voice_type 区分旁白与角色台词，并以 previous_audio_id 串联上下文。样例落盘文件的字段名为 audio_prompt，当前 AIVideoPrompt 模型的字段名为 audio，写解析代码时以模型定义为准。

接入方式

方式 入口 说明
Python SDK create_penshot_agent()、PenshotFunction 同步、异步与批量调用；任务池默认并发 10、队列 1000
REST /api/v1，默认端口 8000 内置 FastAPI 服务，共 17 个端点，含提交、状态、结果与队列观测
Docker neotems/penshot REST 服务的官方镜像，内置健康检查；Compose 可一并启动 Redis
MCP python -m penshot.mcp_server 7 个工具，默认 stdio 传输，可接入 Claude Desktop、Cursor 等客户端
CLI story-shot-agent serve-rest 安装后启动 REST 服务，默认监听 0.0.0.0:8000

上述入口共用同一套任务池与工作流，任务状态与结果一致。接入细节见 集成指南 与 MCP 服务，容器部署见 Docker 部署。

当前边界

边界 说明
只产出提示词 不生成视频，拼接、转场与口型对齐需外部工具完成
分割策略 镜头 ≤ 5.5 秒时走规则路径，通常 1:1 成为片段，不判断语义；超过阈值且 enable_llm=True 才交给 LLM 在动作停顿、句末等边界切分；关闭 LLM 时按 2.5 秒左右等分
时长校验 提示词建议单段不低于 1.5 秒、总时长误差小于 0.5 秒；代码强校验区间为 1.0–5.0 秒，总偏差超过 1 秒告警、超过 2 秒按比例缩放
修复闭环 审计输出 violations 与 recommended_actions，存在 critical 或 major 超过 2 条时置 needs_human_review；自动修复尚未完全闭环
分割缓存 split_cache 为进程内字典，多副本部署时各自独立、无法共享命中
Redis 依赖 可选；不可用时短期记忆降级为本地文件，任务不中断，但多实例之间记忆互不可见

这些边界不影响“剧本 → 分镜提示词”主链路的可用性，但属于生产选型前应评估的部分。
