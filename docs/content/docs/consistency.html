PenShot 的一致性由六条已接线的通道共同保障：全局一致性契约、外观与资产锚点、连续性注释、提示词约束、规则检查加修复回路、跨剧本模板召回。快照回滚与结构化锚点仍未接入主链。

这些通道都在主链内部完成，不额外引入生成模型：契约、锚点与注释是结构化透传，规则检查是确定性判定，检索只读取已有向量库。因此一致性保障的边际成本主要是提示词长度，而不是额外推理调用。

全局一致性契约

解析节点在提取剧本的同时构建 GlobalConsistencyContract，挂到 state.domain.contract，下游只读或追加，不回退已确认的事实。

字段 内容 消费方
characters 角色首次/末次场景、出场列表、外观锚点、服装序列、持有道具 资产计划、提示词、审计
scenes 地点、时间、天气、场景角色、道具状态 场景锚点、连续性检查
style_anchor 全局风格锚点 资产提示词、转换模板
style_anchor_provenance 风格来源字段、候选与冲突丢弃项 风格溯源与审计
assets AssetContract：资产类型、归属、asset_ref、状态 路由、审计、下游交接
version / history 契约版本与变更记录 回溯与调试

外观锚点采用“首值优先”：同一字段第一次出现的值锁定，后续描述只补充缺失字段，不覆盖已确认值，保证锚点在所有片段中完全一致。服装变化不覆盖身份特征，而是进入角色的 outfit_sequence。

资产锚点与回填

资产计划把契约中的角色、道具、场景转换为可复用的视觉锚点，默认只声明规格；下游通过 asset_manifest 回填真实引用后，路由节点把首帧资产挂到片段上。

机制 行为
角色三视图 front / side / back 三视角，identity_lock=true，优先使用正面
道具状态变体 同一道具按片段顺序推导状态（如 crumpled → balled），记录到 state_variants
使用范围 usage.characters / scenes / fragments，由资产计划与路由共同回填
回填绑定 bindings + asset_id_map，把声明式 ID 绑定到下游真实引用
不可覆盖字段 OVERRIDABLE_FIELDS 允许改提示词与参数，资产身份字段不可改

审计会把“使用计划外资产”“必需资产缺失”“外观锚点污染”作为独立违规项，问题带 asset_id 或 fragment_id，可直接定位到资产或片段。路由阶段发现场景锚定无法唯一匹配时，片段进入 blocked_fragments，不进入下游渲染队列。

资产计划如何交给下游、如何回填真实引用见资产计划与交接；首帧引用与场景锚定规则见首帧与图生视频；模型选型见模型路由。

全局元数据与连续性锚点

解析节点从全剧提取 global_metadata，它是跨场景一致性的事实来源；下游只读不改。

字段 内容 消费方
key_props 关键道具及 appears_in 场景列表、重要度 提示词“本场景关键道具”、道具资产
character_outfits 角色在各场景的服装、发型、配饰 提示词“角色服装要求”、服装回填
key_locations 地点名称、appears_in、视觉特征 提示词“本场景地点”、场景锚点
continuity_notes 全剧级连续性提醒 提示词“连续性要求”
audio_atmosphere 整体音频氛围 音频提示词
recurring_sounds 反复出现的环境声、音效 音频提示词

片段级注释由分段节点生成，规则路径与 LLM 路径字段不同：

路径 字段
规则切分 main_character、location（固定为 场景{scene_id}）、main_action、split_type
LLM 切分 另含 continuity_id、prev_fragment、split_reason、segment_part、continuity_hints

提示词约束

转换节点在每个片段提示词中注入四段上下文，来源均为 global_metadata 与片段的 continuity_notes。

段落 生成规则
【本场景关键道具】 按 appears_in 过滤当前场景；无命中时退回全量道具，重要道具加标记
【角色服装要求】 全量输出角色服装，不按场景裁剪
【本场景地点】 按 appears_in 过滤；无命中时退回全量地点
【特别注意，连续性要求】 原样拼接片段 continuity_notes，不做语义改写

四段内容装入模板的【全剧上下文】区块，并在生成指令中追加【重要约束】：人物外观、道具、场景与上下文保持一致。冲突时以上下文为准，而非模型自由发挥。场景过滤的依据是 appears_in；该字段缺失或没有命中时，段落退回全量列表，宁可多给上下文也不省略约束。

六项规则检查

连续性守护节点以关键词和数值规则检查六个维度，不调用 LLM。

维度 判定 违规类型
角色 有对话的角色是否出现在镜头；服装 / 发型 / 配饰词表 CHARACTER_MISSING（MAJOR）、外观变化（WARNING）
场景 相邻镜头 scene_id 跳变及占比 SCENE_JUMP（WARNING）、SCENE_TOO_FREQUENT（>30%，MODERATE）
动作 走/跑/跳/转身/坐下/站起/拿起/放下 按角色追踪 ACTION_BREAK（MODERATE）
风格 AIVideoPrompt.style 去重种类数 种类 >2 → STYLE_INCONSISTENT（MODERATE）
时间 片段起点与前段“起点 + 时长”的差值 正差 >0.1 秒 → TIME_GAP（MAJOR）；负差 → TIME_OVERLAP（ERROR）
道具 拿/举/抱/提/端/持/握 按角色统计 PROP_CHANGE（WARNING）

通过条件为 critical_count == 0 且 major_count ≤ 3；任一 CRITICAL 或 MAJOR 超过 3 个即不通过，其余级别只记录。问题签名由类型、片段、场景、严重度、位置与描述前 100 字组成，同一位置同类问题只报一次；描述超过 500 字符截断。每条问题带 source_stage、auto_fixable 与 suggestion，供修复路由使用。

误报边界：词表法会把“拿手机→握手机”判为道具变化，“转头”不在动作词表；缺少分镜或片段时对应检查直接跳过。规则检查不依赖 LLM，配额耗尽时仍可运行，代价是对近义表达与隐含动作不敏感。

修复回路

质量审计与连续性守护都会把问题转换为修复参数，但回流路径不同：审计固定回转换节点，连续性按问题来源回到解析、拆分、切割或转换。

flowchart TB
    Input([输入原始剧本]) --> Parse[剧本解析<br/>契约 + 全局元数据]
    Parse --> Assets[资产计划<br/>资产锚点]
    Assets --> Segment[镜头拆分]
    Segment --> Split[片段切割<br/>continuity_notes]
    Split --> Convert[提示词转换<br/>全剧上下文 + 模板参考]
    Convert --> Route[模型路由<br/>首帧引用 + usage 回填]
    Route --> Audit[质量审计<br/>11 项规则 + LLM]
    Audit -->|通过| Continuity[连续性守护<br/>六项词表检查]
    Audit -.->|NEEDS_REPAIR / RETRY| Convert
    Continuity -.->|按来源修复| Parse
    Continuity -.->|按来源修复| Segment
    Continuity -.->|按来源修复| Split
    Continuity -.->|按来源修复| Convert
    Continuity -->|通过| FinalOutput[最终输出<br/>AIVideoInstructions + 资产 + 路由]

修复参数按 PipelineNode 写入 state.domain.repair_params，节点只读取自己的键；连续性节点同时设置 needs_continuity_repair 与来源阶段，决策函数返回节点名完成动态路由。修复最多 3 轮（max_continuity_retries），轮次耗尽、存在 CRITICAL 或无法定位来源时转人工。

审查扣分从 100 起算，warning 5、moderate 10、major 25、critical 40、error 60；≥90 PASSED、≥75 MINOR_ISSUES、≥60 MODERATE_ISSUES、≥40 MAJOR_ISSUES、≥20 CRITICAL_ISSUES，否则 FAILED。PASSED 直接放行，MINOR 违规不超过 3 个也放行；MODERATE / MAJOR 带修复参数回到 CONVERT_PROMPT；CRITICAL 重试或转人工。审查的 NEEDS_RETRY 与 NEEDS_REPAIR 都回到 CONVERT_PROMPT，因为审查本身不产生内容。

RAG 模板召回

提示词模板库按相似度检索成功案例，供转换节点参考；默认先查本剧本，名额未满时只读回退到其他剧本的活跃模板。

参数 默认值 作用
min_similarity_score 0.80 低于阈值的模板不注入
top_k 2 每个查询返回的模板数
include_global true 本剧本名额未满时回退到其他剧本模板
max_injected_patterns 6 单次任务最多注入的模板数

检索结果只作为上下文参考，不直接复制；命中模板带 source 与 audit_status 元数据，legacy 模板在检索与注入阶段都会被排除。环境变量可通过 PENSHOT_PROMPT_TEMPLATES__* 覆盖上述默认值。

跨剧本召回是只读的：不会把其他剧本的模板写回当前剧本，也不会修改对方的审计状态。向量库为空、索引不可用或检索异常时返回空结果，不阻断主流程。详细构建流程见RAG 知识库。

种子建议

global_settings 只包含 style_consistency: True 与 use_common_negative_prompt: True，没有种子字段。execution_suggestions 输出三条执行建议：按顺序生成片段、保持相同种子值以获得一致性、生成后检查片段衔接。资产规格中的 consistency.seed 是可选的建议值，供下游生成静态资产时使用，不会自动写入视频提示词。

建议文案不进入模型请求，也不会被校验。执行层若固定种子，应在同一任务内复用同一值，并自行记录以便复现；跨任务沿用同一值只会重现画面风格，不能保证内容正确。
