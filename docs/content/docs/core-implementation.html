PenShot 的核心实现由七类基础件组成：可插拔 LLM 客户端、版本化 YAML 提示词、资产计划与回填、模型能力路由、调用重试与循环控制、任务池调度、上下文窗口约束。它们共同决定一条剧本能否稳定跑完并产出可用的分镜提示词。

事实边界：本页对应 v0.4.4 源码。三层记忆见 记忆系统；一致性契约与修复回路见 一致性策略；节点级输入输出见 工作流节点。

LLM 客户端

所有客户端继承 BaseClient，只实现 llm_model() 与 llm_embed()。上层智能体依赖 LangChain 的 BaseLanguageModel / Embeddings 抽象，不感知厂商差异。配置分两级：配置文件与环境变量提供默认值，代码参数实时覆盖。

厂商 默认 base_url 关键参数
OpenAI https://api.openai.com/v1 timeout=300（settings.yaml）、max_retries=3；嵌入默认 text-embedding-3-small、1536 维
Ollama http://localhost:11434 num_predict=max_tokens*4、keep_alive=timeout*5、num_thread=8
Qwen https://dashscope.aliyuncs.com/compatible-mode/v1 ChatTongyi，streaming=False，采样参数经 model_kwargs 透传

厂商由 detect_ai_provider_by_url() 按域名探测：openai.com → OpenAI，aliyuncs.com → Qwen，deepseek.com → DeepSeek，其余兜底 Ollama。新增厂商只需注册到 CLIENT_REGISTRY，不必改动节点代码。

降级链

LLM 在 PenShot 中是增强项而非必需项。工厂按“默认配置 → fallback 备用配置 → 返回 None”三级尝试；上层拿到 None 后转入规则引擎路径，例如视频切分降级为规则切分，任务不会因 AI 服务不可用而整体失败。

flowchart TB
    A[get_default_llm] --> B{默认配置可用?}
    B -->|是| C[构建 BaseClient]
    B -->|否| D{fallback 配置可用?}
    D -->|是| C
    D -->|否| E[返回 None]
    E --> F[上层转入规则引擎]
    C --> G[detect_ai_provider_by_url]
    G --> H[OpenAI / Ollama / Qwen / DeepSeek]

降级只写 error 日志，不重试、不中断。代价是规则路径的输出质量上限较低，且调用方需要自行监控降级事件。

配置优先级为：代码显式参数 > 环境变量 > 配置文件默认值。模型名、温度、超时与重试次数都可按调用覆盖，密钥只从配置或环境读取。切换厂商时至少要核对 max_tokens 的计量口径、嵌入维度与结构化输出支持，否则会出现“配置没变、行为变了”。

已知副作用

  • OpenAI / Qwen 客户端在构造时写入 os.environ（OPENAI_API_KEY、DASHSCOPE_API_KEY），同进程多实例会互相覆盖。
  • “max tokens”语义不一致：Ollama 的 num_predict 按生成 token 计数，代码乘 4 留余量；Qwen 的 temperature / timeout 只能经 model_kwargs 传入。
  • LLMBaseConfig.seed 仅 Ollama 客户端向下传递；OpenAI / Qwen 不接收该参数。

提示词管理

提示词以 YAML 维护，目录结构为 prompts/{version}/{language}/，每个智能体一个或多个模板键。切换版本或语言即切换目录，便于并行调试与灰度。

模板结构

文件顶部记录 version 与 changelog，正文按 system / user 拆分。以 shot_segmenter（version 1.3）为例，用户模板包含以下占位符：

占位符 来源 用途
{location}、{time_of_day}、{weather}、{description} 当前场景 限定空间、时间与氛围
{elements_list} 场景元素列表 逐元素分配镜头
{global_context} 全剧上下文 角色服装、关键道具等跨场景约束
{repair_hint} 质量审计 上一轮问题的定向修复建议
{history_hint} 记忆系统 历史常见问题与质量等级提示

模板用“规则约束 + 拆分规则 + 镜头衔接 + 转场 + 置信度 + one-shot 示例”组织，并要求直接返回合法 JSON。台词完整性被反复强调，因为省略台词会直接破坏叙事。

加载与匹配

PromptManager（prompt_load_manager.py）负责加载与缓存。首次调用 get_all_prompts() 时遍历目录下全部 YAML，用 _all_prompts_loaded 标志位保证只全量加载一次；缓存上限 1024 条，超出后保留最新部分。

flowchart LR
    A[get_prompt name] --> B{缓存命中?}
    B -->|是| C[返回 template]
    B -->|否| D[get_all_prompts 懒加载]
    D --> E[遍历 YAML 键名]
    E --> F{键名或 name 字段匹配?}
    F -->|是| C
    F -->|否| G[尝试去掉 _prompt 后缀]
    G --> H{仍无匹配?}
    H -->|是| I[抛出 KeyError]
    H -->|否| C

匹配顺序为“缓存 → 键名 → name 字段 → 去 _prompt 后缀”。docstring 列出了五条策略，实现层实际落地的是上述路径。另有一处历史残留：get_all_prompts() 中处理旧格式的 elif isinstance(data, dict) 分支不可达，因为前一个 if 已捕获所有字典。两者都不影响主流程。

模板按 version + language 目录隔离，升级提示词不需要改代码，回滚只需切回旧目录。缓存以进程为界，多进程部署各自维护一份；模板文件更新后需要重启进程或重建管理器才会生效。

模板召回

转换阶段还会按 script_id 召回历史成功模板：默认相似度阈值 0.80、top_k=2、单次最多注入 6 条；本地命中不足时可只读召回其他剧本的模板（include_global=true），但不会写入对方索引。旧版缺陷模板在 0.4.4 中标记为 legacy 并排除在召回之外；升级后可用 scripts/migrate_prompt_templates_044.py 迁移存量数据，默认 dry-run，--apply 才写入。

资产管线

资产生成把“角色、道具、场景”从提示词描述提升为可回填的显式对象。默认配置 image.default.enabled=false，节点只产出 asset_plan，不调用任何生图接口。

flowchart LR
    A[解析产物<br/>角色/道具/场景] --> B[AssetSpec 规格<br/>char_ / prop_ / scene_]
    B --> C[AssetPlanDocument<br/>assets[] + style_anchor]
    C --> D{image.default.enabled?}
    D -->|否| E[仅输出计划<br/>status=pending]
    D -->|是| F[调用生图 provider<br/>生成 asset_ref]
    F --> G[AssetGenerationReport<br/>generated / failed / skipped]
    G --> H[AssetManifest<br/>bindings + asset_id_map]
    H --> I[回填提示词<br/>asset_ref 替换占位]
对象关键字段用途
AssetSpecasset_id、asset_type、views、status、asset_ref声明单个资产及其生成规格
AssetPlanDocumentschema_version、style_anchor、assets[]交付给下游的声明式计划
AssetManifestbindings[]、asset_id_map下游回填的真实资产引用
AssetGenerationReportspecs[]、stats逐资产状态与统计

角色资产默认生成 front、side、back 三个视角；清单按规范 asset_id 查找绑定，优先走 asset_id_map 改名映射。资产生成失败不阻断主链：报告记录 failed，对应片段继续使用文本描述，质量审查会给出资产使用告警。

模型路由

路由层把“写提示词”和“选模型”分开。能力注册表静态声明每个视频模型的时长上限、是否支持图生视频、镜头控制与一致性评分；路由规则在 settings.yaml 中按优先级匹配，输出 RoutePlan 与逐片段的 AdaptedPromptPackage。

模型最大时长图生视频镜头控制文字渲染 / 一致性审美倾向
runway_gen410.0s支持支持0.5 / 0.8电影感
kling_310.0s支持支持0.7 / 0.9写实
luma_dream5.0s支持支持0.6 / 0.7电影感
sora_260.0s不支持不支持0.95 / 0.85写实
pika_24.0s支持支持0.4 / 0.6动画

默认规则五条，按优先级从高到低：critical_text（首帧需呈现可读文字）→ high_consistency（角色一致性要求高）→ complex_motion（复杂运动）→ anime_style（动画风格）→ cinematic_long_take（电影感且时长 ≥8 秒）。未命中任一规则时使用 routing.default_model，默认 kling_3。

图生视频为两阶段：先用 first_frame_builder 生成静态首帧提示词，再由视频模型驱动。首帧提示词不得混入动作序列，Gate 1 会检查静态性；critical_text 路由还要求首帧明确呈现可读文字。Gate 1 只回写 warnings，不阻断输出；blocked_fragments 则记录路由后仍无法满足能力约束的片段，交给下游或人工处理。

路由失败不回滚已生成的提示词：route_plan 置空，主链继续走审查与输出，问题以告警形式保留。适配层允许覆盖时长、风格、镜头等字段，但不允许改写资产身份，避免回填后的角色与计划脱节。

调用重试

智能体通过 _call_llm_chat_with_retry() 调用模型：组装 system / user 两条消息，交给 llm_chat_complete()，后者调用 llm.invoke() 并返回 response.content。异常时 sleep(1) 后重试，默认 max_retries=2；最后一次仍失败则显式上抛，交给节点层与循环控制处理。

sequenceDiagram
    participant A as 智能体
    participant F as llm_chat_complete
    participant L as LLM

    A->>F: system + user 消息
    F->>L: invoke
    L-->>F: response
    F-->>A: content 字符串
    Note over A: 异常时 sleep(1) 后重试
    A->>A: 最多 2 次，仍失败上抛

重试间隔写死为 1 秒，没有读取 retry_delay 配置；也没有区分可重试与不可重试错误，参数类 4xx 同样会重试两次。这是以延迟换实现简单的取舍。

循环控制

多阶段工作流容易在单节点自旋。PenShot 用三套计数器兜底：硬限制按节点累计、永不重置；软限制只在 NEEDS_RETRY 时累加、成功即归零；全局计数所有节点共享，作为最后防线。

        B -->|通过| D[执行节点逻辑]

机制 计数器 默认值 重置条件
硬限制 node_current_loops 按节点配置，2 至 5 永不重置
软限制 stage_current_retries 多为 3；资产、路由、审计与连续性为 2 决策为 SUCCESS / VALID 时归零
全局上限 global_current_loops max_total_loops × 2，默认 40 永不重置

节点硬限制的源码默认值：PARSE_SCRIPT=3、GENERATE_ASSETS=2、SEGMENT_SHOT=5、SPLIT_VIDEO=5、CONVERT_PROMPT=5、ROUTE_MODEL=5、AUDIT_QUALITY=3、CONTINUITY_CHECK=5、ERROR_HANDLER=5、HUMAN_INTERVENTION=2。全局上限在工作流启动时按 config.max_total_loops × 2 计算，配置未传时 ShotConfig 默认 20，因此实际为 40；WorkflowState 中的 30 只是独立的兜底默认值。全局计数达到 80% 时发出一次 warning，由 loop_warning_issued 保证不重复。

软限制超限后降级为 NEEDS_REPAIR 而不是直接失败，修复参数随状态传递，节点带参重跑。无法恢复的错误才进入 NEEDS_HUMAN 或 FAILED。

修复参数由质量审计与连续性检查生成，经 apply_repair_params() 在节点下一次执行前注入，智能体再把它渲染成 {repair_hint}。连续性检查的修复路由已接通，可按问题来源回到解析、拆分、分段或转换；修复轮次受节点上限约束，不会无限回炉。

recover_pending_tasks(max_age_hours=2) 会在进程重启后把两小时内未完成的任务重新入队，用于 Worker 宕机或进程崩溃后的恢复。边界是：重新入队一律使用 NORMAL 优先级，原优先级丢失；超过 2 小时的任务不会自动恢复。

质量检查

规则版审查在提示词包上执行 11 项检查，全部为确定性判定，不调用 LLM。

检查判定对象

提示词内容提示词为空
提示词长度超出 max_prompt_length 或低于 min_prompt_length
片段数量没有任何片段
模型支持模型不在支持列表
外观锚点污染片段提示词改写了契约中的外观锚点
契约违规违反全局一致性契约的约束

上下文窗口

PenShot 没有独立的 ContextWindowManager，也不做重要度评分或相似度去重。实际落地的是四条确定性规则：

规则 位置 行为
滑动窗口 ShortTermMemory deque(maxlen=20)，超出自动丢弃最旧条目
过期回收 Redis 会话历史 ttl=3600 秒；内存模式无自动过期
组装截断 MemoryContext.to_prompt() max_tokens=2000，按 1 token ≈ 2 字符估算
长度审计 ShotConfig max_prompt_length=200 单词，超限触发 PROMPT_TOO_LONG 
flowchart TB
    subgraph 短期记忆层
        C1[全量交互] --> W[deque maxlen=20<br/>滑动窗口]
        W --> T[Redis TTL 3600s<br/>过期回收]
    end

    subgraph 提示词层
        W --> P[MemoryContext.to_prompt<br/>分层组装]
        P --> TR[_truncate<br/>1 token ≈ 2 字符<br/>+ 句边界回退]
        TR --> F[最终上下文<br/> ≤2000 tokens]
    end

    subgraph 质量层
        G[生成的视频提示词] --> R{长度检查<br/>200单词±阈值}
        R -->|超长| FIX[PROMPT_TOO_LONG<br/>触发修复循环]
        R -->|正常| PASS[通过审计]
    end

截断用字符估算而非精确分词：这里只需要一个不超窗的安全上界，引入分词器会给每次组装增加依赖与计算。截断点优先回退到最近的句号或换行，若落在后 30% 之外则保持硬截断，并追加 [上下文已截断] 标记。

字符估算对中文偏保守：一个汉字通常折合一个以上 token，而实现按两个字符折一个 token，因此 2000 token 的实际中文容量可能低于预期。需要精确计费或硬限流时应替换为分词器。

跨场景一致性靠一致性契约与提示词的 global_context 占位符，而不是把完整剧本塞进每次调用。长剧本的分块发生在场景与镜头拆分阶段：shot_segmenter 逐场景处理，video_splitter 逐镜头处理，每个单元只携带本场景信息与全局约束。全剧摘要压缩属于后续方向，当前没有对应实现。

实现边界

边界 现状
LLM 降级 三级链路只写日志；降级后输出质量由规则保证
提示词缓存 全量加载一次，1024 条上限；存在不可达分支
调用重试 固定 1 秒间隔，不区分错误类型
循环上限 硬限制与全局计数不可重置，软限制成功归零
任务恢复 仅恢复两小时内任务，优先级退化为 NORMAL
资产生成 默认关闭，只输出计划；失败不阻断主链
模型路由 静态能力注册表，规则匹配，无在线评测或回退重训
上下文管理 窗口 + 截断 + 长度审计，无动态淘汰

记忆层的写入分发、召回组装与存储降级见 记忆系统；检查点只写不读的现状见 检查点与恢复。
