PenShot 默认不调用任何文生图或文生视频接口。它把角色三视图、关键道具与场景锚点写成一份声明式资产计划（asset_plan），由下游选择图片供应商生成，再把真实引用交回 PenShot 或直接用于视频生成。本页说明这套交接机制的字段、两种接入方式与常见降级行为。

本页对应 v0.4.4 源码。资产计划只描述“要生成什么”，不负责“用哪个模型生成”。如果显式开启 image.enabled 或注入 AssetExecutionAdapter，资产节点也可以调用执行器生图并产出回填清单；默认关闭，本文以声明式交接为主。

快速上手：一次任务，下游消费

推荐先走“直接消费”模式：运行一次 PenShot，读取 asset_plan 生成资产，再按 route_plan.adapted_packages[].references 调用视频服务。

from penshot.api import create_penshot_agent

agent = create_penshot_agent()
result = agent.breakdown_script(script_text)
data = result.data

plan = data["asset_plan"]
instructions = data["instructions"]
generated = {}

# 1) 只生成尚未回填的资产
for asset in plan["assets"]:
    if asset["status"] != "pending":
        continue
    generated[asset["asset_id"]] = image_service.generate(
        prompt=asset["image_prompt"],
        negative_prompt=asset["negative_prompt"],
        size=asset["size"],
        seed=asset["consistency"]["seed"],
    )

# 2) 只有 as_first_frame=true 的引用用于图生视频首帧
for package in instructions["route_plan"]["adapted_packages"]:
    first = next(
        (ref for ref in package["references"] if ref["as_first_frame"]),
        None,
    )
    if first is None:
        video_service.text_to_video(package["prompt"])
        continue

    first_frame = generated.get(first["asset_id"])
    if not first_frame:
        # 资产未就绪：保留声明式提示词，先回退文生视频
        video_service.text_to_video(package["prompt"])
        continue

    video_service.image_to_video(
        prompt=package["prompt"],
        first_frame=first_frame,
        duration=package["duration"],
    )

完整可运行、且不需要 LLM / 图片 / 视频密钥的示例：examples/sdk/08_asset_handoff.py。

asset_plan：声明式生图指令

资产计划由资产节点产出，包含全局风格锚点与一组 AssetSpec。默认状态全部为 pending，不触发任何外部调用。

{
  "schema_version": "0.4.4",
  "task_id": "t1",
  "script_id": "s1",
  "style_anchor": {
    "genre": "neo-noir",
    "description": "cinematic, moody lighting"
  },
  "assets": [
    {
      "asset_id": "char_001",
      "asset_type": "character_sheet",
      "owner_name": "林然",
      "image_prompt": "character reference sheet of 林然, front view, side view and back view, ...",
      "negative_prompt": "multiple characters, duplicate faces, ...",
      "size": "1024x1024",
      "views": ["front", "side", "back"],
      "usage": {
        "characters": ["林然"],
        "scenes": [],
        "fragments": []
      },
      "consistency": {
        "identity_lock": true,
        "preferred_view": "front",
        "seed": null
      },
      "status": "pending",
      "asset_ref": ""
    }
  ]
}
资产类型内容下游用途
character_sheet角色正、侧、背三视图，identity_lock=true身份参考，不作为首帧
prop关键道具静帧，可带 state_variants道具外观与状态参考
scene场景锚点静帧（地点、时间、天气）唯一可作为图生视频首帧的资产类型

status 有四种取值：pending 仅有提示词、等待下游生成；generated 已回填真实引用；failed 生成失败；skipped 已有可用资产、本次跳过。状态变化只影响下游判断，不会让主流程抛异常。

片段引用：三种角色

路由完成后，每个片段会带上 references。引用只描述“需要哪个资产、用来做什么”，不代表资产已经生成。

role来源资产as_first_frame语义
identity_reference角色三视图false锁定角色身份，不直接当首帧
first_frame场景锚点true图生视频的唯一首帧来源
prop道具静帧false道具外观与状态参考

三条硬规则：

  • references[].asset_id 始终是 PenShot 规范 ID，下游改名必须通过 asset_id_map，不要修改它；
  • 只有 as_first_frame=true 的引用适合作为视频首帧；角色三视图与道具静帧不再承担首帧职责；
  • asset_ref 只承载“已回填的场景首帧引用”，不会写入角色三视图的真实图片地址。

使用范围与质量校验

usage.fragments 是资产的使用范围。路由结束时会按片段主角、场景地点与道具出现场景回填，并强制并入 route_plan 中显式引用的片段；引用集合必须是使用范围的子集。

字段含义
usage.characters使用该资产的角名
usage.scenes使用该资产的场景地点
usage.fragments使用该资产的片段 ID，按需生成的主要依据

质量审查会检查片段引用是否落在使用范围内。片段引用了未声明的资产时记为 asset_usage_missing（major），告警同时带 fragment_id 与 asset_id，可直接定位。道具还会额外校验“文本提及 + 场景约束”，避免把无关道具挂进片段。

模式 B：回填 asset_manifest

如果下游生成资产后希望 PenShot 重新解析首帧引用，可以构造回填清单并随下一次任务提交。

{
  "schema_version": "0.4.4",
  "task_id": "t1",
  "bindings": [
    {
      "asset_id": "ds_char_001",
      "view": "front",
      "asset_ref": "/cdn/ds_char_001_front.png",
      "model": "flux-pro",
      "seed": null,
      "checksum": "",
      "source": "downstream_image_service",
      "revision": 1
    }
  ],
  "asset_id_map": {
    "char_001": "ds_char_001"
  }
}

agent.batch_breakdown(scripts, asset_manifests=[manifest_1, None])

MCP 的 breakdown_script 工具同样声明了 asset_manifest 参数。清单解析遵循以下顺序：

规则行为
ID 解析先按 asset_id_map 映射到下游实际 ID，再回退到规范 ID
清单优先下游提供了清单时，清单引用优先于契约中已有的 asset_ref
版本标记当前消费端不会因为 schema_version 不同而拒绝清单；字段结构仍需按 0.4.4 提供
未知资产 ID记录错误，但只跳过对应绑定
本地引用不可用file:// 文件缺失或校验和不匹配时保持 pending 并记录原因，避免把坏引用挂进契约
显式空引用清单已声明该资产但 asset_ref 为空时，首帧引用保持为空，不回退任何旧引用

清单也兼容直接用 assets 字段承载绑定列表的写法；只要没有 bindings，assets 会被当作绑定数组解析。

人工编辑资产提示词

工作流进入人工干预节点时，如果已生成资产计划，界面会展示每个资产的提示词摘要。选择 [7] EDIT_ASSET 后可以按编号修改：

可编辑字段说明
image_prompt角色三视图、道具或场景的正向提示词
negative_prompt对应的负向提示词

编辑生效后会依次发生五件事：

  1. 修改立即写回 asset_plan 与全局契约；
  2. 该资产的旧 asset_ref 清空、status 回到 pending；
  3. 回填清单中对应的 bindings 与 asset_id_map 被移除，避免继续使用旧图；
  4. 工作流回到 GENERATE_ASSETS 重建资产计划，再继续分段与提示词转换；
  5. 编辑记录写入 execution.asset_prompt_edits，资产 metadata 写入 human_edited、edit_source、edit_revision。

没有资产计划或没有修改任何字段时，EDIT_ASSET 会自动回退为 CONTINUE，不会卡住流程。

下游二次修改与溯源

调用视频服务前，下游可以修改提示词或切换目标模型，但必须使用白名单接口并保留溯源信息。

from penshot.neopen.agent.model_adapter import PromptOverride, apply_overrides

apply_overrides(
    adapted_packages,

        PromptOverride(

            field="prompt",
            value="Lin Ran steps into the alley, neon reflections",
            source="downstream_repair",

降级与排查

现象实际行为与处理建议
资产一直是 pending正常状态：仅声明提示词，不阻断主流程。下游按 image_prompt 生成即可
高一致性或含关键文字片段缺角色资产该片段回退 text_to_video，避免生成无身份约束的画面
清单版本号不同当前版本不校验版本号，仍会按 bindings 解析；请确保字段结构与 0.4.4 一致
回填后仍显示 pending检查 bindings[].asset_id 是否命中 asset_id_map；本地文件引用还需检查文件与校验和
片段引用了不存在的资产审查未声明的 asset_id 会被忽略；使用范围缺失会记 asset_usage_missing
首帧始终为空确认片段有 as_first_frame=true 的场景引用，且清单已回填该场景资产
