v0.4.9 · 2026-11-26

以三个真实剧本的运行日志为样本，收口分镜链路在运镜、道具、角色、地点、审计与路由环节的误报和误阻断；同时把许可证迁移为 Apache-2.0。功能性改动集中在分镜、连续性、提示词转换、模型路由与工作流决策。

运镜检测与时长

  • 英文运镜关键词改为按单词边界匹配：pan 不再命中 apartment、pants、panic，tilt 不再命中 head tilted 等人物姿态；补齐 pans、panning、zooms、orbits 等动词变形。
  • 修正错误的 camera.motion 经运动探测污染分镜时长估算的问题（运动与静态基准不同）；模型适配器的同类探测一并修复，并消除由此产生的“运镜关键词冲突”伪告警。

道具、动作与角色连续性

  • 道具持有状态改为显式释放模型：放下、放在、递给、交给、扔、丢、摔、碰倒、打翻、脱下、摘下等动作后清空持有状态，释放对象不匹配时清空当前持有道具。
  • 台词元素中提到的道具视为话题，不再计入角色持有状态；结构化 prop_object 需在元素原文中出现才采信，未命中时回退到持握动词文本提取。
  • 动作断裂只比较相邻的同角色镜头，凝视 → 拾起 → 迈步 这类正常叙事推进不再被判为动作断裂。
  • 画外音或仅声音角色（如电话另一端）按台词元素的镜头归属计入覆盖，不再误报 character_not_in_shots。

地点重写与场景锚定

  • 补充“咖啡店 / 咖啡厅 / 街角”地点词表：计划地点写“城市街角咖啡店外长椅旁”时，提示词中的 cafe、coffee shop、street、street corner 视为同一地点，不再被当作非计划地点阻断。
  • 检测前屏蔽 library card 等非地点固定搭配；按命中区间抑制被更长地点词覆盖的短词，改写成功后不再残留冲突。
  • 分镜阶段保留片段连续性注释并补充场景 ID，修复地点重写的场景定位。

审计、路由与文字判定

  • 与连续性检查同口径：待修复的中度问题全部落在 requires_manual_fix（无自动策略）时记录告警并继续执行，不再反复修复直至审计循环超限、转入人工干预并最终超时失败。
  • 模型支持检查改用能力注册表（get_capability / parse_model_name），修复访问不存在的 ShotConfig.supported_models 导致的 AttributeError；kling_3、runway_gen4 等已注册模型不再被误判为不支持。
  • critical_text 判定收紧：裸“招牌 / 标牌”不再构成可读文字要求，需出现“文字 / 字样 / 写着 / 店名”等明确表述；“咖啡店招牌模糊可见”这类氛围招牌不再误报首帧缺少文字证据。

许可证与升级

  • 项目许可证由 MIT 迁移为 Apache-2.0，统一 SPDX 头注释并新增 NOTICE，LICENSE 同步替换；下游再分发需保留 LICENSE 与 NOTICE。
  • 无破坏性 API 变更，契约 schema、SDK 调用方式与配置项保持兼容。
  • 行为变化均为减少误报：片段 camera.motion 可能由误判的 pan / tilt 回归 static 或真实运镜，分镜时长估算随之变化；氛围招牌片段不再以 critical_text 理由路由；无自动策略的中度问题不再阻塞流程，改在输出 warnings 中携带人工处理项。

v0.4.8 · 2026-11-21

连续性、记忆、报告与检查点的一致性收口。无破坏性改动，无需数据迁移；配置项与 SDK 调用方式保持不变。

连续性与审计

  • 连续性问题均不可自动修复时记录 unfixable_skipped 轮次；final_status 由 not_checked 修正为 continued_with_issues，不再与“检查已执行且流程继续”的事实矛盾。
  • 外观连续性状态子句不再混入服装锚点，避免同一角色因动作或情绪被误报为外观变化。
  • 场景与角色锚点、状态快照、长剧本跨块校验、风格漂移检测正式接入主链；道具结构化解析并写入场景契约。
  • 审计模型支持校验对齐能力注册表；历史阶段统计缺少完整度时不再误判为 poor；修复后重算阶段问题，避免空转循环；声明 last_audit_result 状态字段，修复检查点恢复时字段缺失导致的审计状态不一致。

记忆与提示词

  • 三层记忆统一 BaseMemoryLayer，统一按 key 存取、清理与统计骨架；修复读取链路与工作流键一致性。
  • 中期摘要读写统一使用 medium_summary.json，重启后可回读；长期记忆新增保留上限 long_term_max_documents（默认 500），写入后自动清理最旧记录。
  • 片段固定 seed：显式配置优先，否则按剧本内容派生稳定值；音频链每轮重置，新增剧本语言推断与音频提示词归一，支持跨剧本模板迁移。

检查点与报告

  • 同一任务使用稳定 thread_id（{script_id}_{task_id}），任务启动时检测未完成的最近快照并以 None 续跑；任务收尾按 max_checkpoints_per_script 清理旧检查点，应用关闭时释放检查点连接。
  • quality_report.json 新增 post_repair_score、repair_status、repair_issue_count、repair_action_count；修复后复检分数不再只存在于审计明细中。
  • repair_history.json 汇总质量审查阶段的修复动作，repair_count 与日志一致，并新增 continuity_repair_count / quality_repair 分列。
  • continuity_report.json 的 final_status 新增取值 continued_with_issues；依赖旧枚举值的下游请按未知值兜底处理。

v0.4.7 · 2026-11-20

场景权威、契约修复回路与 P0~P2 质量收口。契约 schema 保持 0.4.4，新增元数据均为可选。

场景与首帧

  • 片段所属场景已登记首帧资产时，以计划场景作为唯一权威，不再退化为文生视频；计划场景与首帧资产不一致计入契约违规，参与质量审查与修复。
  • 按计划地点重写提示词；地点冲突直接阻断片段，告警中给出计划地点与期望首帧资产。地点解析改为 scene_id → continuity_notes 场景 → 剧本唯一地点名，歧义时跳过而非猜错。
  • 景别表述统一归一、收紧景别探测，保留 POV 等主观视角；每轮只输出一条改写汇总。

契约与修复回路

  • 修复参数改用确定性问题码并按真实动作结算，避免“假修复”与空转重试；修复状态按优先级保留，已收敛项、降级项与人工项不再重复计入 requires_manual_fix。
  • unknown_character 区分剧本真实角色与生成幻觉：真实角色补登记契约后即收敛，只对幻觉角色派发修复；复合主角色（如“李明、张晨”）按角色粒度校验与修复。
  • 风格问题改为确定性收敛：统一 [Style: ...] 前缀并移除冲突风格短语；无可靠风格来源时转人工，不再无效重试或报 repaired。
  • 审计节点与修复后复检只采信最终产物快照，已收敛的历史违规不再重复扣分。

审计与可观测性

  • 审计状态、分数与结论统一按检查通过率计算，结论列出未通过的检查项。
  • 测试运行不再写入 logs/penshot_<date>.log；PENSHOT_LOG_TO_FILE=0 关闭文件日志，PENSHOT_LOG_FILE 指定日志路径。
  • 超长片段截断写入 dropped_duration / manual_review_required，并在片元序列元数据输出 truncation_report，便于下游与人工复核。
  • 计划模式下资产 pending 日志由 WARNING 降为 INFO，并输出实际待生成数量；运镜冲突词表与同族判定对齐，减少同义运镜被误判。

v0.4.6 · 2026-11-17

REST 与配置侧安全加固，对外行为保持兼容。

  • 配置环境变量展开限制为可信引用，避免不可信输入通过 ${VAR} 形态读取宿主机环境变量。
  • callback_url 增加协议、凭据、端口、内部主机名与私网地址校验，解析 DNS 后固定已验证的公网 IP 再发起请求，防止 SSRF 与 DNS Rebinding。
  • GET /api/v1/config 改为脱敏的公开配置响应，不再暴露本地路径、数据库连接串与内部客户端密钥对象。
  • 抽取统一 penshot.security 包（env_refs / ssrf / request_config），供 REST 校验与任务回调复用。
  • 兼容性：请求中覆盖 checkpoint_dir 或 postgres_uri 会被重置 / 剔除；其余字段与调用方式不变。

v0.4.5 · 2026-11-14

分镜缺陷修复与资产链收口。无破坏性 API 变更，SDK 调用方式保持不变。

分镜生成

  • 片段时长改为按动作节点确定性推算，并输出片段总时长报告；只有与镜头计划实质偏离时才告警。
  • 新增同镜头重复片段的检测、合并与超长重切，重编号后片段引用保持一致。
  • 首帧提示词清洗中文镜头词、action:、广播与音效标记，保留英文景别；纯音频片段使用空镜兜底。
  • 新增剧本语言推断与音频提示词归一，输出 dialogue_language。

资产与风格一致性

  • 风格锚定证据扩展到环境音与打光；无信号时回退到 mood / lighting / palette，并写入 provenance。
  • 服装材质词表扩展，剧本中给出的材质优先回填；资产声明与回填形成闭环，缺失项可见、可补。
  • 服装关键字段缺失的资产要求降级为剪影或背影，不再阻断片段。

质量门禁与 P0 修复

  • 场景锚定不匹配时自动替换或阻断片段，路由重建时保留阻断状态。
  • 修复环节零动作必须报错并标记，检测分数与修复分数分列。
  • below_threshold 放行时写入 quality_gate 标记，便于下游区分“通过”与“降级放行”。
  • 质量审查采信契约校验结果；critical_text 只按可读文字判定；景别以镜头计划为准并保留 POV；楼道/走廊同义归一。

升级与兼容

  • 新增的 degraded_assets、dialogue_language、quality_gate 标记等字段均为可选，旧产物仍可解析。
  • 无需执行数据迁移；如需使用新的质量标记，升级后重新运行任务即可。

v0.4.4 · 2026-11-11

连续性闭环与首帧语义加固，是本阶段行为变化最集中的版本。

连续性与修复回路

  • 跨场景切换改为确定性插入过渡镜头，修复 scene_jump 重试仍反复重跑分镜、问题无法消解的问题。
  • 外观连续性单轮比较改为主体服装集合，配饰与鞋履增删不再被误报为“外观变化”。
  • 角色外观锚点只保留自由文本中的外观子句，按字段白名单取首值，避免情绪、动作词与半截词污染锚点。
  • 风格维度按题材/氛围补齐六维前缀，互斥打光只保留一个家族，题材别名归一化并输出溯源。

首帧与资产引用

  • 角色三视图与道具静帧不再作为首帧，asset_ref 只代表片段首帧；回填 usage.fragments 并与路由引用保持一致。
  • 场景已登记场景资产时，图生视频路由不再退化为文生视频；无主角色的片段同样以场景首帧走两段式生成。
  • 修复旧产物首帧提示词拼出“of 无”的残句；非角色占位名归一为空。

提示词、模板与质量规则

  • 修复模板索引加载以旧文件名判空导致零命中、单文档索引覆盖既有索引的问题；新增结构化检索诊断与只读召回快照。
  • 模板入库统一质量审查与记忆层的策略，写入 source / audit_status，旧缺陷模板默认排除在召回之外。
  • 新增四条质量规则：外观锚点污染、景别与提示词不一致、互斥打光并存、资产使用范围缺失；违规记录带可定位的 fragment_id / asset_id。
  • 景别一致性以最终提示词为准，保留来源景别与原始值溯源。

升级与迁移

  • CONTRACT_SCHEMA_VERSION 提升至 0.4.4，与 asset_plan、asset_manifest 和路由契约保持一致；新增字段均为可选。该契约版本沿用至 0.4.9。
  • 0.4.3 已入库的缺陷模板需执行一次迁移：python scripts/migrate_prompt_templates_044.py 默认 dry-run，确认后加 --apply 写入；--script-id 可限定单剧本。
  • 迁移会先备份各剧本的 templates_cache.json 与 index_store/；缺陷模板只做隔离标记，不删除底层数据，完成后从活跃缓存全量重建索引。
  • 召回阈值默认 min_similarity_score=0.80、top_k=2、max_injected_patterns=6，可通过 PENSHOT_PROMPT_TEMPLATES__* 覆盖。
  • 下游若把 asset_ref 当作角色三视图或道具图使用，需要改为读取片段首帧引用，否则会拿到空值或场景首帧。

v0.4.3 · 2026-11-09

新增模型路由与结构化相机控制，提示词生成与目标模型决策解耦。

  • 登记 runway_gen4、kling_3、luma_dream、sora_2、pika_2 五个模型的能力：时长上限、是否支持图生视频、镜头控制、一致性与风格倾向。

  • 路由失败只记录告警，route_plan 置为 null，不阻断主流程；未通过质量门的片段进入 blocked_fragments。
  • 修复 time_gap 反复重试与连续性节点崩溃。

升级与兼容

升级前先固定版本号并保留一次可回放的旧产物；涉及契约变化时，按下表处理。

升级路径需要处理
0.4.8 → 0.4.9无破坏性改动；许可证改为 Apache-2.0，再分发保留 LICENSE 与 NOTICE；下游若依赖 camera.motion 或 critical_text 判定，按减少误报后的结果调整预期
0.4.7 → 0.4.8无需迁移；按需读取 post_repair_score、repair_status 与 repair_history 新字段；对 final_status 未知枚举值兜底
0.4.6 → 0.4.7无需迁移；按需读取 truncation_report、scene_prompt_realign_summary；测试环境可设置 PENSHOT_LOG_TO_FILE=0 隔离文件日志
0.4.5 → 0.4.6回调地址必须通过 SSRF 校验（默认只允许公网目标）；请求不能覆盖 checkpoint_dir / postgres_uri；/config 返回字段变少
0.4.4 → 0.4.5无需改动；按需读取 degraded_assets、dialogue_language 与 quality_gate 标记
0.4.3 → 0.4.4执行模板迁移脚本（先 dry-run 再 --apply）；核对下游 asset_ref 语义；质量审查新增四条规则，需检查告警消费逻辑
0.4.2 → 0.4.3读取 instructions.route_plan；处理 null 与 blocked_fragments；如需图生视频，接入场景首帧引用
0.4.1 → 0.4.2资产节点默认只输出 asset_plan，不会生成图片；需要接入下游资产生成与 asset_manifest 回填
0.4.0 → 0.4.1无接口变更，建议重新运行一次任务以生成新的连续性报告
0.3.x → 0.4.x先升级到 0.4.9 并完成模板迁移，再按需启用资产计划与模型路由；旧 0.3.x 模板不会自动具备 0.4.4 的 audit_status

版本号与文档策略

  • 0.x 阶段：次版本号用于向下兼容的功能新增，修订号用于兼容修复；尚未承诺 1.0 级别的 API 稳定性。
  • 破坏性变更、默认行为变化与数据迁移会同时出现在本页与对应 Release Notes 中，升级前应逐条核对。
  • 站点只维护一份最新文档，不按版本复制页面；正文标注的源码基线用于说明“这批描述对应哪次复核”。
  • 项目自 0.4.9 起采用 Apache-2.0 许可证；0.4.8 及更早版本仍按 MIT 分发。
  • 安装包以 PyPI 为准，容器镜像以 Docker Hub 为准。
