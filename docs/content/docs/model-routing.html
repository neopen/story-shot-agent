不同视频模型擅长的东西不一样：有的文字渲染准，有的长镜头稳，有的图生视频一致性好。PenShot 的模型路由节点在提示词生成之后，按确定性规则为每个片段选择目标模型与生成模式，输出一份可解释、可直接消费的 route_plan。

本页对应 v0.4.4 源码。路由只做选型与提示词适配，不调用任何视频生成接口；真实渲染仍由下游完成。

30 秒了解

问题路由的做法
每个片段该用哪个模型抽取片段的文字、动作、一致性、风格、时长特征，匹配优先级最高的规则
规则是否可复现全部是关键词与数值判定，不调用 LLM，同一输入得到同一决策
为什么选了这个模型每个决策带 reason 与能力声明，可直接写入日志或审核界面
模型只支持 5 秒怎么办提示词包时长被收敛到模型上限；若片段超出上限，自动换一个能覆盖时长的模型
规则引用了未注册模型跳过该规则，继续匹配下一条；最终兜底到默认模型
路由失败会中断任务吗不会。异常只记录告警，route_plan 保持为空，其余产物照常输出

路由特征如何抽取

路由节点读取每个 AIVideoPrompt 与全局契约，产出六个确定性特征。没有 LLM 参与，因此不会出现同一片段两次路由结果不同的情况。

特征判定方式
has_critical_text提示词明确要求呈现可读文字。中文词表含“文字、字迹、地址、手写、字幕、招牌、标牌、海报、书名、报纸、书信、标题”；英文按整词匹配 text、readable、address、handwriting、subtitle、newspaper、poster、menu、title
motion_complexity命中打斗、追逐、战斗、爆炸、舞蹈、奔跑、翻滚、旋转、飞跃等关键词为 high；命中走、转身、推、拿起、拥抱等为 medium；其余为 low
character_consistency_need主角在契约中登记了外观锚点为 high；有主角但无锚点为 medium；无主角为 low
style_bias从提示词风格与正文关键词判断 anime、realistic 或 cinematic，默认 cinematic
duration片段原始时长，单位秒
needs_first_last_frame是否属于关键文字或角色外观锚点片段。场景锚点覆盖的片段也会进入两段式，但不会单独把该特征置真

规则匹配与优先级

默认配置开启路由（routing.enabled: true），规则按 priority 从大到小排序；优先级相同时按规则名升序。对每个片段，取第一条“条件全部满足且模型已注册”的规则。

优先级规则条件目标模型模式
100critical_texthas_critical_text = truekling_3image_to_video
90high_consistencycharacter_consistency_need = highkling_3image_to_video
80complex_motionmotion_complexity = highsora_2text_to_video
70anime_stylestyle_bias = animekling_3text_to_video
60cinematic_long_takestyle_bias = cinematic 且时长不少于 8 秒runway_gen4text_to_video

条件的组合是“与”：min_duration 与 max_duration 同时参与判断，未填写的字段不约束。一个片段可能同时满足多条规则，此时只采用优先级最高的一条，不会把多个模型拼在一起。

同一份提示词，五种适配风格

路由选中模型后，会按该模型的习惯重写提示词。差异不只是模型名，还包括正向前缀、负向词、相机表述与生成参数。

与图生视频的关系

路由节点先执行两段式判定，再执行规则路由。两条链路的分工是：

阶段作用
apply_image_to_video_routing判定片段是否值得两段式生成，挂载首帧提示词、动作提示词与资产引用
build_route_plan按特征选择目标模型与模式，并按最终模型重建提示词包

规则可以把片段改成 text_to_video，此时两段式字段会被清空，避免下游拿到失效的资产引用；改成 image_to_video 时，已有的引用、首帧提示词、动作提示词、告警与状态会被保留。若片段没有经过片段级首帧构建，路由会补一份静态首帧提示词与动作提示词，不会让图生视频包缺少首帧。

配置与扩展

默认规则位于 src/penshot/config/settings.yaml 的 routing 段。新增模型分两步：

  1. 用 register_model(ModelCapability(...)) 注册能力声明；
  2. 在规则中引用该模型名，并设置条件、模式与优先级。
from penshot.neopen.agent.model_adapter import ModelCapability, register_model

register_model(
    ModelCapability(
        model_name="my_video_model",
        max_duration=8.0,
        supports_image_to_video=True,
        supports_camera_control=False,
        text_rendering_score=0.6,
        character_consistency=0.8,
        aesthetic_bias="cinematic",
    )
)

注册表是进程内静态表，不会持久化；每个需要路由的进程都要完成注册。适配器注册表当前只内置上述五个模型：只注册能力而没有适配器时，工厂会回退到默认的 runway_gen4 适配器，提示词包的 target_model 也会变成 runway_gen4。要让自定义模型真正参与路由，需要同时提供并注册适配器。

边界与排查

现象原因与处理
route_plan 为空路由节点异常被吞掉，查看告警日志；常见原因是提示词指令为空
所有片段都落到 kling_3没有规则命中且原模型未注册；检查规则条件与模型注册表
规则写了但没生效模型未注册会被跳过；或条件未全部满足；或优先级被更高规则截胡
片段突然变短目标模型最大时长小于片段时长，提示词包被收敛；查看 Gate 1 的时长告警
片段被阻断场景锚定无法唯一匹配，status=needs_manual_fix 并进入 blocked_fragments，需人工指定场景
关键词路由不准特征抽取是词表法，近义动作或隐含文字可能漏判；可在提示词中写明确动作与文字要求
