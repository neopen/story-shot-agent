PenShot 的八段工作流由 LangGraph 编排：每个业务节点完成一次内容生产，经决策函数返回八种状态之一，再进入下一节点、重试、修复或转人工。

格式识别

_detect_script_format 用正则按优先级分类，命中后选择对应的系统提示词；全部不命中时退回通用提示词，不报错。

优先级 判定规则 结果
1 INT. / EXT. / 内景 / 外景 / 场景N： STANDARD_SCRIPT
2 镜头N / shot N / 分镜N / 画面描述： AI_STORYBOARD
3 场景： / 地点： / 时间： / 角色： STRUCTURED_SCENE
4 角色：台词 行数占比 > 70% DIALOGUE_ONLY
5 句号 / 感叹号 / 问号数量 > 冒号 / 引号数量 NATURAL_LANGUAGE
6 以上均不命中 MIXED_FORMAT

质量评估与校验

_evaluate_completeness 给出五维加权分：场景 0.25、角色 0.25、对话 0.20、动作 0.20、总体覆盖率 0.10；再按 min(0.2, 问题数 × 0.05) 扣分。元素 sequence 汇总后校验是否为 1…N，不连续只记 Warning，不阻断流程；缺失 id 时按 elem_{场景序号}_{元素序号} 补全。

解析阶段同时写入全局风格锚点与溯源信息（style_anchor_provenance），供资产计划与提示词转换复用。失败与降级：结果为空或完整性过低时，decide_after_parsing 路由回本节点重试；正则漏判退回 MIXED_FORMAT 通用提示词；没有原文偏移量回溯，sequence 的正确性依赖 LLM 输出质量。

每个资产以 AssetSpec 描述：asset_id、asset_type、owner_name、正负提示词、尺寸、视角、使用范围、连续性约束（identity_lock、preferred_view、建议 seed）与状态。计划整体序列化为 AssetPlanDocument，带 schema_version、style_anchor 与资产列表，写入 asset_plan.json。

报告 AssetGenerationReport 记录 mode（plan / manifest / generated）、供应商、总数、成功/失败/待生成/跳过数量、回填应用数量与错误。无论是否启用出图，asset_plan.json 与 asset_generation_report.json 都会落盘；资产失败不阻断主流程，由下游首帧指令兜底。真实出图默认关闭（image.default.enabled=false），开启后由 ImageClientExecutionAdapter 调用文生图客户端。

回填清单 AssetManifest 支持 bindings 与 asset_id_map（下游改名映射），并兼容下游直接写 assets 的格式。绑定包含 asset_id、view、asset_ref、model、seed、checksum、revision 与错误信息；引用会做格式校验，非法引用降级为警告。

失败与降级：计划生成失败或未启用出图时，资产保持 pending 并继续拆分；同一角色只保留首值外观锚点，后续服装变化进入 outfit_sequence，不会覆盖首次身份特征。

规则模式

判断 条件 结果
连续对话 两个 DIALOGUE 且角色相同 合并进同一镜头
连续动作 两个 ACTION 且角色相同 默认不合并（merge_consecutive_actions=False）
对话后短动作 DIALOGUE 后紧跟 <3.0 秒的 ACTION 合并

景别判定：组内含对话→特写 close_up；含场景描述→全景 wide_shot；其余→中景 medium_shot。ShotType 枚举共 13 种，提示词列出 8 种使用场景供 LLM 选择。

时长估算

LLM 给出的时长只作草案，拆分完成后 estimator_factory.estimate_sequence() 会覆写 shot.duration。动作估算器按中景基准 2.8 秒起算，叠加描述复杂度、速度关键词、场景情绪、角色特征，再与 ActionDurationEstimatorTool 结果按 0.4 : 0.6 加权，最后 clamp 到景别区间。DurationEnhancer 负责边界校准、情感特写至少 3.0 秒、开场/结尾 ×1.2、连续同型镜头错开 0.3 秒。

失败与降级：估算器是关键词与固定系数规则，不感知语义；merge_consecutive_actions=False 会把连续动作拆成多个镜头；增强器中 climax / transition 的节奏系数尚未被引用，当前仅 opening / ending 生效。

  • 双语提示词拼为单字段：combined_prompt = f"{english_prompt}\n\n{original_prompt}"，英文在前、原语言在后。

质量审计 AUDIT_QUALITY

对提示词包做最后一道程序化检查：11 项硬规则、按严重度加权扣分，再合并 LLM 深度审查，输出放行、修复或人工三种走向。规则版实现为 RuleQualityAuditor。

flowchart TD

    B --> C[违规项记入 violations<br/>按严重度加权扣分]
    C --> D[合并 LLM 审查报告]
    D --> E{score 分档}
    E -->|≥90| F[PASSED 放行]
    E -->|≥75| G[MINOR_ISSUES]
    E -->|≥60| H[MODERATE_ISSUES 修复]
    E -->|≥40| I[MAJOR_ISSUES 修复]
    E -->|≥20| J[CRITICAL_ISSUES 重试/人工]
    E -->|低于20| K[FAILED 重试/人工]

连续性守护 CONTINUITY_CHECK

跨阶段检查角色、场景、动作、风格、时间、道具六类问题。实现为关键词与数值规则（ContinuityGuardianChecker），不是 LLM 语义审查；检查结果会驱动上游修复。

flowchart LR
    subgraph Input
        A[解析/拆分/分段/指令<br/>各阶段产物]
    end

    subgraph Process[六项检查]
        B[角色连续性<br/>出现对照+外观词表] --> C[场景连续性<br/>跳转次数占比]
        C --> D[动作连续性<br/>动作词表]
        D --> E[风格连续性<br/>风格种类数]
        E --> F[时间连续性<br/>起止时间差]
        F --> G[道具连续性<br/>道具动词表]
    end

    subgraph Dedup[后处理]
        H[签名去重] --> I[描述截断 500 字符]
    end

    subgraph Output
        J[问题列表<br/>含严重度+来源阶段+可修复标记]

输入 输出
parsed_script、shot_sequence、fragment_sequence、instructions（有则查，无则跳过） ContinuityCheckResult：问题类型、严重度、fragment_id、source_stage、auto_fixable、suggestion
检查 判定方式 触发与严重度
角色 角色出现在场对照；服装 / 发型 / 配饰三类词表 有对话无镜头→CHARACTER_MISSING（MAJOR）；外观词变化→WARNING
场景 相邻镜头 scene_id 变化，统计跳变占比 单次跳变→SCENE_JUMP（WARNING）；占比 >30%→SCENE_TOO_FREQUENT（MODERATE）
动作 动作词表（走/跑/跳/转身/坐下/站起/拿起/放下）按角色追踪 同角色相邻动作词变化→ACTION_BREAK（MODERATE）
风格 AIVideoPrompt.style 去重种类数 种类数 >2→STYLE_INCONSISTENT（MODERATE）
时间 片段 start_time 与前段“起始 + 时长”的差值 正差 >0.1 秒→TIME_GAP（MAJOR）；负差→TIME_OVERLAP（ERROR）
道具 道具动词表（拿/举/抱/提/端/持/握）按角色统计 同角色动词变化→PROP_CHANGE（WARNING）

通过判定：任一 CRITICAL，或 MAJOR 超过 3 个，即 passed=False；其余级别不改变结论。问题签名由“类型 + 片段 + 场景 + 严重度 + 位置 + 描述前 100 字”组成，同一位置同类问题只报一次；描述超过 500 字符截断。

修复回流：节点把可修复问题写入 domain.repair_params，并设置 needs_continuity_repair 与来源阶段；决策函数据此返回阶段节点名，路由回解析、拆分、切割或转换。修复最多 3 轮（max_continuity_retries），轮次耗尽或存在未定位来源的问题时转人工。

失败与降级：词表法会把“拿手机→握手机”判为道具变化，“转头”不在动作词表；上下文缺失时对应检查直接跳过。检查只做词表与数值判断，不理解语义，因此适合发现显性漂移，无法判断隐喻或叙事层面的连贯性。

限制按节点归集，跨节点的路由与计数问题见技术架构的“当前限制”。
