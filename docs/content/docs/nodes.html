PenShot 的六段工作流由 LangGraph 编排：每个业务节点完成一次内容生产，经决策函数返回七种状态之一，再进入下一节点、重试或转人工。

格式识别

_detect_script_format 用正则按优先级分类，命中后选择对应的系统提示词；全部不命中时退回通用提示词，不报错。

优先级 判定规则 结果
1 INT. / EXT. / 内景 / 外景 / 场景N： STANDARD_SCRIPT
2 镜头N / shot N / 分镜N / 画面描述： AI_STORYBOARD
3 场景： / 地点： / 时间： / 角色： STRUCTURED_SCENE
4 角色：台词 行数占比 > 70% DIALOGUE_ONLY
5 句号 / 感叹号 / 问号数量 > 冒号 / 引号数量 NATURAL_LANGUAGE
6 以上均不命中 MIXED_FORMAT

质量评估与校验

_evaluate_completeness 给出五维加权分：场景 0.25、角色 0.25、对话 0.20、动作 0.20、总体覆盖率 0.10；再按 min(0.2, 问题数 × 0.05) 扣分。元素 sequence 汇总后校验是否为 1…N，不连续只记 Warning，不阻断流程；缺失 id 时按 elem_{场景序号}_{元素序号} 补全。

镜头拆分 SEGMENT_SHOT

把场景中的元素序列划分为视觉独立的镜头，并给出景别与时长。LLM 与规则两种实现共享 ShotSequence 输出，由 ShotSegmenterFactory 按 enable_llm 选择。

规则模式

判断 条件 结果
连续对话 两个 DIALOGUE 且角色相同 合并进同一镜头
连续动作 两个 ACTION 且角色相同 默认不合并（merge_consecutive_actions=False）
对话后短动作 DIALOGUE 后紧跟 <3.0 秒的 ACTION 合并

景别判定：组内含对话→特写 close_up；含场景描述→全景 wide_shot；其余→中景 medium_shot。ShotType 枚举共 13 种，提示词列出 8 种使用场景供 LLM 选择。

时长估算

LLM 给出的时长只作草案，拆分完成后 estimator_factory.estimate_sequence() 会覆写 shot.duration。动作估算器按中景基准 2.8 秒起算，叠加描述复杂度、速度关键词、场景情绪、角色特征，再与 ActionDurationEstimatorTool 结果按 0.4 : 0.6 加权，最后 clamp 到景别区间。DurationEnhancer 负责边界校准、情感特写至少 3.0 秒、开场/结尾 ×1.2、连续同型镜头错开 0.3 秒。

失败与降级：估算器是关键词与固定系数规则，不感知语义；merge_consecutive_actions=False 会把连续动作拆成多个镜头；增强器中 climax / transition 的节奏系数尚未被引用，当前仅 opening / ending 生效。

规则模式零 Token、输出稳定，适合批量草稿与离线环境；LLM 模式按语义划分，但镜头边界会随模型输出波动。两种模式共用同一个 estimator_factory，时长后处理不受选择影响。

失败与降级：LLM 切分抛异常时记录日志并自动降级为规则均分。LLM 模式下 _should_use_llm_split 末尾为无条件 return True，复杂镜头与对话关键词分支实际是死代码；规则均分最多 3 段，超长镜头仍可能超过 5.5 秒。

质量审查 AUDIT_QUALITY

对提示词包做最后一道程序化检查：五项硬规则、按严重度加权扣分，输出放行、修复或人工三种走向。规则版实现为 RuleQualityAuditor。

    B --> E[提示词长度检查]
    B --> F[片段数量检查]
    B --> G[模型支持检查]

    E --> H
    F --> H

    I -->|≥90| J[PASSED 放行]
    I -->|≥75| K[MINOR_ISSUES]
    I -->|≥60| L[MODERATE_ISSUES 修复]
    I -->|≥40| M[MAJOR_ISSUES 修复]
    I -->|≥20| N[CRITICAL_ISSUES 重试/人工]
    I -->|低于20| O[FAILED 重试/人工]

AIVideoInstructions QualityAuditReport：status、checks[]、violations[]、stats、score、suggestions
检查项 判定条件 严重度

片段时长（下限） 时长 < 1.0 秒 WARNING
提示词内容 提示词为空 ERROR（PROMPT_EMPTY）

扣分从 100 起算：warning 5、moderate 10、major 25、critical 40、error 60，下限 0。状态分档：≥90 PASSED、≥75 MINOR_ISSUES、≥60 MODERATE_ISSUES、≥40 MAJOR_ISSUES、≥20 CRITICAL_ISSUES，否则 FAILED。PASSED 放行；MINOR 默认放行，违规超过 3 个转修复；MODERATE / MAJOR 回 CONVERT_PROMPT；CRITICAL 重试或转人工。FAILED 但分数 ≥80 仍按 VALID 放行。

报告中的违规项按 PipelineNode 转成修复参数，写入 state.domain.repair_params；下一轮 CONVERT_PROMPT 只读取属于自己的键，应用成功后可调用 clear_repair_params() 清理。

失败与降级：5.5 秒同时作为分段触发阈值与审查红线，分段漏切会在此处直接报 ERROR；五项检查只覆盖可程序化判定的是非问题，合规但平庸的提示词仍可通过。规则版审查不调用模型，LLM 不可用时仍能给出时长与空值结论。

时间 片段 start_time 与前段“起始 + 时长”的差值 正差 >0.1 秒→TIME_GAP（MAJOR）；负差→TIME_OVERLAP（ERROR）
道具 道具动词表（拿/举/抱/提/端/持/握）按角色统计 同角色动词变化→PROP_CHANGE（WARNING）

通过判定：任一 CRITICAL，或 MAJOR 超过 3 个，即 passed=False；其余级别不改变结论。问题签名由“类型 + 片段 + 场景 + 严重度 + 位置 + 描述前 100 字”组成，同一位置同类问题只报一次；描述超过 500 字符截断。

失败与降级：词表法会把“拿手机→握手机”判为道具变化，“转头”不在动作词表；上下文缺失时对应检查直接跳过。更关键的是修复回流未接通：决策函数读取顶层 state.continuity_issues，实际字段在 state.domain.continuity_issues，导致恒为 SUCCESS；返回的 NEEDS_RETRY 也不在条件边键集合中。因此问题会被记录，但不会自动回退上游。

限制按节点归集，跨节点的路由与计数问题见技术架构的“当前限制”。
